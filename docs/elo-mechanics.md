# Механика ELO

## Базовая формула

ELO — система рейтингов для попарных сравнений. Используется в шахматах,
LMSYS Chatbot Arena, и других системах где нужно ранжировать участников
по результатам попарных матчей.

### Ожидаемая вероятность победы

Перед сравнением вычисляется ожидаемая вероятность победы каждой модели:

```
E_A = 1 / (1 + 10^((R_B - R_A) / 400))
E_B = 1 - E_A
```

Где `R_A` и `R_B` — текущие ELO моделей.

**Примеры:**
- A=1200, B=1200 → E_A = 0.50 (равны)
- A=1300, B=1100 → E_A = 0.76 (A фаворит)
- A=1100, B=1300 → E_A = 0.24 (A аутсайдер)

### Обновление рейтинга

После вердикта судьи:

```
R_A' = R_A + K_A × (S_A - E_A)
R_B' = R_B + K_B × (S_B - E_B)
```

Где:
- `S` = 1 (победа), 0 (поражение), 0.5 (ничья)
- `K` = K-factor (см. ниже)
- `E` = ожидаемая вероятность

## Адаптивный K-factor

K-factor определяет, насколько сильно каждый вердикт влияет на рейтинг.
В этой системе K адаптивный — зависит от количества игр модели:

| Игр у модели | K-factor | Логика |
|---|---|---|
| < 10 | 40 | Быстрая калибровка (мало данных — большие шаги) |
| 10–30 | 32 | Стандартный ELO |
| > 30 | 24 | Стабилизация (рейтинг устоялся — мелкие корректировки) |

K применяется **индивидуально** к каждой модели в паре. Если новая модель
(0 игр, K=40) сравнивается с установившейся (35 игр, K=24), новая получает
большие скачки, старая — маленькие.

## Примеры расчётов

### Пример 1: Равные модели, A победила

```
A=1200 (0 игр, K=40), B=1200 (0 игр, K=40)
E_A = 0.50, S_A = 1

R_A' = 1200 + 40 × (1 - 0.50) = 1220
R_B' = 1200 + 40 × (0 - 0.50) = 1180

ΔA = +20, ΔB = -20
```

### Пример 2: Фаворит победил (ожидаемо)

```
A=1300 (15 игр, K=32), B=1100 (15 игр, K=32)
E_A = 0.76, S_A = 1

R_A' = 1300 + 32 × (1 - 0.76) = 1308
R_B' = 1100 + 32 × (0 - 0.24) = 1092

ΔA = +8, ΔB = -8  (малый рост — результат ожидаемый)
```

### Пример 3: Аутсайдер победил (апсет)

```
A=1100 (5 игр, K=40), B=1300 (35 игр, K=24)
E_A = 0.24, S_A = 1

R_A' = 1100 + 40 × (1 - 0.24) = 1130
R_B' = 1300 + 24 × (0 - 0.76) = 1282

ΔA = +30, ΔB = -18  (большой рост A — апсет ценный)
```

### Пример 4: Ничья

```
A=1200 (10 игр, K=32), B=1200 (10 игр, K=32)
E_A = 0.50, S_A = 0.5

R_A' = 1200 + 32 × (0.5 - 0.50) = 1200
R_B' = 1200 + 32 × (0.5 - 0.50) = 1200

ΔA = 0, ΔB = 0  (ничья при равных моделях — ELO не меняется)
```

Но ничья при неравных моделях:
```
A=1300, B=1100, E_A=0.76, S_A=0.5
R_A' = 1300 + 32 × (0.5 - 0.76) = 1292  (A теряет — ничья хуже ожидания)
R_B' = 1100 + 32 × (0.5 - 0.24) = 1108  (B растёт — ничья лучше ожидания)
```

## Пересчёт

ELO пересчитывается **полностью** из всех вердиктов при каждом обновлении:
1. Все модели стартуют с ELO=1200
2. Вердикты применяются последовательно в хронологическом порядке
3. Каждый вердикт обновляет ELO обеих моделей
4. Итоговые ELO записываются в index.json

Это гарантирует консистентность: index.json всегда = функция от matchups/.
При 500 вердиктах пересчёт занимает <100ms.

## Округление

ELO хранится как целое число. Промежуточные вычисления — float, итог
округляется до целого (round half to even — banker's rounding):
- 1216.5 → 1216
- 1217.5 → 1218
