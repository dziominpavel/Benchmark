# Workflow Guide — пошаговая инструкция

## Минимальный прогон (1 задача, 2 ответа, 1 вердикт)

### Шаг 1: Создать задачу (вручную)

Скопируй `tasks/_TEMPLATE.md` в `tasks/T-001-<slug>/task.md`, заполни
front matter (`id`, `title`, опционально `project` + `baseline_commit`)
и разделы (описание, что искать, критерии полноты, ограничения).
Пример готовой задачи: `tasks/T-001-recurrence-bugs/task.md`.

Генеративного skill для создания задач в MVP нет — только шаблон.

### Шаг 2: Прогнать модели (skills)

В чате IDE, по одному вызову на слот:

```
@benchmark-run-a T-001
@benchmark-run-b T-001
```

Каждый skill сам: читает `task.md`, делает `git checkout <baseline_commit>`
в проекте-референсе, анализирует код, пишет ответ
(`answers/T-001/modelA.md` / `answers/T-001/modelB.md`), записывает свой
реальный model-id в `answers/T-001/slots.json` и чистит проект после.
В конце сообщает сколько багов найдено.

Прогон произвольной модели из реестра (например `opencode-mimo-v2-5-free`)
готовым skill не покрыт — ответ пишется вручную по `answers/_TEMPLATE.md`
в файл `answers/T-001/<model-id>.md`.

### Шаг 3: Судья (skill)

```
@benchmark-judge T-001
```

Skill проверяет оба ответа, читает задачу, при противоречиях сверяется
с кодом проекта, оценивает по 5 критериям (полнота, точность, качество кода,
структура, глубина — каждый 1–10, итого /50), объявляет победителя
(ничья — только при разнице ≤ 2 баллов). Сам skill НЕ пишет вердикт и НЕ
считает ELO — это делает отдельный инструмент записи:

```bash
python tools/record_verdict.py --task T-001 --winner b
```

Инструмент сам разрешает слоты modelA/modelB в реальные id (через
`answers/T-001/slots.json`), штампует `seq` + `recorded_at`, пишет
ELO-снэпшот и пересчитывает `index.json`. Вывод команды показывает
рейтинги до/после для обеих моделей.

### Шаг 3 (альтернатива): Судья вручную

1. Открыть чат с любой LLM (судья).
2. Скопировать промпт из [judge-prompt.md](judge-prompt.md).
3. Дать судье:
   - `tasks/T-001-<slug>/task.md` (задача)
   - `answers/T-001/modelA.md` (ответ 1, анонимно)
   - `answers/T-001/modelB.md` (ответ 2, анонимно)
4. Судья отвечает: оценки, победитель, обоснование (2–3 предложения).
5. Записать итог через веб-UI (шаг 4).

### Шаг 4: Записать вердикт

После того как судья (skill или ручной) выбрал победителя, результат
записывается единой точкой записи — `tools/record_verdict.py`. Для ручного
пути:

```bash
python tools/server.py
# → http://localhost:5000
```

В браузере, в форме «Записать результат»:
1. Модель A, модель B (выбора задачи нет — вердикт идёт в корзину `general`)
2. Кнопка «Победила A» / «Победила B» / «Ничья»
   (кнопки активны только когда выбраны две разные модели)
3. Форма вызывает ту же `record_verdict` — вердикт получает seq,
   recorded_at и ELO-снэпшот; index.json пересчитывается автоматически

Или через CLI (без сервера):
```bash
python tools/record_verdict.py --task general \
    --model-a <id-a> --model-b <id-b> --winner a
```

Аннулировать ошибочный вердикт (файл не удаляется — пишется tombstone):
```bash
python tools/record_verdict.py --void general/003 --reason "ошибка"
```

### Шаг 5: Leaderboard

Тот же `localhost:5000` — таблица рейтинга:
```
#  Модель              ELO   Побед  Поражений  Ничьих  Всего
1  <победитель>        1220  1      0          0       1
2  <проигравший>       1180  0      1          0       1
```
(Первый вердикт при K=40 даёт ±20 от 1200.)

Сверху — блок «Рекомендуем к прогону» (топ-3 несравнённых пар с причинами),
кнопка «Прогнать» подставляет пару в форму. Внизу — последние 20 записей истории ELO.

Или статичный экспорт (только чтение, с колонкой «Провайдер» и фильтром архивных):
```bash
python tools/generate_html.py
# → leaderboard.html (открыть в браузере)
```

## Добавление новой модели

Через веб-UI: кнопка «+ Добавить модель» → одно поле с названием → slug
генерируется автоматически (стартовый ELO 1200).

Или через CLI:
```bash
python tools/register_model.py --auto --id gemini-3-pro --name "Gemini 3 Pro"
```

Затем: ответ модели на существующую задачу (вручную в `answers/T-001/<id>.md`),
судейство против уже оценённых моделей (калибровка) — веб-UI сам предложит
пары с новой моделью первыми (у неё 0 игр).

## Архивация модели

Если модель устарела (вышла новая версия, отключена в IDE):

```bash
python tools/archive_model.py claude-sonnet-4.5
# → status: archived
# История и ELO сохраняются; в leaderboard.html скрыта по умолчанию
# (на сервере показывается наравне — ограничение MVP)
```

Разархивировать:
```bash
python tools/archive_model.py --restore claude-sonnet-4.5
```

## Новая версия модели

Когда выходит Claude Sonnet 4.6:
1. Зарегистрировать новый id:
   ```bash
   python tools/register_model.py --auto --id claude-sonnet-4.6 --name "Claude Sonnet 4.6"
   ```
2. Заархивировать старую:
   ```bash
   python tools/archive_model.py claude-sonnet-4.5
   ```
3. Прогнать новую на текущей задаче, сравнить с active-моделями.

## Новая задача

Когда текущая задача исчерпана (все модели прогнаны, достаточно вердиктов):
скопируй `tasks/_TEMPLATE.md` в `tasks/T-002-<slug>/task.md` и заполни.

Модели **не сбрасывают ELO** — рейтинг переносится. Новая задача
продолжает обновлять тот же глобальный ELO.
