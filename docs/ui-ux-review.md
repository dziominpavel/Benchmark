## 1. Аннулирование вердикта из консоли

**Статус:** `[x]` готово (волна 2).
**Сейчас.** Отмена — только из CLI: `python tools/record_verdict.py --void T-001/001 --reason "…"` (`tools/record_verdict.py:57`, `tools/elo.py:427` — `void_matchup`). Журнал получает tombstone-событие (`void_of`), реплей исключает аннулированный матч. В консоли нет ни кнопки, ни статуса: после аннулирования вердикт просто исчезает из рейтинга, аудит-след остаётся только в файле журнала. `record_verdict` уже возвращает `matchup_id` (`elo.py:424`), но success-редирект его не несёт (`server.py:2434`).

**Почему это важно.** Ошибка («не та модель», «не тот победитель», дубль) исправляется там же, где обнаруживается — в истории; сейчас для этого нужно помнить CLI и выполнять команду в терминале.

**Что сделать.**
- POST-роут `/verdict/void` с полями `matchup_id` и `reason`: проверка формата `T-NNN/NNN`, подтверждение, вызов `void_matchup`, редирект с success-сообщением.
- Кнопка «Аннулировать» — в строке истории (когда у вердикта есть `matchup_id`) и в списке вердиктов таска (п. 7).
- Ссылка «Отменить» — прямо в success-строке после записи: прокинуть `matchup_id` в редирект.
- Статус аннулирования — перечёркнутая строка с пометкой и причиной + фильтр «показать аннулированные» (п. 3), чтобы было видно: запись не потеряна, а именно аннулирована.
- (ревизия 2) В журнал через `void_matchup` уже пишется бесплатно; в консоль вернуть и аудит: кто/когда аннулировал (`recorded_at` события) — достаточно показать дату и причину в строке.

**Где менять.** `tools/server.py` (роут рядом с `record_verdict_route`, 2400; шаблон истории ~1100), `tools/elo.py` (`void_matchup`, 427). Формат журнала не менять.

**Эффект / трудоёмкость.** Высокий / низкая–средняя (размер M). Закрывает цикл «запись → проверка → исправление», разорванный между браузером и терминалом.
**Готово, когда:** отмена выполняется из истории в один клик с причиной; аннулированная запись видна как аннулированная; `python tools/elo.py --check` — exit 0; есть тест роута.
