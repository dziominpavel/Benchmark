Прогон модели B на задаче бенчмарка — **выполни задачу сам и запиши ответ**.

**Когда использовать:** когда задача создана и нужно прогнать модель B.
Ты (ассистент) выступаешь в роли участника B — читаешь задачу, изучаешь код,
находишь баги, пишешь ответ в файл. Перед началом прочитай `AGENTS.md` в Benchmark.

## Шаги

1. **Найди задачу:**
   - Пользователь указывает: `@benchmark-run-b T-002` (или просто `@benchmark-run-b`).
   - Явный task-id имеет приоритет. Без него используй `current_task` из
     `data/settings.yaml`; если он не задан — последнюю созданную задачу.
   - Найди `data/tasks/T-NNN-*/task.md`. Если заданной задачи нет, сообщи об этом,
     не подменяй её другой и не выбирай задачу по наличию чужих ответов.

2. **Прочитай task.md** — извлеки id, title, project, baseline_commit,
   источники требований, область анализа, ограничения и формат доказательств.
   Специальный формат конкретной задачи имеет приоритет над шаблоном ниже.

3. **Подготовь безопасный baseline по AGENTS.md и task.md:**
   - Зафиксируй HEAD и статус исходного проекта, не меняя его.
   - Checkout baseline выполняй только в новой отдельной копии своего прогона,
     созданной через `git clone --no-local --no-checkout`; проверь полный HEAD.
   - Не используй копию модели A или судьи. Не копируй секреты, реальные данные,
     `.env`, `.dev.vars`, логи и runtime-state из рабочего проекта.
   - Нельзя переключать/очищать рабочий репозиторий, запускать приложение,
     останавливать реальные процессы, делать deploy или remote migrations.
   - Если задача разрешает тесты, запускай их и проверяй патчи только в своей
     копии с синтетическими данными и локальными подменами. Отдельный каталог
     не изолирует сеть: предварительно проверь код теста и конфигурацию.

4. **Исследуй задачу самостоятельно.** Проверяй вызывающий код, контракты,
   достижимость сценариев и существующие guards/тесты. Не читай ответ A, прежние
   ответы, вердикты, ELO и реестр моделей; соблюдай запрет задачи на готовые
   аудиты и историю исправлений. Гипотезы отделяй от доказанных находок.
   Сначала проверяй дефект на baseline, затем исправление. Недоступный запуск
   отмечай честно — предложенный тест не является выполненным.

5. **Напиши ответ в файл:**
   ```
   C:/projects/Benchmark/data/answers/<task-id>/modelB.md
   ```
   Для повторной записи соблюдай порядок фиксации нового текста из AGENTS.md:
   старый файл своего слота нельзя читать для помощи в решении задачи.
   Для T-002 используй расширенный формат из task.md, включая baseline,
   воспроизведения, тесты и журнал проверок. Если задача не задаёт свой формат:

    ````markdown
    ---
    task: <task-id>
    date: <YYYY-MM-DD>
    ---

   # Ответ на задачу <task-id>

   ## Анализ
   <!-- Краткий обзор что рассмотрено -->

   ## Находки
   ### 1. [Название бага]
   **Файл:** `path/to/file.kt:NN`
   **Критичность:** критичный / средний / низкий
   **Описание:** ...

   **Пример:**
   <!-- Входные данные, на которых баг проявляется -->

   **Исправление:**
   ```kotlin
   // исправленный код
   ```

   ### 2. ...

   ## Граничные случаи (проверено, не баг)
   <!-- Что проверил, почему работает корректно -->

   ## Дополнительные находки
   <!-- Неиспользуемые импорты, стиль, и т.д. -->
   ````

6. **После записи файла:**
   - Сообщи: "Ответ модели B записан в `data/answers/<task-id>/modelB.md`".
   - Кратко назови число подтверждённых анализом находок, отдельно — гипотезы,
     и укажи существенные ограничения проверки.
   - Не запускай A и не выступай судьёй; следующий слот — в новом чате.

7. **Проверь сохранность исходного проекта:**
   - Сравни его HEAD и статус с началом и сообщи о расхождениях, если они есть.
   - Не выполняй автоматическую очистку, checkout/reset/clean/stash и не удаляй
     изменения, появившиеся за время анализа. Свою копию оставь отдельно.

## Правила

- **Ты делаешь работу сам** — не выводишь промпт для копипасты вместо анализа.
- **Имя файла ответа** — `modelB.md` (всегда); поле `model` во front matter MUST NOT присутствовать — слот определяется именем файла.
- **Не пиши `slots.json`** и не сохраняй свой реальный `id` нигде (имя, шапка, тело) — участник анонимен.
- **Ответ = MD-файл** с кодом и доказательствами, не изменения рабочего проекта.
- **baseline_commit** — фиксирован для обоих слотов; checkout только в своей копии.
- **Полнота без выдумок** — все установленные причины и проверенные граничные
  случаи, без обязательной квоты багов и без раздувания дублей.
- **UI-тексты и ответ на русском**, код и идентификаторы на английском.
- **Не изменяй рабочий проект, task.md, инструкции, реестры и вердикты.**
