Координатор батч-судейства — прогоняет N пар (по умолчанию 10) и отдаёт ссылки с предзаполнением в порядке живого топа UI. Вердикты НЕ записывает — их вбивает пользователь через UI.

**Когда использовать:** команда `@benchmark-batch-judge [N] [T-NNN]`. Без N — 10, без таска — текущий топ активных тасков из `get_recommendations` (обычно T-001).

## Шаги

1. **Снапшот и топ:**
   - Зафиксируй `git status --short` и `git rev-parse HEAD` Benchmark (не меняй проект).
   - Возьми `get_recommendations(generate_index(), top_n=K)` с запасом (K = N × 3): сортировка уже в порядке UI.
   - Смапь `id → name` из `models.yaml`; проверь наличие файлов `data/answers/<TASK>/<name>/*.md`. Пары без обоих файлов пропусти и перечисли пропущенные отдельно (флаги `answer_flags.yaml` могут врать).
   - Возьми первые N пар С ФАЙЛАМИ. Это замороженная пачка.

2. **Анонимизация (обязательно):**
   - Скопируй каждую пару в `C:\Users\Dziom\AppData\Local\Temp\opencode\batch-<TASK>-<N>\pair<i>\modelA.md|modelB.md` + `meta.txt` (`pair<i>: A=<id> B=<id> task=<TASK>`).
   - Судьям давай ТОЛЬКО эти пути — никогда оригиналы с именами моделей.

3. **Параллельное судейство:**
   - Запусти N суб-агентов параллельно, каждый строго по `benchmark-judge`: только `task.md` + свои `modelA.md/modelB.md`.
   - Запрети каждому: `index.json`, `models.yaml`, `matchups/`, чужие пары, ELO, выяснение реальных ID, запись в репозиторий, `record_verdict`.
   - Каждый: своя копия baseline (`git clone --no-local --no-checkout`, checkout только там), шкала задачи (T-001 — /50, ничья при разнице <2; T-002 — своя рубрика /100 из task.md).
   - Собери строго по порядку pair1..N: победитель `a|b|draw`, счёт, 3–6 пунктов с `файл:строка`.

4. **Сверка порядка с живым UI:**
   - Перед выдачей заново вызови `get_recommendations(top_n=K)` и отсортируй пачку в ТЕКУЩЕМ порядке UI (ELO плывёт после каждой записи — замороженный порядок всегда разъедется).
   - Выдай таблицу: `TASK | A | B | победитель | счёт` + ссылку предзаполнения на каждую пару:
     `http://localhost:5000/?model_a=<A>&model_b=<B>&task=<TASK>`
   - Напомни: сервер должен быть перезапущен после патча предзаполнения (`stop.bat` → `start.bat`); порт может отличаться (`find_free_port`).

5. **Запреты:**
   - Не записывай вердикты (ни через UI, ни `record_verdict.py`), не коммить (`tools/server.py`, спеки) без явной просьбы.
   - После пачки предложи режим досылки: «записал — пересчитал топ — дослал ссылки».

## Формат выдачи

```
1. <idA> vs <idB> → **<a|b|draw>** (XX:YY)
   http://localhost:5000/?model_a=<idA>&model_b=<idB>&task=<TASK>
...
Пропущены (нет файлов): <id...>
```

## Правила

- Независимость судей как в `benchmark-judge`; анонимность слотов A/B.
- Порядок выдачи = живой топ UI на момент выдачи, не порядок заморозки.
- Кратко, по-русски; код и ID — на английском.
