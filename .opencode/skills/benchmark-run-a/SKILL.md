Прогон модели A на задаче бенчмарка — **выполни задачу сам и запиши ответ**.

**Когда использовать:** когда задача создана и нужно прогнать модель A.
Ты (ассистент) выступаешь в роли участника A — читаешь задачу, изучаешь код,
находишь баги, пишешь ответ в файл.

## Шаги

1. **Найди задачу:**
   - Пользователь указывает: `@benchmark-run-a T-001` (или просто `@benchmark-run-a`)
   - Если task-id не указан — используй последнюю созданную задачу
   - Найди: `data/tasks/T-NNN-*/task.md`

2. **Прочитай task.md** — извлеки: id, title, project, baseline_commit,
   описание, что искать, критерии, ограничения.

3. **Перейди к коду проекта:**
   ```
   cd C:/projects/<project>
   git checkout <baseline_commit>
   ```

4. **Изучи файлы, указанные в задаче.** Читай исходный код внимательно.
   Ищи баги, граничные случаи, нарушения контракта — всё что описано в task.md.

5. **Напиши ответ в файл:**
   ```
    C:/projects/Benchmark/data/answers/<task-id>/modelA.md
   ```

   Формат — Markdown с front matter:
   ```markdown
   ---
   task: <task-id>
   model: modelA
   date: <YYYY-MM-DD>
   ---

   # Ответ на задачу <task-id>

   ## Анализ
   <!-- Краткий обзор что рассмотрено -->

   ## Находки
   ### 1. [Название бага]
   **Файл:** `path/to/file.kt:NN`
   **Критичность:** критичный / средний / низкий
   **Описание:** ...

   **Пример:**
   <!-- Входные данные, на которых баг проявляется -->

   **Исправление:**
   ```kotlin
   // исправленный код
   ```

   ### 2. ...

   ## Граничные случаи (проверено, не баг)
   <!-- Что проверил, почему работает корректно -->

   ## Дополнительные находки
   <!-- Неиспользуемые импорты, стиль, и т.д. -->
   ```

6. **После записи файла:**
   - Скажи: "✓ Ответ модели A записан в `data/answers/<task-id>/modelA.md`"
   - Кратко перечисли сколько багов найдено

8. **Очисти проект:**
   ```
   cd C:/projects/<project>
   git checkout . && git clean -fd
   ```

## Правила

- **Ты делаешь работу сам** — не выводишь промпт для копипасты, а анализируешь код
- **Имя файла ответа** — `modelA.md` (всегда)
- **Не пиши `slots.json`** и не сохраняй свой реальный `id` — участник анонимен
- **Ответ = MD-файл** (анализ + код в блоках), не изменяй код в проекте
- **baseline_commit** — сделай git checkout перед анализом
- **Максимально полный ответ** — все граничные случаи, все находки
- **UI-тексты на русском**, код и идентификаторы на английском
- **Не изменяй проект** — только читаешь и анализируешь
