## Why

Блок «Рекомендуемые модели к прогону» сейчас советует пары без проверки наличия ответов (`answer_flags.yaml`): пользователь нажимает «Прогнать», а судить нечего — хотя бы у одной стороны нет ответа на `recommended_task`. Прогресс прогона считает ячейки `(таск, пара)` только по вердиктам и не различает «надо судить» и «надо добывать ответы». При новой модели и нескольких активных тасках это даёт нелогичные советы и непонятный процент.

## What Changes

- Рекомендация строится только из READY-ячеек: активная пара + активный таск + оба ответа есть (`answer_flags`) + нет неаннулированного вердикта в этом таске. BLOCKED-ячейки (нет хотя бы одного ответа) невидимы для рекомендаций.
- Приоритет тасков строгий лексикографический (`T-001` > `T-002` > ...): пока есть хоть один READY в `T-001`, рекомендации из `T-002` не показываются. Внутри одного таска сохраняется сортировка `pair_games` (глобально) → тир калибровки → близость ELO.
- Блок показывает только топ-1 (одна карточка + «Прогнать»); листание топ-3 (`→`, счётчик, `showRec`/`nextRec`) удаляется. **BREAKING**: вывод `get_recommendations` фактически используется как топ-1.
- Прогресс становится динамическим: `TOTAL = READY + DONE` (BLOCKED исключены из числителя и знаменателя), `процент = DONE / TOTAL` с cap 100%. Повторные вердикты в одной ячейке счёт не меняют. Инвариант: есть READY → процент < 100%.
- Режим рематчей — отдельная доп-фича: когда READY пуст, топ-1 показывает рематч по простой сортировке (`pair_games` → близость ELO, флаги игнорируются) с пометкой «доп. точность»; прогресс при этом 100%. Когда `TOTAL = 0` — черта и пустое состояние без напоминания про долги.

## Capabilities

### New Capabilities

*(нет)*

### Modified Capabilities

- `pairing-algorithm`: кандидаты только READY, строгий приоритет тасков, вывод топ-1, отдельный режим рематчей без учёта флагов.
- `run-progress`: динамический знаменатель `READY + DONE`, исключение BLOCKED, cap 100%, инвариант `READY > 0 → < 100%`.
- `leaderboard-ui`: блок показывает одну карточку топ-1 без листания; состояние 100% (рематч) и пустое состояние; статус-бар на динамическом покрытии.

## Impact

- `tools/server.py`: `get_recommendations`, `format_reason`, `leaderboard()`, `INDEX_TEMPLATE` (блок рекомендаций, JS `usePair`/`showRec`/`nextRec`).
- `tools/elo.py`: `get_coverage` (учёт `answer_flags`), сводка для статус-бара.
- `tools/test_elo.py`, `tools/test_pairing.py`: новые сценарии (приоритет тасков, BLOCKED-невидимость, топ-1, cap 100%).
- `data/index.json`: формат не меняется; флаги читаются из `data/answer_flags.yaml` на лету.
