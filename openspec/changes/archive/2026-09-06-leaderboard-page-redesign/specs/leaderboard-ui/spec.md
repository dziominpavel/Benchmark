# leaderboard-ui Specification

## MODIFIED Requirements

### Requirement: Таблица рейтинга (сервер)

Главная страница SHALL показывать таблицу с колонками: `#`, `Модель`, `ELO`,
`Побед`, `Поражений`, `Ничьих`, `Всего`, отсортированную по ELO по убыванию.
Колонки `Провайдер` в серверной таблице НЕТ (она есть только в статичном экспорте).
Строка статистики SHALL показывать «Моделей: N · Вердиктов: M · Обновлено: D».
Таблица рейтинга SHALL находиться в левой колонке главной страницы (≈60% ширины);
на узких экранах колонки SHALL складываться вертикально — таблица сверху.

#### Scenario: Отображение рейтинга

- **WHEN** пользователь открывает страницу сервера
- **THEN** видит таблицу всех моделей из `index.json` по убыванию ELO
- **AND** ELO отображается как обычное число без цветного фона, бейджа или цветной подсветки
- **AND** таблица находится в левой колонке
- **AND** справа видна панель добавления результата

#### Scenario: Узкий экран

- **WHEN** viewport шириной менее 900 px
- **THEN** контент складывается в одну колонку
- **AND** таблица рейтинга идёт первой, панель добавления результата — под ней

#### Scenario: Нет моделей

- **WHEN** в реестре нет моделей
- **THEN** таблица заменяется пустым состоянием «Нет моделей. Нажмите «+ Добавить модель»…»

#### Scenario: Меньше двух моделей для вердикта

- **WHEN** моделей меньше 2
- **THEN** форма вердикта заменяется состоянием «Нужно минимум 2 модели…»

### Requirement: История ELO

История `elo_history` SHALL показываться в сворачиваемом блоке внизу главной
страницы. По умолчанию блок SHALL быть свёрнут. Раскрытие SHALL происходить по
клику на заголовок блока. Внутри SHALL отображаться не более 20 записей на
одну страницу (новые сверху). Навигация SHALL осуществляться номерами страниц.
Каждая строка SHALL содержать имена обеих моделей, ELO до и после вердикта
для обеих моделей, дельты (+N зелёным / −N красным / ±0 серым), дату и
`recorded_at`. Запись SHALL соответствовать одному вердикту, а не одной стороне.

#### Scenario: История свёрнута по умолчанию

- **WHEN** пользователь открывает главную страницу
- **THEN** блок «История» свёрнут
- **AND** записи не видны

#### Scenario: Раскрытие и пагинация

- **WHEN** пользователь кликает заголовок «История»
- **THEN** блок раскрывается и показывает первые 20 записей
- **AND** при наличии более 20 записей видны номера страниц
- **AND** клик по номеру страницы показывает соответствующие 20 записей

#### Scenario: История после вердикта

- **WHEN** записан вердикт A > B
- **THEN** в истории одна строка:
  - `A vs B  1200 → 1220 (+20)  1200 → 1180 (−20)  2026-09-05 19:32`
- **AND** не создаётся отдельная строка `B vs A`

#### Scenario: Ручная запись через UI

- **WHEN** пользователь ввёл вердикт через веб-форму
- **THEN** в истории появляется одна строка с реальными id модели и соперника
- **AND** для обеих сторон видны ELO до, ELO после и дельта
- **AND** строка содержит `recorded_at`

### Requirement: Статичный экспорт HTML

Скрипт `tools/generate_html.py` SHALL генерировать `leaderboard.html` из
`index.json` (только чтение, без формы). Таблица экспорта, в отличие от серверной,
SHALL содержать колонку `Провайдер`, серую подсветку архивных строк и чекбокс
«Показывать архивные» (по умолчанию скрыты). Статический HTML SHALL повторять
двухколоночный layout страницы сервера: leaderboard слева, справа — панель со
справкой о запуске сервера для записи вердиктов. История SHALL быть
сворачиваемой, пагинированной по 20 записей на страницу. При отсутствии
`index.json` скрипт SHALL завершаться с ошибкой и подсказкой запустить `python tools/elo.py`.

#### Scenario: Генерация статичного HTML

- **WHEN** пользователь выполняет `python tools/generate_html.py`
- **THEN** создаётся `leaderboard.html`, открываемый через `file://`
- **AND** leaderboard находится слева
- **AND** справа видна панель с пометкой о запуске сервера
- **AND** внизу сворачиваемый блок истории с пагинацией по 20 записей

## ADDED Requirements

### Requirement: Панель добавления результата

Главная страница SHALL содержать панель справа (≈40% ширины), в которой
располагаются блок рекомендаций пар и форма записи вердикта. Рекомендации
SHALL находиться над формой. Кнопка «Прогнать» SHALL подставлять рекомендуемую
пару в dropdowns формы. На узких экранах панель SHALL располагаться под таблицей.

#### Scenario: Отображение панели

- **WHEN** пользователь открывает главную страницу
- **THEN** справа виден блок «Рекомендуемые модели к прогону»
- **AND** под ним видна форма «Записать результат»
- **AND** кнопка «Прогнать» заполняет dropdowns формы
