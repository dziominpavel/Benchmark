# Design

## Context

См. `proposal.md` — Why. Метка сборки резолвится в `tools/server.py` при импорте
модуля (`_APP_BUILD_TIME`) и дальше только подставляется в шаблоны; тот же путь
использует статический слепок витрины. Сейчас оба резолвера приводят момент
к локальной зоне машины: `.astimezone()` для git-времени и
`datetime.fromtimestamp(mtime)` для файлового фолбэка. Поэтому локальная консоль
в Минске показывает `21:23`, а слепок, собранный GitHub Actions в UTC, — `18:23`.

Ограничения: `zoneinfo.ZoneInfo("Europe/Minsk")` на этой Windows-машине падает
(`ZoneInfoNotFoundError`, пакет `tzdata` не установлен); git-подпроцессы на пути
запроса недопустимы (резолв уже вынесен на импорт); слепок запекает строку
в HTML на момент экспорта.

## Goals / Non-Goals

**Goals:**

- Одна и та же строка сборки — минское время с меткой `МСК` — в живой консоли,
  в слепке витрины и в фолбэке без git, независимо от зоны машины.
- Сохранить резолв при импорте и отсутствие новых зависимостей.
- Сделать тест сборки независимым от часового пояса тестовой машины.

**Non-Goals:**

- Другие отметки времени консоли (`recorded_at`, даты истории, даты задач)
  не конвертируются — они показываются в той зоне, в какой записаны.
- Настройка зоны пользователем, параметр окружения `TZ` и правки workflow
  витрины: витрина получает исправленное значение из кода Benchmark.
- Переход на именованные зоны IANA и пакет `tzdata`.

## Decisions

- **Фиксированное смещение `timezone(timedelta(hours=3))`, а не
  `ZoneInfo("Europe/Minsk")`.** Беларусь живёт в UTC+3 круглый год с 2011 года,
  переходов на летнее время нет; фиксированное смещение даёт тот же результат
  без зависимости `tzdata`, которая нужна `zoneinfo` на Windows. Альтернатива
  с `ZoneInfo` отклонена: ради одной метки добавлять пакет и менять лок-файл
  несоразмерно. Плата: если правила Беларуси когда-нибудь изменятся, правка —
  в одной константе `MINSK_TZ`.
- **Метка `МСК` — часть `_BUILD_TIME_FMT`, а не шаблона.** Так подвал, секция
  «О консоли» и слепок автоматически получают единый текст из одной точки,
  а тесты фиксируют одну строку. Альтернатива — дописывать `МСК` в `shell.html`
  и шаблоне настроек — отклонена: два места правки и риск расхождения.
- **Общий форматтер для обоих источников.** Небольшой хелпер
  `_format_build_time(moment: datetime) -> str` принимает aware-момент и
  форматирует его в `MINSK_TZ`; `_git_build_time` парсит `%cI` и вызывает
  хелпер, `_file_build_time` строит момент через
  `datetime.fromtimestamp(mtime, tz=MINSK_TZ)`. Это убирает последний путь,
  зависящий от локальной зоны, и даёт тестам чистую точку входа без git
  и без файловой системы.
- **Тесты — на фиксированных моментах.** Вместо повторения
  `.astimezone()` в тесте (как сейчас в `test_version_badge`) проверяется
  конкретный результат: `2026-10-19T18:23:54+00:00` → `19.10.2026 21:23 МСК`,
  `2026-10-19T21:23:54+03:00` → та же строка. Файловый фолбэк проверяется
  фиксированным epoch с заранее посчитанным минским временем. Так тест ловит
  регрессию и на UTC-машине CI, и на минской рабочей машине.
- **Подсказка в секции «О консоли» дополняется.** Текст «Сборка — дата и время
  коммита…» уточняется словами «по минскому времени», чтобы пояснение
  происхождения значений соответствовало отображению.

## Risks / Trade-offs

- [Беларусь вернёт переход на летнее время] → смещение сосредоточено
  в константе `MINSK_TZ`; при необходимости меняем на `ZoneInfo` + `tzdata`.
- [В опубликованном слепке останется запечённое `18:23` до пересборки] →
  после правки нужен повторный экспорт слепка штатным конвейером витрины;
  в `CHANGELOG` и задачах это отдельный шаг.
- [Долгоживущий процесс после правки покажет старую строку] → ожидаемо:
  `_APP_BUILD_TIME` фиксируется при импорте, значение обновляется
  перезапуском — как и у версии.
- [Тест привязан к приватному хелперу `_format_build_time`] → допустимо:
  хелпер — часть модуля `tools/server.py`, тесты уже обращаются к приватным
  `resolve_*`; в обмен получаем детерминированную проверку без git.

## Migration Plan

1. Правки `tools/server.py`, `tools/test_data_cache.py`, подсказки в шаблоне
   настроек и записи `CHANGELOG.md` — в одном change.
2. Прогоны: `uv run python tools/test_data_cache.py`,
   `uv run python tools/test_export.py`, `openspec validate --all`.
3. Перезапуск локальной консоли — подхватить новую константу (значение
   резолвится при импорте).
4. После мержа (при необходимости — релиза) — пересборка статического слепка
   штатным конвейером витрины, чтобы опубликованный HTML получил `21:23 МСК`.
   Откат — revert коммита правки; данные и API не затрагиваются.
