## Context

См. `proposal.md` (Why). Факты: `get_recommendations` уже возвращает `tier/elo_diff/pair_games/pair_wins_*` (ничего дотягивать не надо); кнопка «Прогнать» уже предзаполняет форму (`usePair`); имя модели сейчас ведёт на `/edit/<id>`; `elo_history` в `ensure_index()` содержит всё для графика и истории (стороны, `winner`, снапшоты, `recorded_at`/`date`). Изменений `elo.py` и формата данных не требуется.

## Goals / Non-Goals

**Goals:**
- Страница `/model/<id>` на существующих данных кэша.
- Обоснование пары без изменения вывода `get_recommendations`.
- Легенда, топ-3, секция архивных — только шаблоны + лёгкая логика роута.

**Non-Goals:**
- Переименование «Прогнать» (см. D2); обоснование судьи; экспорт/импорт; смена формулы winrate (H2H использует тот же `format_winrate`, что таблица).

## Decisions

1. **Обоснование считает `leaderboard()`, а не `get_recommendations`.**
   В `pairing-algorithm` действует запрет на поле `reason` в выводе («Поле `reason` SHALL NOT возвращаться»). Поэтому в `server.py` — чистая функция `format_reason(rec)` из готовых полей (`pair_games`, `pair_wins_a/b`, `elo_diff`, `tier`), результат кладётся в словарь рекомендации под ключом `reason` уже после вызова (вывод pairing-движка не меняется).
   Формат: `не встречались · Δ=N` (+ ` · новая модель` при `tier==0`); рематч: `счёт A:B · Δ=N` (порядок карточки).
2. **Новой кнопки «Принять пару» не будет — её роль уже играет «Прогнать».**
   Существующая кнопка подставляет пару в dropdowns и прокручивает к форме — ровно то, что требовал proposal под другим именем. Переименование отвергнуто: churn в спеках и привычке ради нулевой функциональности. В спеке остаётся «Прогнать».
3. **Чистые функции страницы модели — в `render_helpers.py`, роут и шаблон — в `server.py`.**
   `get_model_detail(index_data, model_id)` (агрегация: точки графика, H2H, история; `None` для неизвестного id → 404) и `build_elo_svg(points)` (SVG-строка) — без Flask, тестируемы напрямую. Роут `/model/<model_id>` только дёргает их и рендерит `MODEL_TEMPLATE`.
4. **Имя модели ведёт на `/model/<id>`, правка — через иконку.**
   Ячейка: `<a href="/model/...">имя</a>` + компактная «изменить» на `/edit/<id>` (маршрут правки жив, страница `/add` со списком тоже ссылается на него).
5. **Топ-3 считает роут, шаблон только проверяет множество.**
   `leaderboard()` передаёт `top3_ids` (первые 3 активных по ELO); медали/класс — если `m.id in top3_ids` и `filter != 'inactive'`. Правило «ELO — обычное число» не задето (красится строка).
6. **Секция архивных — `<details>` под таблицей в режиме `active`.**
   Роут уже знает всех моделей; передаёт `archived_list` (имя, id, elo, сортировка по ELO). В `all`/`inactive` без изменений.

## Risks / Trade-offs

- [Risk] SVG при 500 матчах — сотни точек в строке, страница тяжелеет. Mitigation: полилиния из ~500 точек — десятки КБ, приемлемо для MVP; diet шага 4 кэш не трогает в части истории.
- [Risk] `format_winrate` делит на ноль при 0 игр. Mitigation: в H2H и истории вызывать только при встречах >0 (у соперника всегда ≥1 встреча); график при 0 играх — отдельное пустое состояние.
- [Risk] Модель переименована после вердиктов — снапшоты имён в журнале отсутствуют (только id). Mitigation: страница всегда показывает текущее имя из реестра; это консистентно с лидербордом.
