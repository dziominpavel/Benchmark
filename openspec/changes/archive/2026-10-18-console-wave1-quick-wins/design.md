# Design

## Context

См. `proposal.md` — Why. Рамки, задающие решение:

- Консоль — один Flask-файл `tools/server.py`: Jinja-шаблоны хранятся строками (`INDEX_TEMPLATE`, `SETTINGS_TEMPLATE`, `EDIT_TEMPLATE`), мелкий inline-JS живёт там же (образец — `usePair`, `tools/server.py:1071`); правила оформления — `tools/static/css/console.css` (токены, dark-first: базовый блок `:root, [data-theme="dark"]`, переопределения — `[data-theme="light"]`); общий шелл — `tools/templates/shell.html`; статика отдаётся Flask (`Flask(__name__)` → `/static`, файл `tools/static/icon.svg` существует).
- Токен `--caption-opacity` (`console.css:26`) объявлен только в тёмном блоке и наследуется светлой темой; потребители — `.model-caption` (`console.css:1256`) и `.dist-caption` (`console.css:1252`).
- Рекомендации: `get_recommendations(top_n)` уже параметризован (главная использует `top_n=1`); `format_reason` — `server.py:835`; карточка — `server.py:989-1008`; очередь — `server.py:1725-1775`; строка статистики — `server.py:885`; плашка прогресса — `server.py:863-881`.
- Сводные числа: покрытие (`run-progress`) и `matchups_summary`/`elo_history` из `data/index.json` через `data_cache` (инвалидация по дайджесту). Проверено на срезе: 602 записи `elo_history`, уникальных пар 595 → рематчей 7.
- Тестовая обвязка: `tools/test_data_cache.py` (роуты через Flask test client), `tools/test_pairing.py` (формат полей рекомендации), `tools/test_perf.py` (маркеры HTML на пределе 1000 моделей), `tools/test_export.py` (маркер `__root__icon.svg` в слепке).
- Затрагиваемые прошлые решения: `2026-09-22-answer-aware-progress` ввёл запрет карусели (тогда top-3 мог содержать BLOCKED-пары); `2026-10-17-dim-model-captions` закрепил единый `--caption-opacity: 0.45`.

## Goals / Non-Goals

**Goals:**

- Закрыть волну 1 обзора (`docs/ui-ux-review.md`, ревизия 2): контраст подписей ≥ AA, роли сообщений, `scope` таблиц, подтверждения, противоречие очереди, единая сводка, компактная плашка при 100%, favicon, ссылки в карточке, «Другая пара».
- Уложиться в существующие паттерны: Jinja-строки, inline vanilla JS, токены CSS; URL и форматы данных не менять.

**Non-Goals:**

- Волны 2–4 обзора: цикл вердикта (аннулирование), форма вердикта, фильтры истории, аналитика, пункты 3/5/10.
- Изменения `pairing-algorithm`, `run-progress`, формата журнала и `index.json`.
- Возврат карусели: стрелки `→`, счётчик `N / M`, URL-состояние `showRec`/`nextRec` остаются запрещёнными.

## Decisions

### D1. Потемные значения контраста подписей (0.75 тёмная / 0.90 светлая)

Токен `--caption-opacity` получает разные значения по темам: `0.75` в базовом блоке (`:root, [data-theme="dark"]`) и `0.90` в `[data-theme="light"]`. Потребители (`.model-caption`, `.dist-caption`) не меняются.

Замеры (WCAG 2.x: `--muted` × непрозрачность на фоне `--surface`):

- тёмная тема (`#9aa7b8` на `#12141c`): 0.45 → 2.49:1; 0.60 → 3.47:1; 0.75 → 4.74:1; порог AA достигается при ≈ 0.73;
- светлая тема (`#55606d` на `#ffffff`): 0.45 → 2.01:1; 0.60 → 2.65:1; 0.90 → 5.04:1; порог AA — при ≈ 0.86.

Альтернативы: единый компромисс 0.60 — не проходит AA ни в одной теме (3.47 / 2.65); единый 0.90 для обеих тем — тёмная пересвечена (6.30:1) и теряет приглушённость; отдельный токен цвета вместо непрозрачности — лишняя сущность без выгоды.

Осознанно повышаем прежнюю задумку «0.45, не засоряет экран» (change `dim-model-captions`) до минимально проходящей AA; приглушённость сохраняется относительно базового текста.

### D2. Роли сообщений и `scope="col"` у таблиц

`role="status"` добавляется контейнерам `.alert-success`, `role="alert"` — `.alert-error`; правка во всех 7 парах шаблонов (главная, модель, аналитика, добавление, редактирование модели, редактирование таски, настройки). Сообщения остаются серверными (после редиректа), без JS-зависимостей; альтернатива с `aria-live`-регионом через JS отклонена.

`scope="col"` добавляется всем `<th>` (26 штук в шаблонах; все заголовки — столбцовые, строковых `th` в консоли нет). Внешний вид не меняется; альтернатива с `<caption>`/`aria-labelledby` — избыточна.

### D3. Подтверждения: inline `confirm()` на формы

- Форма редактирования модели (`server.py:1399`, `<select name="status">`): на форму добавляются `data-status` (текущий статус) и `data-name`; `onsubmit="return confirmModelStatus(this)"`. Хелпер подтверждает только переход «не архив → архив» (`select[name="status"].value === 'archived' && form.dataset.status !== 'archived'`). Обычное сохранение и разархивация диалога не вызывают.
- Форма удаления значения справочника (`server.py:1807+`): `onsubmit="return confirmDelete(this)"`, объект передаётся через `data-value` (а не подстановкой значения в JS-строку — исключает проблемы экранирования кавычек), текст: «Удалить значение «X» из справочника?».
- Альтернативы: серверное двухшаговое подтверждение (страница-подтверждение) — лишние роуты и шаблоны для локальной консоли; глобальный перехватчик всех форм — неявно и шире необходимого.
- Trade-off: без JS подтверждение не сработает (форма отправится). Для локальной консоли принято; серверные проверки (нельзя удалить используемое значение; архивация не теряет данные) сохраняются независимо, в read-only-режиме формы отключены и подтверждение недостижимо.

### D4. Очередь: счётчики, обоснование, объяснение рематча

- Заголовок карточки (`server.py:1726`): убирается суффикс `(N)`.
- Строка счётчиков (`server.py:1728`): `открытых: N` (разбивка по таскам — существующей скобкой), `рематчей: M` — только при показанной строке рематча (`M = len(rematch)`), затем существующее `закрыто D из T`.
- Таблица (`1742-1750`): четвёртая колонка «Обоснование»; значения — `format_reason(...)` тех же рекомендаций (поля `tier`, `elo_diff`, `pair_games`, `pair_wins_*` уже есть). Обоснование переиспользует функцию главной, а не изобретается в шаблоне, — строки на главной и в очереди не разойдутся.
- Строка рематча (`1760-1773`): получает ту же колонку и обоснование.
- Пустое состояние (`1759`): если ниже показывается строка рематча — «Открытых пар нет. Ниже — матч для доп. точности (рематч).»; если рематча нет — «Открытых пар нет.» (текст не обещает строку, которой нет).
- Контекст страницы: к элементам `queue` и `rematch` добавляется `reason`, в контекст — `queue_rematch_count`.

### D5. Формат строк «личные встречи» и «обоснование»

- `h2h_label` (`server.py:729-734`): при `pair_games == 0` — без изменений; при `pair_games > 0` — «личные встречи: {N}» плюс « · ничьих {D}», если `D = N − wins_a − wins_b > 0`.
- `format_reason` (`server.py:835-851`): без истории — без изменений; с историей — «счёт по победам {wins_a}:{wins_b} · Δ={diff}».
- Итог: счёт печатается один раз (в обосновании), ничьи видны в строке встреч; случай «одна ничья» читается как «личные встречи: 1 · ничьих 1» + «счёт по победам 0:0 · Δ=…» вместо голого «счёт 0:0».
- Альтернатива: оставить счёт в строке встреч, а обоснование сократить до «Δ=N» — потеряна объясняющая часть; выбранный вариант сохраняет обе строки информативными.
- Тесты: обновить ожидание `tools/test_pairing.py:197` («личные встречи: 2 · счёт 1:1» → «личные встречи: 2»), добавить кейс с ничьими; консольные проверки новых строк — в `test_data_cache.py`.

### D6. «Другая пара»: top-3 без перезагрузки

- `leaderboard()` запрашивает `get_recommendations(top_n=3)`; в шаблоне рендерятся до трёх вариантов карточки (у каждого свой «Прогнать» и свои ссылки имён), первый видим, остальные `hidden`; кнопка «Другая пара» (показывается при ≥2 вариантах) циклически переключает видимость inline-скриптом (по образцу `usePair`, без библиотек).
- В режиме рематчей вариантами становятся до трёх рематчей (пометка «доп. точность: рематч» у каждого).
- Альтернативы: URL-параметр `?rec=N` с серверным рендером — перезагрузка сбрасывает прокрутку и состояние формы, лишние ключи кэша; карусель со стрелками — остаётся запрещённой (см. дельту).
- Граница с изменением `answer-aware-progress` зафиксирована в требовании: стрелки, счётчик `N / M`, URL-состояние `showRec`/`nextRec` SHALL NOT существовать; прежний запрет обосновывался BLOCKED-мусором в top-3 — сейчас кандидаты READY-фильтрованы сервером, и ограничение смягчается одной кнопкой.

### D7. Единая сводка и счётчик рематчей

- Состав: `Моделей: … · Вердиктов: N (рематчей: R) · Пары: F/T · Таски: KA из KM`; на главной в конце — существующее «Обновлено: …».
- `Пары` — покрытие видимых ячеек (та же метрика, что у плашки прогресса); `Вердикты` — текущий счётчик `matchups_count` (`server.py:885`, `2250`); `R` — `matchups_count − число уникальных пар`; уникальные пары считаются по `elo_history` (`model_a_id`/`model_b_id`, `frozenset`); проверено: 602 − 595 = 7. Расчёт оборачивается в `data_cache` (инвалидация по дайджесту), чтобы не пересчитываться дважды на главную+настройки.
- `(рематчей: R)` показывается только при `R > 0`.
- Модели: на главной счётчик сохраняет текущее фильтр-зависимое поведение (требование «Границы действия фильтра» не меняется); в настройках — «Моделей: A из M» (активные из всех). Таски — активные из известных.
- Размещение: главная — на месте строки статистики (`server.py:885`); настройки — новый блок `.stats` сразу после `settings-nav` (`server.py:1517-1523`). Числа — ссылки: `/settings#models`, `/history`, `/settings#recommendation-queue`, `/settings#tasks` (все анкоры уже существуют: `1526`, `1597`, `1725`).
- Альтернатива: убрать прогресс-плашку и оставить сводку — отклонено: плашка — самостоятельный progressbar-блок (a11y), нужна при частичном покрытии; в волне ограничиваемся компактным видом при 100%.

### D8. Компактная плашка прогресса при 100%

Ветка в `INDEX_TEMPLATE` (`863-881`): при `coverage_done` вместо бара и meta рендерится одна строка «Прогресс прогона — 100% · все пары закрыты» (компактный вид — существующий класс `progress-card--done` плюс новый модификатор в CSS). Семантика `progressbar` исчезает вместе с баром — в компактном виде это статусная строка, а не виджет прогресса. Альтернатива «убрать плашку совсем» — отклонена: теряется заголовок «Прогресс прогона», а состояние завершения полезно видеть.

### D9. Favicon живой консоли

`tools/templates/shell.html:9-10`: существующая mirror-ветка (`__root__icon.svg` только при `read_only()`) расширяется `{% else %}<link rel="icon" href="/static/icon.svg">{% endif %}`. Flask с `Flask(__name__)` отдаёт `tools/static` по `/static`; файл `tools/static/icon.svg` существует, новых роутов не требуется. Слепок и `test_export.py` не меняются (маркер сохраняется).

## Risks / Trade-offs

- [Подписи стали заметнее — риск «визуального шума»] → значения выбраны на нижней границе AA (4.74/5.04), не ярче; в задаче — ручная проверка обеих тем.
- [«Другая пара» частично отменяет прошлое «одна карточка»] → граница явно зафиксирована в дельте (карусель и URL-состояние остаются запрещены), кнопка появляется только при ≥2 вариантах.
- [`confirm()` не срабатывает без JS] → принято для локальной консоли; серверные проверки сохраняются, в read-only всё отключено.
- [Тестовые маркеры разойдутся с текстами] → в задачах явно: `test_perf.py:292` («осталось»), `test_data_cache.py:512` («осталось 105»), `test_pairing.py:197` (h2h) обновляются вместе с правками.
- [Расчёт рематчей добавляет проход по истории] → один проход по уже загруженному `index.json`, кэш по дайджесту; бюджеты `test_perf` на 1000 моделях не затрагиваются (история — 602 записи).
- [Длинная строка сводки на узких экранах] → блок `.stats` уже переносится по строкам, числа компактные.
