# Proposal

## Why

Чтение журнала вердиктов линейно растёт с объёмом данных: на текущих 535 вердиктах клик по фильтру занимает ~0.4 с, а на целевом масштабе (до 1000 моделей, 30–50 тысяч вердиктов) текущая архитектура «один файл на вердикт + полный пересчёт на каждый запрос» даёт >10 с на клик и ~9–10 с на запись вердикта. Реестр растёт на несколько моделей в неделю, поэтому структурные изменения дешевле заложить сейчас, чем мигрировать с десятками тысяч вердиктов.

## What Changes

- **BREAKING** Раскладка журнала: вердикты перестают храниться как отдельные файлы `data/matchups/T-NNN/NNN.json`; журнал становится единым append-only JSONL-файлом `data/matchups/journal.jsonl` (одна строка — одно событие: вердикт или аннулирование). `seq` — сквозной глобальный номер; `data/matchups/state.json` более не ведётся.
- Одноразовая миграция существующих вердиктов в `journal.jsonl` с верификацией (полное совпадение реплея ELO и `--check`) до удаления старых файлов.
- Дайджест журнала сохраняет семантику «sha256 содержимого журнала» (теперь одного файла) — критерий устаревания `data/index.json` не меняется.
- Server-кэш производных данных между запросами: журнал, пары, рекомендации, покрытие, тренды, `index.json`, реестр, справочники и скомпилированные шаблоны пересчитываются только при изменении входных данных (дайджест журнала + метаданные управляющих файлов), а не на каждый клик.
- Алгоритмы, ограниченные на 1000 активных моделей: обход только размеченных флагов, streaming top-K без построения записей для всех пар, тренды одним проходом, без двойного парса `index.json`, шаблоны компилируются один раз.
- Запись вердикта: строка журнала + пересчёт `index.json` из кэша — ~0.2–0.5 с при 10k вердиктов вместо ~9–10 с.
- Тесты: perf-guard на синтетике 1000 моделей / 10k вердиктов; адаптация существующих тестов к новому формату журнала.
- Осознанно НЕ меняются: Flask и UI-поведение консоли, контракт `data/index.json`, формула ELO, семантика pairing. Витрина для публикации при >10k вердиктов — отдельный будущий вопрос (порог зафиксирован в design).

## Capabilities

### New Capabilities

Нет — изменение не вводит новых capability, только меняет контракты существующих.

### Modified Capabilities

- `data-storage`: формат журнала (единственный `journal.jsonl`), миграция, целостность (файловый lock, оборванная последняя строка), масштаб хранилища и бюджеты отзывчивости чтения на целевом масштабе.
- `matchup-management`: запись вердикта и аннулирование как события журнала; нумерация через глобальный `seq`.
- `benchmark-workflow`: сценарии записи вердикта ссылаются на строку журнала вместо отдельного файла.
- `task-management`: множество известных тасок определяется по содержимому журнала, а не по директориям `data/matchups/T-NNN/`.
- `run-progress`: DONE-ячейка определяется наличием неаннулированного события журнала по паре и таску.
- `leaderboard-ui`: сценарии формы вердикта и страниц консоли, ссылающиеся на файл вердикта, переводятся на события журнала; добавляется бюджет отзывчивости консоли на целевом масштабе.
- `pairing-algorithm`: статистика личных встреч считается поверх событий журнала, а не «всех директорий `data/matchups/*/`».
- `elo-engine`: порядок реплея — строго по возрастанию `seq` событий журнала.

## Impact

- Код: `tools/elo.py` (load/replay/digest/record/void/state), `tools/server.py` (кэш, рекомендации, покрытие, leaderboard, шаблоны), `tools/render_helpers.py` (тренды), `tools/record_verdict.py`, новые скрипты миграции, тесты `tools/test_elo.py` / `tools/test_pairing.py`.
- Данные: `data/matchups/T-001/*.json` (535 файлов) → `data/matchups/journal.jsonl`; `data/matchups/state.json` удаляется; `data/index.json` пересчитывается.
- Документация и скиллы: `README.md`, `docs/architecture.md`, `.opencode/skills/benchmark-batch-judge/SKILL.md`, комментарии-докстринги в `tools/`.
- Совместимость: `data/index.json` сохраняет контракт; внешние наблюдатели раскладки журнала (`git diff` сценарии в спеках) обновляются в этом же change.
