## Context

См. `proposal.md` (Why). Текущее состояние: `tools/elo.py:collect_tasks_info()` сканирует `data/answers/<task-id>/*.md` в `index.tasks[].answers`, но `is_index_stale()` этот каталог не учитывает (индекс врёт: `T-002.answers=["modelA"]` при пустой папке). `tools/server.py:has_answer()` + плашка «нужны ответы» завязаны на этот список и при внешнем хранении текстов горят всегда. Front matter слотов требует `model: modelA/B`, судья обязан его проверять (`benchmark-judge/SKILL.md`, `docs/judge-prompt.md`), что путает при опечатке и рвёт анонимность при утечке id.

## Goals / Non-Goals

**Goals:**

- Слот = имя файла; судья не смотрит внутрь шапки.
- Удалить ложный авто-учёт ответов из индекса и UI.
- Ручная матрица модель x таск в настройках с дефолтом false.

**Non-Goals:**

- Не меняем ELO-математику, pairing-algorithm, формат вердиктов.
- Не переносим тексты ответов обратно в проект.
- Не делаем API/экспорт матрицы (только серверный рендер + POST формы).

## Decisions

### 1. Поле `model` удалить, а не игнорировать

Почему удаление, а не «оставить как игнорируемое»: дублирующий источник правды провоцирует рассинхрон (файл `modelA.md` с `model: modelB` внутри) и даёт модели канал деанонимизации. Удаление ломает формат один раз, дальше шапка минимальна (`task`, `date`). Альтернатива «оставить и игнорировать» мягче для старых файлов снаружи, но сохраняет мусор; выбрано удаление с явной оговоркой — старые файлы судятся по имени, шапка игнорируется.

### 2. Новый файл `data/answer_flags.yaml`, а не расширение `settings.yaml`

`settings.yaml` — настройки (статусы тасок, current), читается глазами; матрица `модели x таски` раздует его до сотен строк. Отдельный файл даёт разделение ответственности, простую чистку мусора (неизвестные id дропаются при сохранении) и точечный git diff. Формат — разреженный (`answer_flags: {task: {model: true}}`, отсутствие = false), чтобы дифф показывал только true. Альтернатива «расширить settings» отвергнута из-за шума. Загрузка — по образцу `load_settings` (простой парсер без зависимостей).

### 3. Считать матрицу живьём, в `index.json` не класть

Матрица — маленький YAML, скан на каждый запрос — миллисекунды; класть её в кэш значит чинить инвалидацию (сейчас её нет и для `answers/`). Живой расчёт исключает класс «индекс врёт». Альтернатива «положить в индекс + answers_digest» отложена до появления API/экспорта.

### 4. UI: сводка в `/settings` + матрица там же или `/coverage`

В `/settings` — сводка «ответы: закрыто X из Y» со ссылкой; сама матрица — секция настроек при малом масштабе, отдельный роут при росте (фильтр «только долги», поиск, bulk по строке/столбцу). Сохранение — одна кнопка POST на всю матрицу (проще конкурентности, чем автосейв по клику). Сортировка: должники сверху, таски по id. Архивные/неактивные скрыты по умолчанию с опцией показать (как на `/history`).

### 5. Чистка: удалить `has_answer`, `index.tasks[].answers`, `ANSWERS_DIR` из сводки

`collect_tasks_info` перестаёт сканировать `answers/`; поле `answers` из индекса удаляется (**BREAKING** для читателей индекса — их в репо нет, кроме сервера). `get_recommendations` (pairing-algorithm) не меняется — меняются только дисплейные флаги в `leaderboard()`. Альтернатива «оставить поле пустым» сохраняет враньё в схеме; выбрано удаление.

## Risks / Trade-offs

- [Риск] Старые файлы снаружи с полем `model` → судья по привычке смотрит внутрь → Митигация: явная строка в skill и judge-prompt «слот = имя/порядок, шапку игнорируй» + сценарий в спеке.
- [Риск] Ручные флаги расходятся с реальностью (отметил, а текста нет) → Митигация: это осознанный trade-off ручного учёта; флаги — утверждение координатора, верификации нет.
- [Риск] Матрица разъедется при 30+ моделях → Митигация: фильтр «только долги», липкая первая колонка, bulk-действия; пагинация не планируется до 10 тасков.
- [Риск] Потеря несохранённых чекбоксов → Митигация: одна кнопка + `beforeunload`-предупреждение (опционально), без автосейва.
- [Trade-off] Удаление `index.tasks[].answers` ломает внешних читателей индекса → в репо их нет; миграция — пересчёт `python tools/elo.py`.

## Migration Plan

1. Пересчитать индекс (`python tools/elo.py`) — поле `answers` исчезнет.
2. Создать пустой `data/answer_flags.yaml` (`answer_flags: {}`) — вся матрица false = все в долгах; координатор размечает по факту.
3. Обновить `data/answers/_TEMPLATE.md` (убрать `model`), skills run-a/b/judge, `docs/judge-prompt.md`.
4. Откат: git revert ченджа; старый формат с `model` внутри продолжает судиться (судья нового формата шапку игнорирует, старого — проверял; откат возвращает проверку).
