## Why

Тексты ответов хранятся вне проекта (анонимность судьи, защита от подсматривания), а в проекте нет учёта «у какой модели на какой таск ответ уже есть». Авто-скан `data/answers/` врёт (индекс показывает `modelA` при пустой папке), поле `model: modelA` внутри файла дублирует имя файла и путает судью.

## What Changes

- Слот ответа определяется только именем файла (`modelA.md` / `modelB.md`); поле `model` из front matter участников убирается (**BREAKING** для формата ответов).
- Судья проверяет только наличие двух файлов, непустоту и `task`/дату; содержимое шапки `model` игнорирует и не требует.
- Авто-учёт ответов удаляется: `index.tasks[].answers`, `has_answer`, плашка «нужны ответы» в рекомендациях больше не сканируют `data/answers/`.
- Вводится ручной учёт наличия ответов (матрица модель x таск) — координатор отмечает галочки в настройках; тексты по-прежнему вне проекта.
- `data/answers/` в проекте остаётся только транзитной зоной «два файла для текущего судейства».

## Capabilities

### New Capabilities

- `answer-coverage`: ручной учёт наличия ответов (матрица модель x таск, дефолты, фильтры, bulk-действия, хранение).

### Modified Capabilities

- `answer-management`: формат ответа без поля `model`, слот = имя файла, судья игнорирует шапку.
- `leaderboard-ui`: убрать авто-подсказки про ответы, добавить UI ручного учёта в настройках.
- `data-storage`: `answers/` — транзитные слоты, новый source of truth `data/answer_flags.yaml`, убрать `answers` из индекса.
- `benchmark-workflow`: обновить шаги прогона и судейства под новый формат и ручной учёт.

## Impact

- Затронуты: `tools/elo.py` (`collect_tasks_info`, константа ответов), `tools/server.py` (`has_answer`, рекомендации, `/settings`, новый роут), `data/answers/_TEMPLATE.md`, skills `benchmark-run-a`, `benchmark-run-b`, `benchmark-judge`, `docs/judge-prompt.md`, спеки.
- Обратная несовместимость формата ответов участников (поле `model` удаляется); старые файлы вне проекта продолжают судиться — судья их шапку игнорирует.
