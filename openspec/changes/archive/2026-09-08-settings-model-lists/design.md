## Context

См. proposal.md — Why. Карточка «Модели» на `/settings` — таблица
`tasks-table` из трёх строк (`tools/server.py`, `SETTINGS_TEMPLATE`).
Данные отдаёт роут `settings_page`, сейчас только счётчики.
ELO и статус модели есть в `ensure_index()` (`id/name/status/elo/games`),
`load_models_yaml()` отдаёт только `id/name/provider/status` без ELO.

## Goals / Non-Goals

**Goals:**

- Раскрываемые списки моделей в карточке «Модели» без добавления JS.
- Минимальная правка: один шаблон + один роут в `tools/server.py`.

**Non-Goals:**

- Изменение карточки «Таски», фильтров лидерборда, `/add`, `/model/<id>`.
- Изменение данных (`models.yaml`, `index.json`) — только чтение.

## Decisions

### 1. Нативный `<details>/<summary>` вместо JS-аккордеона

В проекте уже есть прецедент — блок «Дополнительно: проект и baseline»
в `EDIT_TASK_TEMPLATE`. `<details>` даёт сворачивание, состояние
«свёрнуто по умолчанию» и доступность с клавиатуры бесплатно.
Альтернатива (JS-аккордеон) добавила бы скрипт ради поведения,
которое уже покрывает HTML.

### 2. Вёрстка: таблица уходит, вместо неё блоки-«строки»

`<details>` невалиден внутри `<tr>`/`<tbody>` и не может порождать
строки таблицы при раскрытии. Поэтому блок статистики переверстывается:
список из трёх визуальных строк — простая строка «Всего в реестре» и два
`<details>` («Активных», «Неактивных (архив)»), стилизованных под
прежние строки таблицы (`summary` — вся строка кликабельна).
Внутри `<details>` — список `<a href="/model/<id>">` с именем и ELO.

Альтернатива — оставить `<table>` и раскрывать дополнительные `<tr>`
скриптом; отвергнута в пользу решения без JS.

### 3. Источник данных: `ensure_index()`, а не `load_models_yaml()`

Нужны `id`, `name`, `status`, `elo`. Всё это есть в моделях индекса
(`generate_index` синхронизирует `status` из `models.yaml`, а
`is_index_stale` гарантирует актуальность). `load_models_yaml()`
пришлось бы джойнить с индексом ради ELO. `settings_page` переключается
на `ensure_index()` и передаёт `models_active_list` /
`models_archived_list` — отсортированные по `elo` desc.

Альтернатива — оставить `load_models_yaml()` + джойн с индексом;
отвергнута как лишний код без выигрыша (индекс и так читается на
каждой странице).

## Risks / Trade-offs

- Переверстка таблицы может чуть изменить внешний вид карточки →
  переиспользовать существующие CSS-классы (`tasks-table`, `status-pill`)
  и проверить в браузере.
- `ensure_index()` при устаревшем индексе триггерит пересчёт — это уже
  поведение остальных страниц, цена та же.
- Стрелку/индикатор раскрытия у `<summary>` стилизовать минимально —
  дефолтного маркера браузера достаточно.
