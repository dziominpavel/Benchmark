## Context

См. `proposal.md` — мотивация и скоуп. Сейчас история ELO рендерится внутри
`<details>` на главной серверной странице (`/`) и в статичном
`leaderboard.html`. Добавление фильтра по модели внутри свёрнутого блока на
главной перегружало бы основную колонку, поэтому история выносится на
собственный роут `/history`. Параллельно убирается неиспользуемый
`tools/generate_html.py` и `leaderboard.html`.

## Goals / Non-Goals

**Goals:**
- Добавить в `tools/server.py` роут `/history` с фильтром по модели и
  чекбоксом включения неактивных (archived) моделей в выпадайку.
- Убрать блок истории с главной страницы сервера; добавить ссылку в шапку.
- Удалить `tools/generate_html.py` и вычистить все упоминания
  `leaderboard.html` из README, docs, `.gitignore` и OpenSpec-спек.
- Сохранить существующий способ пагинации по 20 записей и формат строки
  истории.

**Non-Goals:**
- Изменять логику начисления ELO, формат `index.json`, формат вердиктов или
  реестр `models.yaml`.
- Реализовывать статичную `history.html` с клиентским фильтром.
- Менять внешний вид таблицы рейтинга, блок рекомендаций и форму вердикта.
- Персистить выбор фильтра между сессиями (localStorage и т.п.).

## Decisions

### 1. История — это отдельный серверный роут, а не клиентский фильтр внутри главной

**Выбрано**: новый роут `/history` со своим Jinja-шаблоном, серверная фильтрация
и пагинация.

**Рационал**: `tools/server.py` уже использует Jinja-шаблоны
(`render_template_string`) и серверную пагинацию. Вынести историю на отдельный
экран — естественное разделение: главная остаётся рабочим инструментом
(рейтинг + рекомендации + вердикт), `/history` — журналом.

**Альтернативы**: client-side фильтр внутри `<details>` на главной — отклонена,
так как перегружает основную колонку и не соответствует запросу
«перенести на отдельную страницу».

### 2. Фильтр по модели — один dropdown, фильтрация по A или B

**Выбрано**: выпадайка с моделями, «Все» по умолчанию. При выборе модели M
остаются записи, где `model_a_id == M` или `model_b_id == M`.

**Рационал**: соответствует естественному запросу «посмотреть историю модели».

### 3. Чекбокс «Включать неактивные модели» влияет только на выпадайку

**Выбрано**: чекбокс добавляет archived-модели в опции dropdown; вид истории
при «Все» остаётся без изменений.

**Рационал**: пользователь явно просил такое поведение («включать в выпадайку
для фильтра неактивные модели»). Это предсказуемо: «Все» — это всё, а чекбокс
— инструмент поиска конкретной archived-модели.

### 4. URL сохраняет `model` и `include_inactive`

**Выбрано**: GET-параметры `model` и `include_inactive` передаются в ссылках
пагинации и при отправке формы фильтра.

**Рационал**: пользователь может поделиться ссылкой или вернуться назад
без потери фильтра.

### 5. Удаление `tools/generate_html.py` вместо адаптации

**Выбрано**: полностью удалить скрипт, не генерировать `history.html`.

**Рационал**: статичный файл не позволяет записывать вердикты; поддерживать
его параллельно серверу — двойная работа. Дублирование UI (отдельная
`history.html` с JS-фильтром) — лишний мусор. Удаление упрощает репозиторий.

**Альтернативы**: генерация отдельной `history.html` с клиентским JS —
отклонена из-за избыточности.

### 6. Модели в выпадайке берутся из `index.json` и `models.yaml`

**Выбрано**: для dropdown используется список моделей, отсортированный по
имени; статус берётся из `index.json`/`models.yaml`.

**Рационал**: уже есть `is_model_active()` и загрузка `models.yaml`; не нужно
новых источников данных.

## Risks / Trade-offs

- **[Risk] Пользователь открыл старый `leaderboard.html` в закладках.**
  → **Mitigation**: `leaderboard.html` в `.gitignore` удаляется; если файл
  остался в рабочей директории, его можно удалить вручную. В README/Docs
  будет указано, что статичный экспорт больше не поддерживается.

- **[Risk] Ссылки на `/history` из шапки могут сломать старый `leaderboard.html`,
  если он случайно открыт.**
  → **Mitigation**: `leaderboard.html` удаляется вместе со скриптом; ссылок
  на него не остаётся.

- **[Risk] Удаление `generate_html.py` ломает скрипт, если кто-то использовал
  его в CI/автоматизации.**
  → **Mitigation**: change помечен как **BREAKING**; `leaderboard.html` всегда
  был read-only, поэтому сгенерированный экспорт заменяется запуском сервера.

- **[Trade-off] Фильтр по модели не позволяет выбрать пару моделей.**
  Это осознанное упрощение: для поиска по паре можно выбрать одну и визуально
  искать вторую на странице, либо вернуться к «Все».

- **[Trade-off] Фильтр по archived-модели требует предварительно включить
  чекбокс.** Это соответствует запросу и не даёт случайно отфильтровать
  по неактивной модели.

## Migration Plan

1. Реализовать `/history` в `tools/server.py` и убрать историю с главной.
2. Удалить `tools/generate_html.py`.
3. Вычистить `README.md`, `docs/workflow-guide.md`, `.gitignore`.
4. Обновить `openspec/specs/leaderboard-ui/spec.md` и
   `openspec/specs/data-storage/spec.md` при архивации change.
5. (Опц.) удалить старый `leaderboard.html`, если он есть в рабочей копии.
