# Design

## Context

Консоль после волн 1–3: страница `/stats` содержит одну карточку
«Распределение Elo» (серверный SVG `build_elo_distribution_svg`, клиентский
фильтр «Показывать»/агенты/компании, в зеркале — пересборка `mirror.js`),
страница `/model/<id>` — шапка, график (`build_elo_svg`), H2H-таблица и
«История матчей», экрана задачи нет. Данные для волны уже есть:
`index.json` (модели с `elo/games/wins/losses/draws/agent/provider/status`,
`elo_history` с `seq/date/recorded_at/model_a_id/model_b_id/winner/elo_a/elo_b`,
`voided_history` с `task`), реестр `models.yaml` (версия, релиз, добавление,
заметки), `data/answer_flags.yaml` (флаги ответов), `data/tasks/`.

Ограничения, задающие решения:

- серверный рендер без JS-библиотек; клиентский JS — только `mirror.js`
  (слепок) и `combobox.js`; новые live-контролы в зеркале не рендерятся;
- memo-слой `data_cache.cached` для агрегатов; новые тяжёлые проходы
  добавляются memo-ключами, а не пересчётом на каждый запрос;
- слепок `export_web.py`: карта URL → файлы, перезапись адресов по
  `href|src|action` и проверка `check_output` — SVG-ссылки `<a href>`
  попадают в перезапись и проверку наравне с HTML;
- контракты данных (журнал, формат `index.json`, ELO) не меняются.

## Goals / Non-Goals

**Goals:**

- блоки аналитики A1–A8 как отдельные карточки `/stats`, каждый — отдельная
  итерация с тестом; страница остаётся быстрой на memo-слое;
- профиль модели: место/тренд, последний матч, покрытие по таскам,
  метаданные, ссылки из «Истории матчей», поиск и сортировка «Личных встреч»;
- страница задачи `/task/<id>`: шапка, прогресс, список вердиктов тем же
  рендером, что история, перекрёстные ссылки;
- слепок: страницы задач экспортируются, новые блоки и контролы деградируют
  по правилам «только просмотр»;
- тесты: чистые хелперы — новый `tools/test_analytics.py`; роуты —
  `test_data_cache.py`; слепок — `test_export.py`.

**Non-Goals:**

- оверлей «сравнить две модели» (icebox), кликабельность старых баров
  гистограммы, клиентский JS для аналитики сверх `mirror.js`;
- изменения журнала, `index.json`, ELO-механики, существующих роутов;
- редактирование задачи со страницы задачи (остаётся `/edit_task/<id>`);
- пагинация/фильтры списка вердиктов задачи сверх `page` и виджета.

## Decisions

### 1. Маршруты и контекст страницы задачи

- `GET /task/<task_id>` — новый роут `task_page(task_id)`. Известная задача
  = существует директория `data/tasks/<task_id>-*` (`find_task_dir`); иначе
  `abort(404)`.
- `GET /task/<task_id>/md` — отдача `task.md` как `text/plain` (utf-8);
  в режиме «только просмотр» ссылка на него не рендерится (роут экспортом
  не вызывается).
- Контекст: `task` (`get_task_info`), `is_active` (`memo_active_tasks`),
  `is_current` (`current_task` из настроек), `progress`, `feed` (страница
  вердиктов), пагинация.

Прогресс задачи:

- вердиктов — применённые записи `elo_history`, у которых таск из `matchup`
  (префикс до `/`) равен id;
- `F из T` — пары моделей, у обеих true в `answer_flags.yaml` на таск (T),
  из них пары с неаннулированным вердиктом по таску (F) — источник
  `get_pair_task_verdicts()` (memo `pair_scan`);
- моделей — различные участники вердиктов таска;
- аннулированных — записи `voided_history` с `task` = id.

### 2. Строка вердикта — общий макрос

Разметка строки (server.py, HISTORY_TEMPLATE, блок строк 1747–1780)
извлекается в `tools/templates/_verdict_row.html`, макрос
`verdict_row(item, show_task=True, extra_class="", void_next=None)`:

- `extra_class` — классы подсветки истории (`filter-hit`/`filter-miss`);
- `show_task=False` — на странице задачи бейдж не рендерится;
- бейдж таска ведёт на `url_for('task_page', task_id=item.task)` в обоих
  режимах (в зеркале страницы задач экспортируются);
- чип `matchup_id` в live — постоянная ссылка, в read-only — span
  (как сейчас); форма «Аннулировать» — только live.

`HISTORY_TEMPLATE` и новый `TASK_TEMPLATE` импортируют макрос
(`{% from "_verdict_row.html" import verdict_row with context %}`).
Пагинация — существующий макрос `pagination` из `_pagination.html`; на
странице задачи поле «Страница» шлёт GET на `/task/<id>` с `page`.

### 3. A1 «Интервалы рейтинга»

- Чистый хелпер `interval_groups(rows)` (render_helpers): половина интервала
  — `confidence_half_width(games)`; строки сортируются по `(-elo, id)`;
  соседние строки перекрываются, если нижняя граница верхней ≤ верхней
  границе нижней; группы — максимальные цепочки перекрывающихся соседей
  (транзитивно по соседям); одиночка без перекрытий — различима.
- SVG `build_rating_intervals_svg(rows)`: шкала X покрывает все интервалы;
  на строку — место, имя (ссылка на профиль), ELO, точка и полоса
  интервала; модель без игр — точка без полосы; группы «место не
  определено» — фоновая плашка/левая метка с подписью; подпись-пояснение
  под заголовком.
- Пул — активные модели (не зависит от фильтров страницы; осознанно см.
  «Риски»). Ссылки на профили работают и в слепке (страницы моделей есть).

### 4. A2 «Динамика ELO»

- Параметры: `lines` (CSV id; одновременно не более 10 — лишние
  отбрасываются, остаются 10 наибольших по текущему ELO), `period` =
  30/90/all (иначе 90).
- Выбор моделей — из реестра (валидные id; неизвестные игнорируются);
  по умолчанию — топ-5 активных по ELO.
- SVG-хелпер `build_elo_multiline_svg(series, x_count, dates, colors)`:
  общая шкала Y включает 1200; X — позиция матча в общем упорядоченном
  списке матчей выбранных моделей периода; палитра 10 цветов; легенда —
  HTML под графиком (цвет, имя, текущий ELO, «нет матчей в периоде»).
- Контролы: форма чекбоксов активных моделей (submit), пресеты-ссылки
  «Топ-5»/«Топ-10», сегменты периода; всё под `{% if not read_only() %}`,
  в слепке видно состояние по умолчанию.

### 5. A3 «Активность по дням»

- Хелпер `activity_by_day(elo_history)`: день — `date[:10]` (fallback
  `recorded_at[:10]`), пустые дни между первым и последним заполняются
  нулями.
- SVG `build_activity_bars_svg(days)`: столбики с `<title>DD.MM.YYYY: N</title>`,
  подписи первой/последней даты; сводка «дней · вердиктов · максимум» в
  заголовке карточки. Без URL-состояния и контролов.

### 6. A4 «Матрица пар»

- Чистый хелпер `pair_matrix(ids, pair_stats)` → ячейки (число игр,
  рематч); порядок — активный пул по ELO по убыванию.
- SVG `build_pair_matrix_svg(..., links=True)`: сетка, диагональ пуста,
  заливка по числу игр, метка рематча при >1, `<title>`; в live ячейки —
  `<a href="/history?pair=A:B">`, в read-only `links=False` (без ссылок).
- Обёртка `overflow-x: auto`; лимитов пула нет (текущий пул 35), риск при
  росте — в «Рисках».

### 7. A5 «Агенты и компании»

- Хелпер `group_summary(models, key)` → строки: моделей, медиана, среднее,
  игры, винрейт (победы/игры); порядок по медиане вниз, при равенстве — по
  названию. HTML-таблица; пустые — «без агента»/«без компании»; без ссылок.

### 8. A6 «Взлёты и падения»

- Хелпер `delta_leaders(elo_history, models, days)`: топ-5 роста и топ-5
  падения по сумме ΔELO; окна 7 и 30. Опорная дата — последняя дата
  истории (детерминизм для слепка и тестов).
- `stale_models` — активные без игр в последних `STALE_GLOBAL_GAP` (30)
  глобальных вердиктах (константа уже есть в render_helpers).
- Оба окна показываются сразу, URL-состояния нет.

### 9. A7 «Сила оппозиции»

- Хелпер `opposition_strength(...)`: средний ELO соперников (ELO соперника
  «до» матча), апсеты (победы над моделями текущего топ-10), игры; порядок —
  как рейтинг. HTML-таблица, имя — ссылка на профиль.

### 10. A8 «Исходы»

- Хелпер `winner_shares(elo_history)`: числа и проценты по «a/b/draw»;
  разбивка по активным таскам при двух и более (таск из `matchup`).
  Проценты округляются до целого.

### 11. Профиль модели

- `get_model_detail` расширяется: в элементы истории — `seq` и `matchup`
  (постоянная ссылка), `last_match`, `task_games` (memo-хелпер
  `task_model_games`: один проход по `elo_history`, `{task: {model: games}}`),
  `meta` (сырая запись реестра: version/released/added/status/notes).
- Место/тренд: пул активных + `compute_rank_trends` под новым memo-ключом
  `trends:profile` (не переиспользуем ключи главной — там пул зависит от
  фильтров); место — позиция в отсортированном пуле (как в таблице),
  стрелка — из трендов; архивные — «вне активного рейтинга».
- Поиск/сортировка H2H: `h2h_q` (подстрока по имени/id, регистронезависимо),
  `h2h_sort` (games|w|l|d|winrate), `h2h_dir` (desc по умолчанию); заголовки —
  ссылки с `aria-sort`; фильтрация/сортировка — в `model_page` после
  `get_model_detail`; нечисловые значения («—») — в конец.
- Даты строк «Истории матчей» — ссылки `/history?v=<seq>#v-<seq>`; кнопка
  «Показать в истории» — `url_for('history_page', model=...)`. В слепке
  поиск/сортировка не рендерятся (ссылки с query на статике не работают).
- Метаданные в `MODEL_TEMPLATE`: карточка со всеми непустыми полями; при
  отсутствии всех полей карточка не показывается.

### 12. Слепок (export_web)

- `build_url_map(task_ids, model_ids, queue_pages)`: `/task/<id>` →
  `task/<id>/index.html`; `task_ids` — ключи `tasks` из `index.json`; в цикле
  записи — страница на каждую задачу.
- Деградации read-only: кнопка «Записать вердикт» — span `aria-disabled`;
  ссылка `task.md` не рендерится; контролы A2 и поиск/сортировка H2H
  отсутствуют; ячейки A4 без ссылок; бейдж таска — ссылка (страницы задач
  экспортируются); «Показать в истории» работает (mirror.js обрабатывает
  `model` в URL истории).
- SVG-ссылки `<a href>` попадают в перезапись (`_ATTR_RE`) и `check_output`
  (HTMLParser обходит атрибуты) — подтверждено кодом; тест слепка дополнится
  кейсом со ссылкой внутри SVG A1.

### 13. CSS

`console.css`: полосы и плашки групп A1, легенда мультилинии, столбики A3,
матрица A4 (+ горизонтальный скролл), сводки A5/A7, списки A6, доли A8,
шапка и прогресс задачи, карточки профиля, контролы H2H.

### 14. Тесты

- `tools/test_analytics.py` (новый): `interval_groups` (перекрытие, цепочка,
  разрыв, модель без игр), `activity_by_day`, `pair_matrix`,
  `group_summary`, `delta_leaders`, `opposition_strength`, `winner_shares`,
  разбор `lines`/`period`.
- `tools/test_data_cache.py`: `/stats` с блоками A1–A8 (200), `/task/T-001`
  (200: прогресс, строки, аннулированный), неизвестная задача → 404,
  `/task/<id>/md` (text/plain), read-only-гейты (нет формы записи и ссылки
  task.md), профиль (место, метаданные, ссылки), H2H-поиск/сортировка.
- `tools/test_export.py`: страницы задач в выводе; целостность ссылок
  покрывает их автоматически; контролы A2 отсутствуют; ячейки A4 без
  ссылок; бейдж ведёт на страницу задачи; SVG-ссылка A1 разрешается.

### 15. Мемо-слой

Новые ключи: `task_model_games`, агрегаты A5/A7, `delta_leaders`, `stale`;
тренды профиля — `trends:profile`. Тяжёлые блоки читают уже разобранные
события журнала (`journal_events`, `pair_scan`), не перечитывая файлы.

## Risks / Trade-offs

- Волна крупная (17 новых требований): tasks дробятся по блокам; каждый блок
  приёмлем отдельно, но спека фиксирует итог волны.
- A1 намеренно не зависит от фильтров `/stats`: места считаются по активному
  пулу, гистограмма остаётся фильтруемой; компромисс зафиксирован в спеке,
  подпись блока поясняет.
- Матрица A4 отрисовывается разреженно: фон и сетка — O(n) элементов,
  прямоугольники и подписи — только у ячеек со встречами; пул в сотни
  моделей не раздувает страницу (проверено на синтетике 1000 моделей),
  лимит топ-N не требуется.
- Ссылки `?v=` и `?pair=` в слепке не подсвечивают/не фильтруют клиентски —
  как в волне 3, вне скоупа.
- Проценты A8 округляются до целого — сумма может не равняться 100%.
- Длинные тексты требований — валидатор может предупреждать; детали вынесены
  в сценарии.
