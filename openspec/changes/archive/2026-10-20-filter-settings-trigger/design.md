# Design

## Context

См. `proposal.md` — Why. Текущее состояние (после архивного change `filter-display-settings`):

- Макрос `filter_panel()` (`tools/templates/_tag_filter.html:11-77`) рендерит `<form class="filter-card">`: `.filter-head` (заголовок и условная ссылка «Сбросить»), затем `<details class="filter-settings">` первым содержимым формы, затем `.filter-rows`.
- CSS (`tools/static/css/console.css:1506-1533`): `.filter-settings > summary` — `display: inline-flex`, цвет `--muted`, без рамки и фона; `inline-flex` подавляет нативный маркер, поэтому до клика триггер выглядит серой подписью. Тело `.filter-settings-body` — в потоке.
- Подпись свёрнутого триггера собирает `filter_panel_context()` (`tools/server.py:505-576`, поле `filter_settings_badge`); в статическом слепке `updateBadge()` (`tools/static/js/mirror.js:300-309`) перезаписывает `summary.textContent`.
- `shell.html` подключает `theme.js` всегда, `combobox.js` — в live-консоли, `mirror.js` — в слепке (все с `defer`). `export_web.py` копирует `tools/static` целиком (`:540`) и переписывает `src="/static/..."` в относительные пути (`:177-178`).
- Готовый паттерн шеврона: `.model-groups summary .mg-label::before` с `\25B8` / `\25BE` (`console.css:1356-1363`); токены `--elevated`, `--shadow-2`, `--r-sm` есть в обеих темах.

## Goals / Non-Goals

**Goals:**

- Триггер «Настройки фильтра» без клика читается как кнопка (рамка, фон, шеврон), расположен в шапке блока рядом со «Сбросить».
- Панель — поповер поверх содержимого: раскрытие не сдвигает контролы фильтра.
- Панель закрывается повторным нажатием, кликом вне и Escape; после Escape фокус возвращается на триггер. Поведение одинаково в live-консоли и в статическом слепке.
- Подписи сегментов «Режим отображения» и «Сортировка чипов»; подпись-бейдж и URL-параметры не меняются.
- Серверная логика, `filter_panel_context()`, `mirror.js` и правила фильтрации не затрагиваются.

**Non-Goals:**

- Не менять состав и порядок контролов фильтрации (вариант D — перенести «Сортировку чипов» к чипам — отклонён).
- Не делать панель всегда развёрнутой (вариант C) и не превращать шапку целиком в `<summary>` (вариант B2).
- Не менять значения `view`/`chips`, текст бейджа, семантику режимов «Скрывать лишние»/«Подсвечивать».
- Не подключать сторонние библиотеки; только нативный HTML/CSS/JS.
- Не трогать поведение «сохранить панель открытой после выбора сегмента» — отдельная тема, вне рамок.

## Decisions

### 1. Триггер в шапке, панель-поповер (вариант B1)

Рассмотренные варианты из макета: A — пилюля в теле карточки (тоже решает проблему, но остаётся в потоке и менее заметна); B2 — вся шапка становится `<summary>` (нативно, без JS, но «Сбросить» переезжает из шапки, а заголовок «Фильтр» становится кликабельным); C — всегда развёрнутая панель (отклонена ещё в `filter-display-settings`: «просили сворачиваемый»). B1 выбран как максимальная заметность входа без изменения состава блока: кнопка стоит там, где пользователь ищет действия, панель не сдвигает фильтры и не ломает спекой зафиксированное «контролы видны без разворачивания».

### 2. `<details>` + общий `filter-panel.js` — вместо Popover API и «совсем без JS»

`<details class="filter-settings">` остаётся: он даёт бесплатное раскрытие/сворачивание и уже используется `mirror.js` (селектор `details.filter-settings > summary`). Браузерный Popover API дал бы light dismiss без скрипта, но позиционирование панели у триггера требует CSS anchor positioning, поддержка которого в браузерах посетителей слепка не гарантирована, а без него поповер встаёт по центру вьюпорта — визуальный регресс. Вариант «совсем без JS» оставляет открытую панель поверх фильтров, пока пользователь не нажмёт триггер повторно, — клик по фильтрам под панелью не закрывает её.

Добавляется маленький общий скрипт `tools/static/js/filter-panel.js` (прогрессивное улучшение): клик вне `details` снимает `open`, Escape снимает `open` и возвращает фокус на `summary`. Он не управляет рендером и не дублирует `mirror.js`. Это уточнение non-goal прошлого change «не делаем клиентский JS-слой»: рендер остаётся серверным, скрипт отвечает только за закрытие панели и без него страница работает (закрытие доступно повторным кликом).

### 3. Шеврон — только `::after`, бейдж остаётся текстом

`mirror.js updateBadge()` перезаписывает `summary.textContent`, поэтому любой вложенный элемент (шеврон-`span`) был бы стёрт. Шеврон делается псевдоэлементом `summary::after` по существующему паттерну (`\25B8` свёрнуто / `\25BE` раскрыто), а подпись «Настройки фильтра — подсветка · чипы по ELO» остаётся текстовым узлом внутри `summary`. Селектор `updateBadge` и его результат не меняются.

### 4. Разметка и CSS

`_tag_filter.html`: `<details>` переезжает в `.filter-head` внутрь обёртки `.filter-head-actions` (кнопка настроек + условная «Сбросить»); при скрытой «Сбросить» обёртка остаётся последним элементом шапки, и кнопка сохраняет правое выравнивание за счёт `justify-content: space-between` у `.filter-head`.

`console.css`:

- `.filter-head-actions { display: inline-flex; align-items: center; gap: var(--sp-3); }`
- `.filter-settings { position: relative; margin-bottom: 0; }` — прежний `margin-bottom: var(--sp-3)` больше не нужен, элемент ушёл из потока тела блока.
- `summary` — кнопка: `padding`, рамка `--border-strong`, фон `--surface`, `border-radius: var(--r-sm)`, `list-style: none` + `::-webkit-details-marker { display: none; }`, ховер/открытое состояние — `--elevated` и акцентная рамка через `color-mix`.
- `summary::after` — шеврон `\25B8`/`\25BE`, как у `.model-groups`.
- `.filter-settings[open] > .filter-settings-body` — поповер: `position: absolute; top: calc(100% + 8px); right: 0; z-index: 30; width: min(460px, calc(100vw - 64px)); padding: var(--sp-3); border: 1px solid var(--border-strong); border-radius: var(--r-sm); background: var(--elevated); box-shadow: var(--shadow-2); margin-top: 0;`
- `.filter-settings-body .filter-label { min-width: 128px; }` — длинные подписи выравнивают сегменты в колонку (замерено: «Режим отображения» ≈128px при 13px semibold).

Узкие экраны: `@media (max-width: 640px)` — панель растягивается по ширине карточки (`left: 0; right: 0; width: auto`) и `.filter-head` получает `flex-wrap: wrap`. Точный брейкпоинт уточняется при ручной проверке.

### 5. Подписи

В шаблоне: «Режим» → «Режим отображения», «Чипы» → «Сортировка чипов»; `aria-label` сегментов приводятся к тем же формулировкам. Параметры URL и значения не меняются. Пользователь видел эти подписи в макете B1 и выбрал его.

### 6. Подключение скрипта и слепок

`<script src="/static/js/filter-panel.js" defer></script>` добавляется в `shell.html` безусловно (рядом с `theme.js`), поэтому работает и в live-консоли, и в зеркале. Экспорт копирует `tools/static` целиком, а `_rewrite_links` переводит `/static/...` в относительный путь; отдельных правок `export_web.py` не требуется. Проверки `test_export.py` дополняются ожидаемым файлом и маркером в сборке.

### 7. Тесты и проверка

- `tools/test_data_cache.py`: триггер рендерится в шапке (`.filter-head-actions` содержит `filter-settings`), подписи «Режим отображения»/«Сортировка чипов», бейдж при `view=highlight&chips=elo` по-прежнему «Настройки фильтра — подсветка · чипы по ELO».
- `tools/test_export.py`: `static/js/filter-panel.js` есть в файлах сборки и подключён на страницах слепка относительной ссылкой; маркеры live-only (`combobox.js` и т. п.) не задеты.
- Ручная проверка в браузере: клик по триггеру/повторный клик, клик вне панели, Escape с возвратом фокуса, Tab-порядок, отсутствие сдвига чипов, тёмная и светлая темы, узкая ширина; та же проверка на странице слепка.
- `openspec validate --all` без ошибок.

## Risks / Trade-offs

- [Скрипт-хелпер противоречит non-goal прошлого change] → в design зафиксировано уточнение: рендер остаётся серверным, скрипт — прогрессивное улучшение (без него всё работает, кроме light dismiss); поведение общее для консоли и слепка.
- [Поповер перекрывает контролы фильтра] → light dismiss по клику вне, Escape, закрытие по повторному нажатию; после выбора сегмента форма отправляется и страница перерисовывается с закрытой панелью.
- [`mirror.js` стирает шеврон] → шеврон только в `::after`, в DOM-тексте `summary` его нет.
- [Узкий экран: кнопка и «Сбросить» не влезают, поповер выходит за карточку] → `flex-wrap` у шапки, `width: min(460px, calc(100vw - 64px))`, медиазапрос на всю ширину карточки; проверка на 360/480/768px.
- [Длинный бейдж делает кнопку широкой] → текст в `summary` переносится, `max-width: 100%`; проверка не-дефолтного состояния обоими сегментами.
- [Дублирование логики закрытия, если в будущем появится ещё один поповер] → хелпер общий и маленький; при втором использовании вынести в общий модуль.

## Migration Plan

Данные не мигрируются, серверный код и URL-контракты не меняются. Порядок: правки шаблона/CSS/JS → проверки → экспорт слепка штатным прогоном → пользовательский пункт в `CHANGELOG.md` (`[Unreleased]`). Откат — revert коммита: единственное состояние — значение `open` у `<details>` в браузере, данные не затрагиваются. Слепок пересобирается тем же экспортом; старые сборки продолжают работать без нового скрипта (кнопка и панель отрисуются, light dismiss не будет — деградация безопасная).
