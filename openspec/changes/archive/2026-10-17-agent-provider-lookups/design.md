# Design

## Context

См. `proposal.md` — Why. Состояние на момент планирования:

- Консоль — Flask-сервер `tools/server.py`: роуты и inline-шаблоны в одном файле,
  общий каркас — `tools/templates/shell.html`.
- Фильтр «Агент и компания» (change `model-agent-provider-filter`) живёт в макросе
  `tools/templates/_tag_filter.html`: свёрнутый `<details>` с кнопкой «Показать»,
  вызывается на пяти страницах; контекст готовит `tags_filter_context()`
  (`server.py` ~187), значения — `_tag_values()` из реестра (~139), прохождение —
  `model_passes_tags()` (~175).
- «Показывать» — отдельные контролы: главная (`INDEX_TEMPLATE` ~624), `/stats`
  (~978), `/settings` (`answer_filter` в секции «Наличие ответов» ~1356);
  на `/history` — выпадайка «Модель» и чекбокс «Включать неактивные»; на
  `/settings` в матрице — клиентский чекбокс «только долги» и JS-счётчик
  «показано X из Y».
- Стили — `.tag-filter*` в `tools/static/css/console.css` (~1215–1267).
- Поля `agent`/`provider` в `data/models.yaml` — свободный ввод через datalist;
  сериализация — `parse_existing`/`format_model` (`tools/register_model.py`),
  ими же пользуются сервер (`update_model`, ~401, пересобирает `index.json`)
  и CLI `register_model.py`.
- `data/index.json` — генерируемый кэш (version 2), его схема не меняется.

Ограничения: только stdlib + Flask, без JS-фреймворков; витрина `web/` вне
скоупа; семантика фильтра (ИЛИ/И, «без агента/компании», URL `agents`/`providers`)
и границы его действия (места/медали/d5, форма вердикта, очередь) не меняются.

## Goals / Non-Goals

**Goals:**

- Единый блок «Фильтр» на пяти страницах — видимый, консистентный, с мгновенным
  применением и кнопкой «Сбросить».
- Справочники агентов и компаний (`data/lookups.yaml`) с CRUD в «Настройках».
- Выбор агента и компании в формах модели только из справочника.
- Наполнение справочника из CLI без падения авто-прогонов.

**Non-Goals:**

- Изменение логики фильтра и его границ, формата `index.json`, расчёта ELO.
- Витрина `web/` (там нет agent/provider).
- Отдельный CLI для управления справочниками (кроме авто-добавления при
  регистрации) и миграции данных.

## Decisions

### D1. Разметка блока «Фильтр»

Макрос `tag_panel()` заменяется на `filter_panel()` (и `tag_hidden()` — на
аналог, отдающий скрытые поля всех фильтров страницы). Блок — форма GET с
заголовком «Фильтр», всегда развёрнутая (без `<details>`), чекбоксы и селекты
отправляют форму `onchange="this.form.submit()"`, кнопка «Показать» удаляется,
«Сбросить» — ссылка на URL страницы без фильтр-параметров (сейчас это
`tag_reset_url`). Страницы передают свой набор контролов через контекст.

Отклонённые альтернативы: оставить `<details open>` (лишний «свёрнутый» вид);
оставлять кнопку «Показать» (лишний шаг — жалоба пользователя).

### D2. Состав блока по страницам

| Страница    | Контролы блока                                    |
|-------------|---------------------------------------------------|
| главная `/` | «Показывать», «Агент», «Компания»                    |
| `/stats`    | «Показывать», «Агент», «Компания»                    |
| `/history`  | «Модель», «Включать неактивные», «Агент», «Компания» |
| `/add`      | «Агент», «Компания»                                  |
| `/settings` | «Показывать» (`answer_filter`), «Агент», «Компания», «Только долги» |

На `/settings` переключатель «Показывать» переносится из секции «Наличие ответов» в
блок: страница получает один фильтр-блок, как и остальные. Альтернатива —
оставить «Показывать» в секции — отклонена ради единообразия; решение обратимо
без смены URL-контракта.

### D3. «Только долги» — серверный фильтр

Чип «Только долги» переезжает из flags-bar в блок и становится URL-параметром
`only_debts=1`: сервер отбирает строки матрицы с долгом, клиентский JS-фильтр
и счётчик «показано X из Y» удаляются. При включённом параметре и отсутствии
долгов — пустое состояние «Долгов нет». Сохранение флагов не меняется: форма
несёт параметры страницы скрытыми полями и возвращает их в redirect.

Альтернатива — оставить мгновенный клиентский JS — отклонена: состояние не
переживало перезагрузку и «Сбросить», выбивалось из поведения блока.

### D4. Скрытые поля

`tag_hidden()` обобщается: формы, отправляемые отдельно (сохранение флагов,
пагинация истории, «Сбросить»), получают скрытые копии параметров `agents`,
`providers`, `model`/`include_inactive`, `answer_filter`, `only_debts` — как
сейчас это делается для agent/firm.

### D5. Файл справочника

`data/lookups.yaml` — два списка простых строк:

```yaml
agents:
  - Codex
  - Cursor
providers:
  - Anthropic
```

Парсер/сериализатор — stdlib по образцу `parse_existing`/`format_model`
(шапка-комментарий сохраняется), порядок файла = порядок вывода; новые значения
добавляются в конец списка. Сид — текущие значения реестра (уникальные непустые,
сортировка case-insensitive). Отклонённые альтернативы: PyYAML (в проекте нет
зависимостей), JSON (нет комментариев), хранение в `models.yaml` (смешение
сущностей).

### D6. Источники значений

- Селекты форм `/add` и `/edit` — справочник + «— не указано —»; на `/edit`
  текущее значение вне справочника показывается пунктом «(вне справочника)».
- Чипы фильтра — как сейчас: значения, встречающиеся в реестре, плюс
  «без агента»/«без компании». Альтернатива — брать значения из справочника —
  отклонена: значения без моделей дают заведомо пустую выдачу.
- Рядом с полями формы — ссылка «Справочники» на `/settings#lookups`
  (открывается в новой вкладке).

### D7. CRUD справочника

POST-роуты страницы `/settings` (redirect с `error`/`success`, как у остальных
действий страницы):

- `/lookups/add` — добавить значение (пустое/дубликат → ошибка);
- `/lookups/rename` — переименовать: валидация, каскад по `models.yaml`
  (все записи со старым значением), регенерация `index.json`;
- `/lookups/delete` — только если значение не использует ни одна модель;
- `/lookups/promote` — «внести в справочник» значение из реестра (записи
  реестра не меняются).

Валидация выполняется до записи: при ошибке не пишется ничего. Счётчик
использования — по всем моделям реестра, независимо от статуса.

### D8. CLI

`register_model.py`: непустое значение `--agent`/`--provider` вне справочника
добавляется в него (в конец) с сообщением в stdout; режим `--auto` не падает.
Это сохраняет совместимость skills `benchmark-run-a/b`.

### D9. Секция «Справочники»

Пятая секция `/settings` (`id="lookups"`, после «Очереди рекомендаций») и пятый
пункт якорной навигации. Таблицы «Агенты»/«Компании»: значение, число моделей,
действия. Переименование — inline-форма (input + кнопка); «Удалить» — кнопка
disabled с подписью «используется у N» для используемых значений; над таблицей —
форма добавления. Значения вне справочника — отдельные строки в конце таблицы
с пометкой и кнопкой «внести в справочник».

### D10. Формы модели

Серверная валидация: `/add_model` принимает пустое значение или значение из
справочника; `/edit_model` — пустое, из справочника или текущее значение модели
(не изменённое). Иначе — redirect с ошибкой, запись не меняется.

### D11. Стили

Единый набор классов блока: `.filter-card`, `.filter-head`/`.filter-title`/
`.filter-reset`, `.filter-rows`/`.filter-row` (строка «подпись + контролы»),
`.filter-label`, `.filter-chips`/`.chip` (мультивыбор), `.segmented` (статус).
Старые `.tag-filter*` удалены после переезда всех страниц; первичные
`.filter-group`/`.filter-options-cols`/`.check-label` заменены чипами (см. D13).

### D12. Проверки

- Расширение smoke-скрипта: блок на пяти страницах (заголовок, отсутствие
  `<details>`/«Показать», наличие «Сбросить»), работа фильтров с URL-параметрами
  как раньше, `only_debts`, CRUD справочника (файл, каскад, счётчики, запрет
  удаления, promote, «вне справочника»), CLI-авто-добавление, отклонение
  значения вне справочника в `/add_model`.
- Браузерный обход со скриншотами: пять страниц, секция «Справочники», формы
  `/add` и `/edit`.
- `openspec validate --all`; версия не бампится, запись в CHANGELOG
  `[Unreleased]`.

### D13. UI-ревью блока «Фильтр»

После первой версии (селект «Показывать» + чекбоксы в fieldset-группах) блок
переработан по ревью пользователя:

- «Показывать» — сегментированный переключатель взаимоисключающих сегментов
  («Активные»/«Все»/«Неактивные») вместо выпадающего списка: все контролы
  одного класса выглядят одинаково на страницах.
- «Агент»/«Компания» — чипы-переключатели (визуально скрытый чекбокс + pill-метка;
  выбранный — акцентная заливка, фокус — видимое кольцо): ушли fieldset-рамки,
  длинные списки переносятся строками, узкие карточки не ломаются.
- Чипы — чекбоксы с общим именем: форма отправляет повторяющиеся параметры
  (`agents=A&agents=B`); сервер собирает их `getlist`-хелпером `_tag_query_csv`,
  принимая оба транспорта — повторяющиеся параметры и CSV ссылок/скрытых полей
  (по мотивам функционального ревью: `.get()` терял вторую и далее отметки).
- Группы — строки «подпись + контролы»; «Сбросить» — тихая ссылка справа, видна
  только при применённых фильтрах (`reset_extra`: режим «Показывать» не по
  умолчанию, «Модель», `include_inactive`, `only_debts`, выбранные агент/компания).
- «Включать неактивные» на `/history` и «Только долги» на `/settings` — чипы той
  же семьи, что и мультивыбор; URL-параметры не менялись.
- Терминология: пользовательские тексты говорят «компания» вместо «фирмы»
  (код и параметры — `provider`/`providers` без изменений).

## Risks / Trade-offs

- [«Только долги» теперь с перезагрузкой страницы] → состояние в URL и
  сбрасывается кнопкой; при приёмке решение легко откатить на клиентский JS.
- [«Показывать» на `/settings` больше не «внутри» секции ответов] → связь
  подкреплена общей карточкой и подписью; URL-контракт не менялся.
- [Авто-добавление CLI фиксирует опечатки] → значения видны в секции
  «Справочники», доступны переименование и удаление.
- [Каскадное переименование правит много записей] → валидация до записи,
  round-trip сериализации сохраняет поля и преамбулу, регенерация `index.json`,
  тест на копии реестра.
- [Значения вне справочника никуда не деваются] → штатный режим «вне
  справочника» с кнопкой «внести»; отсутствие файла не ломает страницы.
- [Старые ссылки с `agents`/`providers`] → параметры и семантика не изменились,
  `only_debts` — добавка.

## Migration Plan

1. Справочник: файл, парсер/сериализатор, сид из реестра, тесты (UI не затронут).
2. CLI: авто-добавление значений.
3. Блок «Фильтр»: макрос, стили, пять страниц, `only_debts`.
4. Секция «Справочники» и CRUD-роуты.
5. Селекты в `/add` и `/edit`.
6. Smoke-тесты, браузерная приёмка, CHANGELOG и шапка `models.yaml`.

Откат: revert коммита; `data/lookups.yaml` безвреден — старый код его не читает.
