# Design

## Context

Карточка «Динамика ELO» на `/stats` выбирает, какие модели показать линиями.
Сейчас выбор задают три независимых контрола: чипы выбранных моделей, текстовое
поле «id моделей через запятую» и отдельное поле «Поиск по реестру» с
выпадашкой (`tools/server.py:2362-2403`, `tools/static/js/lines-picker.js`).
Разбор параметра `lines` — `parse_lines_param()` в `tools/render_helpers.py:1108` —
принимает только точные `id` реестра и молча отбрасывает всё остальное; пустой
результат подменяется дефолтом `parse_lines_param(...) or default_line_ids(...)`
(`tools/server.py:3724`).

Замер на рабочих данных (37 моделей, 675 вердиктов) показывает четыре молчаливых
искажения:

| ввод | результат разбора | что на графике |
|---|---|---|
| `Cursor Fable 5.1 1M Max` (имя) | `[]` | тихо топ-5 по ELO |
| `id, Имя` | только `id` | имя исчезло без следа |
| 12 корректных `id` | 10 наибольших по ELO | порядок ввода потерян |
| пустое поле | `[]` | тихо топ-5 по ELO |

Дополнительно: поле «Поиск по реестру» не имеет атрибута `name` и без
JavaScript не отправляется — на странице без скриптов оно выглядит рабочим, но
ничего не делает; лимит 10 в JS (`MAX_LINES`) проглатывается молча; палитра
`ELO_LINE_COLORS` (`tools/render_helpers.py:1102`) содержит ровно 10 цветов, то
есть 10 линий — аппаратный предел карточки.

Ограничения, которые учитывает решение:

- `/stats` — один GET без состояния на сервере; страница обязана оставаться
  отзывчивой на 1000 моделях (спека `leaderboard-ui`, «Отзывчивость консоли на
  целевом масштабе»).
- Зеркало (`tools/export_web.py`) собирает `/stats` с `READ_ONLY=1`: контролы
  выбора не рендерятся, карточка показывает состояние по умолчанию (топ-5,
  90 дней) — это требование `static-mirror`, менять его нельзя.
- Форма выбора — обычная GET-форма; без JavaScript она обязана работать.
- `parse_lines_param` и `default_line_ids` — общие помощники; их использует и
  слепок.

## Goals / Non-Goals

**Goals:**

- Один контрол выбора вместо трёх; текстовое поле — источник правды, чипы —
  производная его разбора.
- Разбор списка на сервере как единственный источник правды: серверный рендер
  страницы, подсказки в поле и живая проверка в браузере используют один и тот
  же результат.
- Ни одного молчаливого искажения: неразобранный токен, неоднозначный токен,
  не вошедшая в лимит модель и пустой результат видны пользователю.
- Поведение без JavaScript не хуже текущего: та же форма применяет выбор.

**Non-Goals:**

- Механика ELO, формула, `data/index.json`, журнал вердиктов, экспорт и слепок
  не меняются.
- Настраиваемые пользователем наборы моделей, сохранённые пресеты, другие
  способы фильтрации графика.
- Расширение лимита линий: 10 линий ограничено палитрой, палитра не трогается.
- Изменение блока фильтра страницы («Показывать», агент, компания): пул
  выбора моделей не зависит от него, дефолт остаётся «топ-5 активных по ELO»
  по всему реестру.

## Decisions

### D1. Текстовое поле — источник правды, чипы — его разбор

Поле содержит список токенов через запятую; чипы показывают результат разбора
этого текста (найденные модели, «не найдено», «неоднозначно»). Удаление чипа
убирает соответствующий токен из текста поля.

*Альтернативы.* (а) Оставить три контрола — текущее состояние: непонятно,
какой из них главный, и поле поиска без JavaScript мертво. (б) Только чипы с
выпадающим списком — отказ от ручного ввода, ради которого всё и затевалось.
(в) Отдельный `<select multiple>` — не поддерживает произвольный текст и
плохо переживает 1000 моделей.

### D2. Резолвер на сервере, правила — в порядке убывания строгости

Порядок разбора токена: точный `id` → точное имя (без учёта регистра) →
однозначная подстрока имени → однозначная подстрока `id`. Ничего не подошло —
«не найдено»; подошло несколько — «неоднозначно» с кандидатами. Дубликаты
схлопываются на первом вхождении.

Резолвер живёт в `render_helpers.py` рядом с `parse_lines_param` и возвращает
структуру «список моделей + токен с его статусом». Её используют и рендер
страницы, и JSON-эндпоинт, и браузер.

*Альтернативы.* (а) Клиентский резолв по полному реестру — нужен весь реестр
в браузере (десятки килобайт на 1000 моделей) и риск расхождения правил с
сервером. (б) Только `id` — текущее поведение: ручной ввод по имени невозможен.

### D3. Отсутствие параметра и неразбираемый параметр — разные случаи

`lines` отсутствует → дефолт «топ-5 активных по ELO» (состояние по умолчанию,
которое видит и зеркало). `lines` присутствует, но не разбирается → пустое
состояние карточки, подмены на дефолт не происходит. Связка
`parse_lines_param(...) or default_line_ids(...)` разрывается: дефолт
применяется только по отсутствию параметра.

*Альтернатива.* Оставить подмену и отличать «пусто» от «ошибка» только по
тексту подсказки — пользователь продолжит получать чужой график.

### D4. Порядок ввода вместо отбора по ELO

При числе разрешённых моделей больше 10 берутся первые 10 в порядке
перечисления, и карточка сообщает, какие модели не вошли. Отбор «10
наибольших по ELO» молча переставлял набор и выкидывал модель, которую
пользователь поставил последней.

*Альтернатива.* Сохранить отбор по ELO — он неожиданен для ручного списка и
противоречит идее «порядок ввода = порядок линий».

### D5. URL канонический, поле — человеческое

Поле рендерится именами выбранных моделей, а не `id`. Если все токены
разобрались, ответ отдаётся редиректом на канонический URL, где `lines`
содержит `id`; если часть токенов не разобралась, редиректа нет — исходный
текст сохраняется в URL, чтобы предупреждения и текст пользователя не
потерялись.

Итог: адрес однозначен и стабилен (можно делиться), при этом читается руками
и не превращается в набор слагов.

*Альтернативы.* (а) Хранить в URL сырой текст пользователя — длинный,
нестабильный (переименование модели ломает ссылку), допускает many-to-one
«один набор — много URL». (б) Без редиректа, только канонические `id` — тогда
после отправки имена теряются, и «почему в адресе слаг, а в поле имя» требует
пояснений.

### D6. Пресеты показывают состав до применения

Ссылки «Топ-5»/«Топ-10» подписываются именами моделей, которые в них попадут
(состав считается на текущий момент по всему реестру, как и дефолт). Клик по
ссылке применяет набор и открывает страницу с этими моделями.

*Альтернатива.* Ссылка без состава — пользователь узнаёт содержимое набора
только после перехода; длинный URL со слагами нечитаем.

### D7. Один эндпоинт разбора вместо поиска по подстроке

`GET /stats/models/resolve?q=<список токенов>` отдаёт по каждому токену
статус (`ok` / `ambiguous` / `not-found`), разрешённый `id`, имя, ELO и
кандидатов для неоднозначных. Эндпоинт `/stats/models?q=` (поиск по
подстроке) используется только пикером и заменяется этим: тот же ответ
обслуживает и подсказки по текущему токену, и живую проверку всего списка.

*Альтернативы.* (а) Два эндпоинта — дублирование правил выдачи кандидатов.
(б) Отдавать клиенту весь реестр — лишние килобайты и риск расхождения правил.

### D8. Без JavaScript: форма и серверный разбор

Без скриптов работает GET-форма: поле со списком моделей, кнопка «Показать»,
серверный разбор и рендер чипов. Недоступны подсказки, живая проверка и
удаление отдельного чипа — вместо них правка текста поля. Поле «Поиск по
реестру» как отдельный контрол исчезает, поэтому мёртвый без скриптов
элемент из интерфейса уходит.

### D9. Зеркало не меняется

`READ_ONLY=1` по-прежнему скрывает контролы выбора, карточка показывает
топ-5 за 90 дней. Новый эндпоинт разбора в зеркале не нужен: клиентский код
пикера в зеркале не подключается.

## Risks / Trade-offs

- [Редирект на канонический URL добавляет один запрос к отправке формы] →
  канонизация выполняется только когда все токены разобрались; при ошибках
  редиректа нет, поэтому цикла не возникает.
- [Правила разбора могут дать неоднозначность там, где пользователь ожидал
  точное имя] → точное имя проверяется первым, неоднозначность показывается с
  кандидатами, а не молча.
- [Поле в формате «имена через запятую» ломается на именах с запятой] →
  имена с запятой в реестре отсутствуют; правило оговорено в design, при
  появлении таких имён поле выводит `id` вместо имени.
- [Живая проверка добавляет запросы на каждое нажатие клавиши] → debounce как
  в существующем `live-search.js` (180 мс), запрос один на весь список.
- [Редирект меняет URL, по которому пришёл пользователь] → сохраняются все
  прочие параметры страницы (фильтры, период, постраничность), как это уже
  делает `_stats_url()`.
