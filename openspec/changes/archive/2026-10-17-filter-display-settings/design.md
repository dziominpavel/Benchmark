# Design

## Context

См. `proposal.md` — Why. Текущее состояние (после архивной доработки `agent-provider-lookups`, коммит c2c1282):

- Единый блок «Фильтр» рендерит макрос `filter_panel()` (`tools/templates/_tag_filter.html`): одна GET-форма страницы, контролы через `{% call %}`, чипы — чекбоксы с `onchange="this.form.submit()"`, сегменты «Показывать» — radio. Контекст строит `filter_panel_context()` (`tools/server.py:200`): списки чипов из `_tag_values()` (алфавит), выбранные наборы, скрытые поля для отдельных форм (`filter_hidden()`).
- Скрытие реализовано в каждом роуте по-своему: главная (`leaderboard`, :1794) фильтрует `models_sorted` → `models_visible`, ранги/медали/d5 считаются по статусному пулу до фильтра; `/stats` (:1730) сужает пул; `/history` (:1605) сужает записи; `/add` (:1954) сужает список; `/settings` (:2099) сужает строки матрицы; POST `/answer_flags` (:2420) пересчитывает набор `visible`, чтобы сохранить скрытые флаги как были.
- Строка статистики главной: `Моделей: X из Y · Вердиктов …`; счётчик истории: `Всего записей: N · Фильтр: …`; сводка статистики: `моделей: N · ниже 1200: …`.
- Бары `/stats` строит `build_elo_distribution_svg()` (`tools/render_helpers.py:332`): `<rect class="dist-pt-below|dist-pt-above">`, подписи/линии.
- CSS-слои строк: `tr.top-1..3 td` (фон, `console.css:590`), `tr.archived td {opacity:.6}` (:599), hover перекрывает фон top-строк.

## Goals / Non-Goals

**Goals:**

- Все настройки — производные отображения: ни один роут не меняет правила совпадения, состав данных в режиме «Подсвечивать» и файлы данных.
- Одна точка чтения/сортировки — `filter_panel_context()`; роуты лишь ветвятся «фильтровать или помечать».
- Нулевая персистентность: `view`/`chips` живут в URL текущего запроса и переносятся собственными ссылками страницы.

**Non-Goals:**

- Не трогаем форму вердикта, очередь рекомендаций, `get_recommendations`, формулу ELO, `index.json`.
- Не переносим настройки между страницами и заходами (cookie/сессии сознательно нет).
- Не сортируем по ELO саму таблицу/матрицу — только чипы.
- Не делаем клиентский JS-слой: рендер серверный, как везде.

## Decisions

### 1. Раскрывашка `«Настройки фильтра»` — нативный `<details class="filter-settings">` первым элементом формы

Внутри — две строки `.filter-row` с `.segmented` (существующий CSS-паттерн): «Режим» — radio `view=hide|highlight`, «Чипы» — radio `chips=alpha|elo`; `onchange="this.form.submit()"`. Подпись summary формирует `filter_panel_context()`: при дефолтах — только «Настройки фильтра», иначе «подсветка · чипы по ELO» (текстовые метки от значений). Альтернативы: JS-попап (лишний JS, в проекте нет), всегда развёрнутый блок (место, просили сворачиваемый).

### 2. Параметры `view`/`chips` — поля той же GET-формы, валидация на сервере

Хелперы рядом с `valid_answer_filter()`: `valid_filter_view()` → `hide|highlight`, `valid_chips_order()` → `alpha|elo`; отсутствие/невалидное = дефолт. Значения добавляются в `filter_panel_context()` (`filter_view`, `filter_chips`), в `filter_hidden_fields` — как `view`/`chips`, когда не дефолт. Перенос: `history_params` (пагинация), `_settings_filter_params` (redirect'ы /settings), redirect после POST `/answer_flags`. «Сбросить» формируется в контексте с сохранением параметров. Альтернативы: cookie/localStorage — отвергнуто («состояние хранить нигде не надо»); POST — форма страницы уже GET.

### 3. «Подсвечивать» в роутах — маркировка вместо фильтрации

Универсальное правило: `hit` = строка проходит весь блок (статус + чипы + «Только долги» на /settings). По страницам:

- **Главная**: `models_sorted` = полный реестр (все статусы, сортировка по ELO); ранги 1..N, медали/тренды — по этому пулу (`compute_rank_trends` уже принимает pool ids). Каждой видимой строке — признак `hit`; шаблон рендерит все строки с классами `filter-hit`/`filter-miss`, секция `archived-section` в этом режиме не рендерится, счётчик — `Моделей: N · подсвечено M`, пустое состояние не показывается.
- **`/stats`**: `pool` = все модели; `entry["hit"]`; `build_elo_distribution_svg(entries, dim=True)` добавляет барам класс `dist-pt-*-hit` / `-miss`; сводка дополняется `· подсвечено: M`.
- **`/history`**: `raw_history` не сужается; `format_elo_history()` получает карту `hit` и отдаёт `item["hit"]`; страница рендерит до 20 записей всей истории, счётчик `Всего записей: N · подсвечено: M`; `hit` считается по правилам состава (модель/чипы), выпадайка — как раньше.
- **`/add`**: `models_list` не сужается, каждая запись `hit`; пустое состояние не показывается.
- **`/settings`**: `answer_rows` = все строки матрицы, `r["hit"]` по `answer_filter` + чипам + `only_debts`; счётчики «Активных»/«Неактивных (архив)» — полный реестр; save-роут в этом режиме считает все строки видимыми (правило «скрытые сохраняются как были» остаётся только для неактивных тасков).

Альтернатива: отдельные ветки на каждую страницу с дублированием условий — отвергнуто: признак `hit` считается из уже существующих предикатов (`model_passes_tags`, статус, долги), одна семантика на всех.

### 4. Порядок чипов — сортировка в `filter_panel_context()`

`_tag_values()` остаётся; при `chips=elo` списки пересортировываются по убыванию max ELO моделей группы (по полному `models`, включая архивные), при равенстве — алфавит (case-insensitive). Чип «без агента/компании» уже рендерится шаблоном после цикла — «всегда последним» сохраняется без правок. Альтернативы: средний/медианный ELO (max — «сильнейшая модель группы», устойчивее на малых группах).

### 5. CSS-слой подсветки

Новые правила в `console.css` (после правил `top-*`/`archived`):

- `tr.filter-hit td { background: color-mix(in srgb, var(--accent) 12%, transparent); }` + полоса слева inset-тенью на первой ячейке; hover — как у top-строк (`var(--surface-2)`).
- `tr.filter-miss td { opacity: .55; }`, `tr.filter-miss:hover td { opacity: .85; }`.
- Комбинации: `tr.archived.filter-miss td { opacity: .45; }`, `tr.archived.filter-hit td { opacity: .8; }` — прозрачности не перемножаются автоматически, комбинации фиксируем явно.
- Бары: `rect.dist-pt-below.filter-miss, rect.dist-pt-above.filter-miss { opacity: .5; }`, `rect.dist-pt-below.filter-hit, rect.dist-pt-above.filter-hit { stroke: var(--accent); stroke-width: 2; }`.
- История/`/add`: тот же класс `filter-hit`/`filter-miss` на `.history-item` и `tr`; «приглушение» через `opacity`, чтобы работало и на тёмной, и на светлой теме.

### 6. Пустые совпадения

`hit_count == 0` при активных контролах: приглушение не применяется (нет `filter-miss`), на главной/истории/настройках — подпись «ничего не подсвечено»; на `/stats` — «подсвечено: 0» в сводке. Пустые состояния скрывающего режима не рендерятся.

## Risks / Trade-offs

- [Каскад CSS: фон top-1..3 vs filter-hit, прозрачности archived × miss, hover и темы] → правила filter-* объявлены после top-*/archived, комбинации заданы явными селекторами; ручная проверка всех комбинаций на тёмной и светлой темах.
- [В подсветке матрица `/settings` содержит все строки в форме — больше полей в POST] → локальная консоль (десятки строк), приемлемо; save-роут берёт видимость строк из того же расчёта, что рендер.
- [Пагинация истории в подсветке размазывает отобранные записи по страницам] → принято сознательно («ничего не скрываем»); счётчик показывает объём подсвеченного.
- [Ранги/d5 на главной в подсветке считаются по полному реестру, в скрывающем режиме — по статусному пулу] → зафиксировано в спеках; при переключении режима цифры места меняются — это ожидаемое следствие пула.
- [Забытые ссылки/redirect'ы теряют `view`/`chips`] → единый источник `filter_hidden_fields` + `history_params` + `_settings_filter_params`; проверка сброса, пагинации и сохранения матрицы в ручном прогоне.

## Migration Plan

Данные не мигрируются, деплой не требуется (локальный сервер): изменение выходит вместе с обычным перезапуском `tools/server.py`; откат — revert коммита, настройки живут только в URL. Пользовательский пункт — в `CHANGELOG.md` (`[Unreleased]`, «Добавлено»), по правилам репозитория.
