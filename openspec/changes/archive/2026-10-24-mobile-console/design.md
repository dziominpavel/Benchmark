# Design

## Context

См. `proposal.md` — Why. Ниже только то, что определяет технические решения.

- Вся раскладка живёт в одном `tools/static/css/console.css`; шаблон оболочки —
  `tools/templates/shell.html`.
- Строка истории `_verdict_row.html` верстается сеткой из пяти колонок
  (`badge | a | vs | b | meta`) с `minmax(0, 1fr)` у колонок участников.
  Мобильной ветки у `.history-item` нет, поэтому обе `1fr`-колонки сжимаются
  в 0, а кластер `.history-meta` с `white-space: nowrap` и `min-width: 86px`
  у `.outcome` задаёт минимальную ширину строки около 412 px.
- `.page`, `.site-header-inner`, `.site-footer` используют
  `clamp(24px, 4%, 32px)`, а `.table-wrap` — отрицательные поля `-var(--sp-6)`.
- `.mirror-banner` переносится по строкам без ограничения высоты.
- `.settings-grid` — `repeat(auto-fit, minmax(320px, 1fr))`.
- Графики — SVG с фиксированным `viewBox="0 0 860 …"` и CSS `width: 100%`;
  при контейнере 292 px шрифт 11 px в единицах SVG превращается в 3,7 px.
- Статическое зеркало (`tools/export_web.py`) рендерится теми же шаблонами и
  копирует тот же CSS, поэтому любые правки раскладки попадают в него
  автоматически.

## Goals / Non-Goals

**Goals:**

- Убрать горизонтальное переполнение страниц на 360–430 px и сделать историю
  читаемой.
- Сократить высоту шапки, плашки и фильтра, не скрывая контролы фильтрации.
- Вернуть читаемость подписей графиков.
- Сохранить вид консоли на десктопе и в статическом зеркале.

**Non-Goals:**

- Переверстка таблицы рейтинга в карточки и скрытие её колонок.
- Сворачивание блока «Фильтр» в `<details>` — спека `leaderboard-ui` прямо
  запрещает скрывать контролы фильтрации.
- Мобильное меню-гамбургер и любая раскладка, требующая JS.
- Изменение данных, API и формата экспорта.

## Decisions

### D1. Единая переменная отступов `--page-pad`

На `:root` вводится `--page-pad: clamp(24px, 4%, 32px)`; при `max-width: 600px`
она становится `12px`. Переменную используют `.page`, `.site-header-inner`,
`.site-footer`, `.mirror-banner` и отрицательные поля `.table-wrap`.

Почему: сейчас отрицательные поля таблицы жёстко привязаны к `--sp-6` (24 px) и
не совпадают с отступами контейнера после их уменьшения — таблица начала бы
вылезать за вьюпорт. Одна переменная убирает рассинхрон.

### D2. Стековая строка истории вместо пяти колонок

```
@media (max-width: 600px) {
  .history-item {
    grid-template-columns: minmax(0, 1fr) auto;
    grid-template-areas:
      "badge badge"
      "a     aelo"
      "b     belo"
      "meta  meta";
    gap: 2px var(--sp-3);
  }
  .history-item-no-task {
    grid-template-areas: "a aelo" "b belo" "meta meta";
  }
  .history-vs { display: none; }
  .history-elo-group { justify-content: flex-end; }
  .history-meta { justify-content: flex-start; flex-wrap: wrap; }
  .outcome { min-width: 0; }
}
```

При 360 px остаётся 336 px контента: 12 px отступа строки, 12 px зазора и
около 128 px на блок счёта — имени достаётся примерно 184 px вместо нуля.
Длинные имена по-прежнему усекаются многоточием по существующему требованию,
полное имя остаётся в `title`.

Почему не оставить пять колонок с горизонтальной прокруткой: прокручивать
каждую из 20 записей отдельно бессмысленно, а общая ширина строки расширяет
страницу. Почему не карточки с дублированием разметки: текущая сетка уже
даёт нужные блоки, достаточно переопределить `grid-template-areas`.

### D3. Компактная оболочка

- `.site-header-inner`: `flex-wrap: nowrap`, `padding: 8px var(--page-pad)`,
  зазор 8 px.
- `.brand`: шрифт `--fs-sm`, зазор 8 px, `min-width: 0`.
- В `shell.html` текст названия оборачивается в `<span class="brand-text">`.
  При `max-width: 520px` он скрывается визуально (`position: absolute`,
  `clip-path: inset(50%)`), но остаётся в DOM — скринридер сохраняет имя
  ссылки. Знак «E» остаётся ссылкой на главную.
- `.site-nav`: `flex-wrap: nowrap`, зазор 0.
- `.site-nav a`: `min-height: 44px`, `display: inline-flex`,
  `padding: 0 8px`, шрифт `--fs-sm`; при `max-width: 400px` — `--fs-xs` и
  `padding: 0 6px`.
- `.theme-toggle`: 40×40 → 44×44 (высота шапки 44 + 16 = 60 px плюс граница).
- `.mirror-banner`: `padding: 4px var(--page-pad)`, шрифт `--fs-xs`,
  зазор `2px var(--sp-3)`. Фраза «демонстрационная копия — только просмотр»
  и ссылка в каталог не меняются — плашка просто переносится на две строки
  и занимает около 40 px вместо 87.

Почему скрывается именно текст, а не навигация: четыре ссылки и кнопка темы —
это функциональный минимум, а знак «E» вместе с пунктом «Рейтинг» дублирует
переход на главную.

### D4. Компактный, но всегда видимый фильтр

Ветка `max-width: 600px`: `padding: var(--sp-3)` у `.filter-card`,
`margin-bottom: var(--sp-2)` у `.filter-head`, `gap: var(--sp-2)` у
`.filter-rows`, `gap: 6px var(--sp-2)` у `.filter-row`, `min-width: 0` у
`.filter-label`, `flex: 1 1 120px; min-width: 0` у полей и селектов,
уменьшенные чипы. Существующее правило `≤639px`, растягивающее
`.filter-head-actions` на всю ширину, отменяется.

Ожидаемая высота: главная — около 230 px вместо 486–555 px; живая история —
около 460 px вместо 737 px (замер на 360 px). Разница объясняется составом:
на живой истории 15 контролов (модель, таск, даты с пресетами, исход, пара и
три флажка) и 22 чипа компаний, а в read-only зеркале интерактивных контролов
нет — там история укладывается в 241 px. Цель ≤320 px зафиксирована только для
главной и зеркала; для живой истории принят предел ≤480 px, потому что
уложиться в 320 без скрытия контролов (запрещено спекой `leaderboard-ui`) или
сжатия полей дат до нечитаемых ~70 px нельзя. Сворачивание отклонено:
требование «Единый блок «Фильтр»» запрещает прятать контролы фильтрации в
сворачиваемый элемент.

### D5. Обёртка графиков `.chart-scroll` в `render_helpers`

Все три построителя (`build_elo_svg`, `build_rating_svg`,
`build_elo_multiline_svg`) оборачивают готовый `<svg>` в
`<div class="chart-scroll">…</div>`; легенда и пустые состояния остаются
снаружи. CSS:

```
.chart-scroll { overflow-x: auto; overscroll-behavior-x: contain; }
@media (max-width: 900px) { .chart { min-width: 800px; } }
```

При `viewBox` шириной 860 и минимальной ширине 800 px эффективный кегль
подписей — около 10,2 px вместо 3,7 px. Обёртка централизована в трёх
функциях, поэтому шаблоны страниц менять не нужно и зеркало получает то же
поведение.

Почему не увеличивать `font-size` в SVG: подписи позиционируются в единицах
`viewBox`, рост кегля без пересчёта отступов приводит к наложению.

Почему не генерировать отдельный «мобильный» SVG: сервер не знает ширину
вьюпорта, а два варианта в разметке удваивают вес страницы.

### D6. Сетка настроек и таблицы

- `.settings-grid`: `repeat(auto-fit, minmax(min(320px, 100%), 1fr))` — трек
  больше не может быть шире контейнера.
- `.table-wrap` на мобильных сохраняет полноэкранную прокрутку, но считает
  поля от `--page-pad`.
- Ячейки таблиц при `max-width: 600px` получают уменьшенные горизонтальные
  отступы, чтобы в кадр помещалось больше колонок.

### D7. Проверка

1. `python -m pytest tools -q` — тесты аналитики и экспорта зелёные.
2. `python tools/export_web.py --out <temp>` — зеркало собирается.
3. Браузерная проверка на 360×740, 390×844 и 430×932 для `/`, `/history`,
   `/stats`, `/settings`, `/model/<id>` и страниц зеркала:
   - `document.documentElement.scrollWidth <= window.innerWidth`;
   - высота `.site-header` ≤ 64 px, высота `.mirror-banner` ≤ 48 px;
   - у `.history-item` ширина контента ≤ ширины контейнера, ширина ссылки
     модели > 0;
   - ширина `.chart` ≥ 800 px на мобильных;
   - трек `.settings-grid` ≤ ширины контейнера.
4. Повторная проверка на 1440×900: десктопная раскладка не изменилась.

## Risks / Trade-offs

- **Строка истории становится выше**: 4 строки вместо 2 при 20 записях на
  страницу. → Зазоры сведены к 2 px, кегль остаётся `--fs-sm`; выигрыш в
  читаемости важнее плотности.
- **Горизонтальная прокрутка графиков**: часть графика видна не сразу. →
  Прокрутка ограничена карточкой, ось и подписи читаемы, страница не
  расширяется.
- **Скрытие названия консоли на узкой шапке**: меньше узнаваемости. →
  Знак «E» остаётся ссылкой на главную, текст сохраняется для скринридеров,
  `<title>` страницы не меняется.
- **Единый CSS для живой консоли и зеркала**: правка затрагивает оба
  представления. → Это осознанно: зеркало должно повторять консоль; проверка
  зеркала входит в приёмку.
- **`scroll-margin-top: 84px` в истории** рассчитан на прежнюю высоту шапки. →
  После уменьшения шапки поправить на 72 px, чтобы якорь не оставлял лишний
  зазор.

## Migration Plan

Миграции данных нет. Для витрины нужно пересобрать статическое зеркало
(`export_web.py`) и передеплоить стор. Откат — revert коммита и повторная
сборка.
