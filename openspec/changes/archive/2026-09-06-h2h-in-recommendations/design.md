## Context

Блок рекомендаций рендерится сервером `tools/server.py`: `get_recommendations`
считает `pair_games` через `get_pair_game_counts` (число неаннулированных
вердиктов пары по всем `matchups/*/`) и формирует текстовую `reason`.
Вердикты (`matchups/*/NNN.json`) содержат `winner` (`a`/`b`/`draw`),
поэтому счёт серии восстановим. См. proposal.md — Why.

## Goals / Non-Goals

**Goals:**
- Показать в карточке число личных встреч пары и счёт по победам.
- Убрать поле `reason` из вывода и из UI.
- Не менять сортировку рекомендаций и формат журнала `matchups/`.

**Non-Goals:**
- Ничьи в счёте не выделяются (осознанное решение пользователя).
- Маркеры «новая модель» / «мало игр» не возвращаются в другом виде —
  число игр модели видно в колонке leaderboard.
- Разрез личных встреч по задачам не вводится (как и в `pair_games`).

## Decisions

**D1: `get_pair_game_counts` заменяется на `get_pair_stats`.**
Одна функция за один проход по `matchups/` возвращает
`{frozenset({a, b}): {"games": int, "wins": {model_id: int}}}`.
`games` используется для сортировки (бывший `pair_games`), `wins` — для
счёта серии. Альтернатива — вторая функция для побед — отвергнута:
двойной обход журнала и два источника правды о паре.

**D2: `h2h_label` форматируется в Python внутри `get_recommendations`.**
Шаблон остаётся «тупым»: `{{ rec.h2h_label }}`. Форматирование строки
(и ветка «не встречались») тестируется без рендера HTML. Вердикт с
`winner: "a"/"b"` маппится на id через `resolve_matchup_models` —
победа засчитывается id победителя, а не позиции в карточке.

**D3: Ориентация счёта = порядок карточки.**
`h2h_label` — «личные встречи: N · счёт W_a:W_b», где `W_a`/`W_b` —
победы `model_a` и `model_b` (отсортированные id, слева направо в
карточке). Пользователю не нужно знать, кто был «A» в конкретном
вердикте.

**D4: `reason` удаляется полностью, не заменяется маркером.**
ELO-причины неинформативны (разница видна в карточке); «новая модель» /
«мало игр» дублируют колонку игр leaderboard. Сортировка продолжает
использовать `tier`/`score` внутри `get_recommendations` — поля
остаются в выводе для прозрачности и тестов.

**D5: CSS-класс `rec-reason` переименовывается в `rec-h2h`** (или
переиспользуется без переименования — решение на этапе реализации,
визуально строка не меняется).

## Risks / Trade-offs

- `test_pairing.py` мокает `get_pair_game_counts` и ассертит «рематч» в
  `reason` → мок и assert обновляются под `get_pair_stats`/`h2h_label`;
  задача явно внесена в tasks.md, иначе тест упадёт.
- Потеря объяснения «почему эта пара первая» для новых моделей → принято:
  сортировка не видна в UI ни сейчас, ни после; при необходимости маркер
  вернётся отдельной маленькой правкой.
- `pair_games` считает вердикты со всеми результатами, включая ничьи →
  возможны строки вида «личные встречи: 3 · счёт 1:1» (третья встреча —
  ничья); это осознанно и соответствует решению не выделять ничьи.
