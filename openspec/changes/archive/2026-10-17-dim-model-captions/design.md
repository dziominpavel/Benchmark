# Design

## Context

См. `proposal.md` — Why. Состояние на момент планирования:

- Подписи `Компания · Агент` рендерятся в двух видах разметки:
  - HTML — класс `.model-caption`: главная (`tools/server.py:694`), архивные на
    главной (`732`), `/history` (`875`, `877`), шапка `/model/<id>` (`910`),
    `/add` (`1077`), `/settings` (`1311`, `1330`, `1437`); стиль —
    `tools/static/css/console.css:1180` (`color: var(--muted)`, 12px, блок
    под именем);
  - SVG — класс `.dist-caption`: только бары «Распределение Elo» `/stats`
    (`tools/render_helpers.py:392`); стиль — `console.css:1176`
    (`fill: var(--muted)`, 10px).
- Краска `--muted`: `#9aa7b8` (тёмная тема, поверх карточки `--surface`
  `#12141c`) и `#55606d` (светлая, поверх `#ffffff`); это уже «второй
  уровень» яркости.
- Архивные строки таблиц приглушены: `tr.archived td { opacity: 0.6 }`
  (`console.css:596`).
- Переменные тем: общий блок `:root, [data-theme="dark"]` (`console.css:9`)
  и оверрайды `[data-theme="light"]` (`console.css:83`).
- У имени, подписи и бара есть `<title>`-тултип с полной строкой
  («имя (подпись) · elo · игр») — при приглушении данные остаются доступны
  при наведении.
- Витрина `web/` подписей не содержит; выпадающие списки и чипы фильтра —
  не место вывода подписи.

Ограничения: меняем только прозрачность; размер шрифта, цветовая основа,
положение и разметка не меняются; стек — stdlib + Flask, без JS-фреймворков.

## Goals / Non-Goals

**Goals:**

- Понизить визуальный шум подписей `Компания · Агент` во всех местах вывода
  единым значением.
- Одна точка тюнинга уровня тусклости (токен), без правки разметки.
- Сохранить присутствие подписи («едва заметна на фоне») и доступность полной
  информации через тултип.

**Non-Goals:**

- Изменение состава подписи, правил пустых значений и `Unknown` (см. спеку).
- Изменение шрифтов, цветовых основ, положения, разметки шаблонов и рендера.
- Тумблеры/настройки отображения подписей в UI.
- Витрина `web/` (подписей там нет).

## Decisions

### D1. Механика — `opacity`, а не смена краски

В правила `.model-caption` и `.dist-caption` добавляется
`opacity: var(--caption-opacity)`. Свойство `opacity` работает одинаково для
HTML (`color`) и SVG (`fill`), поэтому один приём и одно значение закрывают
оба класса.

Отклонённые альтернативы: `fill-opacity` только в SVG-правиле (два разных
свойства ради одного эффекта); отдельная приглушённая краска вместо
прозрачности (пришлось бы держать пару значений на две темы и пересчитывать
под каждый фон — прозрачность даёт то же самое бесплатно).

### D2. Единый токен в общем блоке переменных

`--caption-opacity: 0.45` объявляется один раз в общем блоке
`:root, [data-theme="dark"]`; светлая тема наследует значение. Тюнинг — одна
переменная. Отклонённая альтернатива: литералы `0.45` в двух правилах (две
точки правки при подстройке).

### D3. Стартовое значение 0.45

Ориентир заказчика — «едва заметно на фоне, но не исчезает». Оценка результата:
`0.45 × --muted` даёт ≈ `#4f5662` над тёмной карточкой и ≈ `#b2b7bd` над белой —
«фон-подсказка» в обеих темах. Диапазон кандидатов — .35–.55 (.55 — тускло, но
читаемо; .35 — почти призрак). Значение окончательно подтверждается визуальной
проверкой при apply и при необходимости правится только токен.

### D4. Архивные строки — принять перемножение

В архивных строках действует `tr.archived td { opacity: 0.6 }`, поэтому подпись
получит эффективную непрозрачность ≈ 0.27 (0.45 × 0.6) и станет почти
неразличимой. Принимается как желаемое «архив тише». Отклонённая альтернатива:
компенсация `tr.archived td .model-caption { opacity: 0.75 }` (0.45 / 0.6) —
лишняя правка ради редкого контекста; добавим одной строкой, только если
визуальная проверка покажет провал.

### D5. Что явно не трогаем

`.dist-name`, `.dist-value`, размеры шрифтов, тултипы, разметку `server.py` и
`render_helpers.py`, витрину `web/`. В `CHANGELOG.md` запись не вносится —
UI-косметика по `docs/versioning.md`.

## Risks / Trade-offs

- [Подпись становится нечитаемой] → это осознанная цель («едва заметна»);
  полная информация остаётся в `<title>`-тултипе; тюнинг/откат — одно значение
  токена.
- [Светлая тема окажется слишком бледной или непоследовательной] → значение
  одно на обе темы (одинаковое «расстояние» от базовой краски); при системной
  проблеме — переопределение `--caption-opacity` в `[data-theme="light"]` без
  структурных правок.
- [Архивные строки «проваливаются»] → см. D4: однострочная компенсация при
  необходимости.
