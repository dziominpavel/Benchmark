## MODIFIED Requirements

### Requirement: Источник кандидатов

Кандидатами SHALL быть все неупорядоченные пары активных моделей из
`index.json` (`C(n,2)`). Сыгранные пары НЕ исключаются: для каждой пары
SHALL вестись счётчик `pair_games` — число вердиктов этой пары поверх
всех директорий `matchups/*/` (без tombstone- и аннулированных вердиктов).
Наличие ответов и разрез по задачам НЕ учитываются (упрощение MVP).

#### Scenario: Одна уже сравнённая пара

- **WHEN** существует вердикт A vs B (в любой директории matchups)
- **THEN** пара A-B остаётся кандидатом с `pair_games = 1`
- **AND** ранжируется ниже всех пар с `pair_games = 0`

#### Scenario: Аннулированный вердикт не считается

- **WHEN** вердикт A vs B аннулирован tombstone-событием
- **THEN** он SHALL NOT увеличивать `pair_games` пары A-B

#### Scenario: Меньше двух моделей

- **WHEN** в `index.json` меньше 2 активных моделей
- **THEN** рекомендации пусты

### Requirement: Тиры калибровки и сортировка

Пары SHALL раскладываться по тирам калибровки по `min_games`
(числу игр менее игранной модели в паре, данные из `index.json`):
тир 0 — `min_games == 0` (новая модель), тир 1 — `min_games < 3`
(нужна калибровка), тир 2 — остальные. Сортировка SHALL быть
лексикографической по трём ключам: сначала `pair_games` по возрастанию
(несыгранные пары выше любых рематчей), затем тир по возрастанию,
внутри — близость ELO (`score = closeness = 1 / (1 + elo_diff / 100)`,
`elo_diff = |elo_a − elo_b|`), больший score выше. Потолка на число
рематчей НЕТ: пары с большим `pair_games` автоматически опускаются ниже.

#### Scenario: Расчёт score

- **WHEN** пара A-B: elo_diff=0
- **THEN** score = closeness = 1.0

#### Scenario: Несыгранная пара выше рематча

- **WHEN** пара X: pair_games=0, elo_diff=200, тир 2;
  пара Y: pair_games=1, elo_diff=0, тир 2
- **THEN** выше ранжируется пара X

#### Scenario: Новая модель выше старого близкого боя

- **WHEN** пара X: pair_games=0, elo_diff=0, min_games=1 (тир 1);
  пара Y: pair_games=0, elo_diff=200, min_games=0 (тир 0)
- **THEN** выше ранжируется пара Y

#### Scenario: Рематчи по возрастанию встреч

- **WHEN** все пары сыграны; пара A: pair_games=1, пара B: pair_games=3
- **THEN** выше ранжируется пара A

### Requirement: Причина рекомендации

Каждая рекомендация SHALL содержать человекочитаемую причину по фактическим
порогам кода. Для уже игравшей пары (`pair_games > 0`) причина SHALL быть
«рематч (встречались N раз)». Для несыгранной пары (`pair_games == 0`):
`min_games == 0` → «новая модель, ещё не играла»;
`min_games < 3` → «мало игр (N), нужна калибровка»; `elo_diff < 50` →
«близкий рейтинг (разница N)»; `elo_diff < 150` → «рейтинг различается
умеренно (ΔN)»; иначе → «разный уровень (ΔN) — проверить апсет».

#### Scenario: Новая модель

- **WHEN** модель D имеет 0 игр, пара с D не играла
- **THEN** пары с D получают причину «новая модель, ещё не играла»
- **AND** как тир 0 среди несыгранных стоят выше всех пар без новых моделей

#### Scenario: Близкий рейтинг

- **WHEN** A=1216 (5 игр), B=1220 (5 игр), пара не играла (pair_games=0)
- **THEN** причина — «близкий рейтинг (разница 4)»

#### Scenario: Рематч

- **WHEN** пара A-B уже встречалась 2 раза (pair_games=2)
- **THEN** причина — «рематч (встречались 2 раза)»

### Requirement: Вывод рекомендации

Система SHALL возвращать не более 3 пар (`top_n=3`), отсортированных
по `pair_games`, затем по тиру, затем по убыванию score. Каждая запись
содержит: `model_a`, `model_b`, имена, `elo_a`, `elo_b`, `elo_diff`,
`pair_games`, `reason`, `tier`, `score`. Блок «Рекомендуемые модели к
прогону» показывает имя, ELO и причину; кнопка «Прогнать» подставляет
пару в форму вердикта.

#### Scenario: Отображение рекомендации

- **WHEN** есть активные пары-кандидаты (моделей ≥ 2)
- **THEN** пользователь видит до 3 карточек «Имя (ELO) vs Имя (ELO) | причина»

#### Scenario: Все пары сыграны

- **WHEN** все возможные пары уже сравнены (у всех pair_games ≥ 1)
- **THEN** блок продолжает показывать топ-3 — рематчи с наименьшим
  `pair_games` и наименьшим elo_diff
- **AND** плашка «Все пары уже прогнаны…» SHALL NOT отображаться

#### Scenario: Нет несравнённых пар

- **WHEN** все возможные пары уже сравнены (при ≥ 2 активных моделях)
- **THEN** рекомендации НЕ пусты — возвращаются рематчи по общей
  сортировке (минимальный `pair_games`, затем тир, затем близость ELO)
