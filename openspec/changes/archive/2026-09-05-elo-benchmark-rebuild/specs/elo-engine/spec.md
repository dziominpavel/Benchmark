## Purpose

ELO-движок пересчитывает рейтинги моделей на основе попарных вердиктов судей. Использует классическую формулу ELO с адаптивным K-factor для быстрой калибровки новых моделей и стабильности установившихся рейтингов.

## ADDED Requirements

### Requirement: Начальный ELO

Все новые модели стартуют с ELO = 1200.

#### Scenario: Новая модель регистрируется

- **WHEN** модель добавляется в реестр (models.yaml)
- **THEN** система присваивает ей ELO = 1200
- **AND** поле `games` = 0, `wins` = 0, `losses` = 0, `draws` = 0

### Requirement: Расчёт ожидания

Перед каждым вердиктом система вычисляет ожидаемую вероятность победы по формуле: E_A = 1 / (1 + 10^((R_B - R_A) / 400)), где R_A и R_B — текущие ELO моделей.

#### Scenario: Равные модели

- **WHEN** модель A (ELO=1200) сравнивается с моделью B (ELO=1200)
- **THEN** E_A = 0.50, E_B = 0.50

#### Scenario: Фаворит против аутсайдера

- **WHEN** модель A (ELO=1300) сравнивается с моделью B (ELO=1100)
- **THEN** E_A = 0.76, E_B = 0.24

### Requirement: Адаптивный K-factor

K-factor зависит от количества игр модели: < 10 игр → K=40; 10–30 игр → K=32; > 30 игр → K=24. K-factor применяется индивидуально к каждой модели в паре.

#### Scenario: Новая модель (0 игр)

- **WHEN** модель с 0 игр получает вердикт
- **THEN** её K-factor = 40

#### Scenario: Установившаяся модель (35 игр)

- **WHEN** модель с 35 игр получает вердикт
- **THEN** её K-factor = 24

#### Scenario: Модели с разным опытом в одной паре

- **WHEN** модель A (5 игр, K=40) сравнивается с моделью B (35 игр, K=24)
- **THEN** обновление A использует K=40, обновление B использует K=24

### Requirement: Обновление рейтинга

После вердикта система обновляет ELO: R_A' = R_A + K_A × (S_A - E_A), где S = 1 (победа), 0 (поражение), 0.5 (ничья). ELO обеих моделей обновляется симметрично.

#### Scenario: Победа фаворита (ожидаемый результат)

- **WHEN** A (ELO=1300, K=32, E_A=0.76) побеждает B (ELO=1100, K=32)
- **THEN** R_A' = 1300 + 32 × (1 - 0.76) = 1308
- **AND** R_B' = 1100 + 32 × (0 - 0.24) = 1092

#### Scenario: Победа аутсайдера (апсет)

- **WHEN** A (ELO=1100, K=40, E_A=0.24) побеждает B (ELO=1300, K=24)
- **THEN** R_A' = 1100 + 40 × (1 - 0.24) = 1130
- **AND** R_B' = 1300 + 24 × (0 - 0.76) = 1282

#### Scenario: Ничья

- **WHEN** A (ELO=1200, K=32, E_A=0.50) играет вничью с B (ELO=1200, K=32)
- **THEN** R_A' = 1200 + 32 × (0.5 - 0.50) = 1200
- **AND** R_B' = 1200 + 32 × (0.5 - 0.50) = 1200

### Requirement: Пересчёт из вердиктов

ELO пересчитывается путём последовательного применения всех вердиктов в хронологическом порядке. Каждый вердикт обновляет ELO обеих моделей. Система MAY пересчитывать с нуля или инкрементально — результат идентичен.

#### Scenario: Полный пересчёт

- **WHEN** вызывается пересчёт ELO
- **THEN** система загружает все вердикты из matchups/ в хронологическом порядке
- **AND** применяет каждый вердикт последовательно, начиная с ELO=1200 для всех моделей
- **AND** записывает итоговые ELO в index.json

### Requirement: История изменений ELO

Система сохраняет историю изменений ELO для каждой модели: дата, ELO после обновления, дельта, идентификатор вердикта, который вызвал изменение.

#### Scenario: Запись истории

- **WHEN** вердикт T-001/001 обновляет ELO модели A с 1200 до 1216
- **THEN** в elo_history добавляется запись: { model: "A", date, elo: 1216, delta: +16, after_matchup: "T-001/001" }

### Requirement: Архивные модели не обновляются

Модели со status=archived не участвуют в новых вердиктах. Их ELO замораживается. История сохраняется.

#### Scenario: Архивная модель в пересчёте

- **WHEN** система пересчитывает ELO из всех вердиктов
- **THEN** вердикты с участием архивной модели учитываются (история)
- **AND** новые вердикты с архивной моделью не создаются (pairing engine не предлагает)

### Requirement: Целочисленный ELO

ELO хранится как целое число. Промежуточные вычисления используют float, итог округляется до целого (round half to even).

#### Scenario: Округление

- **WHEN** вычисление даёт R_A' = 1216.7
- **THEN** сохраняется ELO = 1217
