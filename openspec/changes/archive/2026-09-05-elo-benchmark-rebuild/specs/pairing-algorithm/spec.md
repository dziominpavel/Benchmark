## Purpose

Алгоритм предложения пар моделей для сравнения. Помогает пользователю выбрать, какие два ответа на задачу отправить судье. Приоритизирует пары по информативности для ELO-рейтинга.

## ADDED Requirements

### Requirement: Источник пар

Система предлагает пары только для задач, у которых есть ≥ 2 ответов от active-моделей. Пара = (задача, модель A, модель B), где обе модели имеют ответы на эту задачу.

#### Scenario: Задача с одним ответом

- **WHEN** у задачи T-001 только один ответ
- **THEN** система не предлагает пары для T-001

#### Scenario: Задача с тремя ответами

- **WHEN** у задачи T-001 три ответа (A, B, C)
- **THEN** система рассматривает пары: A-B, A-C, B-C

### Requirement: Фильтрация архивных моделей

Архивные модели (status=archived) исключаются из предложений новых пар.

#### Scenario: Архивная модель в ответах

- **WHEN** задача T-001 имеет ответы от A (active), B (active), C (archived)
- **THEN** система предлагает только пары среди active: A-B
- **AND** не предлагает A-C, B-C

### Requirement: Фильтрация уже оценённых пар

Система не предлагает пару (задача, A, B), если для этой задачи уже существует вердикт между A и B. Повторное сравнение возможно только при явном запросе пользователя.

#### Scenario: Пара уже оценена

- **WHEN** для T-001 существует вердикт A vs B
- **THEN** система не предлагает пару A-B для T-001

#### Scenario: Принудительный повтор

- **WHEN** пользователь явно запрашивает повторное сравнение A-B на T-001
- **THEN** система создаёт новый вердикт с следующим NNN
- **AND** ELO пересчитывается с учётом обоих вердиктов

### Requirement: Приоритет пар — калибровка новых моделей

Пары с участием модели, у которой < 3 вердиктов на текущей задаче, получают наивысший приоритет. Это обеспечивает быструю калибровку новых моделей.

#### Scenario: Новая модель

- **WHEN** модель D добавлена, имеет 0 вердиктов на T-001, а модели A, B, C уже сравнены между собой
- **THEN** система предлагает D-A, D-B, D-C (в порядке убывания ELO оппонента)

### Requirement: Приоритет пар — близость ELO

Среди пар без новых моделей система приоритизирует пары с близким ELO. Чем меньше разница |ELO_A - ELO_B|, тем выше приоритет.

#### Scenario: Близкие модели

- **WHEN** A=1216, B=1220, C=1280, все пары не оценены
- **THEN** система предлагает A-B первой (разница 4), затем A-C (разница 64), затем B-C (разница 60)

### Requirement: Приоритет пар — недооценённость

Среди пар с одинаковой близостью ELO система приоритизирует пары, у которых меньше общее количество вердиктов с участием этих моделей.

#### Scenario: Равная близость, разная недооценённость

- **WHEN** A-B и A-C имеют одинаковую разницу ELO, но A имеет 2 вердикта, B — 5, C — 1
- **THEN** система предлагает A-C первой (C недооценена)

### Requirement: Композитный score

Система вычисляет композитный score для каждой пары: score = 0.5 × (1 / (1 + games_count)) + 0.3 × (1 / (1 + elo_diff / 100)) + 0.2 × (1 / (1 + min_games / 10)). Пара с наивысшим score предлагается первой.

#### Scenario: Расчёт score

- **WHEN** пара A-B: games=0, elo_diff=4, min_games=0
- **THEN** score = 0.5 × 1.0 + 0.3 × 0.96 + 0.2 × 1.0 = 0.988

### Requirement: Вывод рекомендации

Система показывает пользователю рекомендацию: задачу, пару моделей, причину выбора (близкий ELO / новая модель / мало голосов), и текущий ELO обеих моделей.

#### Scenario: Отображение рекомендации

- **WHEN** система предлагает пару A-B для T-001
- **THEN** пользователь видит: "Задача T-001 | A (ELO 1216) vs B (ELO 1220) | Причина: близкий ELO, 0 голосов у пары"
