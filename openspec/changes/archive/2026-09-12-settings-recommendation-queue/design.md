## Context

См. `proposal.md` (Why). Текущее состояние: главная (`leaderboard()` в `tools/server.py`) показывает только топ-1 из `get_recommendations(index, top_n=1)`. Страница `/settings` (`settings_page`, `SETTINGS_TEMPLATE`) состоит из двухколоночного `.settings-grid` (Модели, Таски) и полноширинной карточки «Наличие ответов». Покрытие считается в `get_coverage`: `total − filled = осталось`. Ограничение: новый CSS должен вписаться в тёмную тему без новых компонентов.

## Goals / Non-Goals

**Goals:**

- Показать всю очередь READY в порядке рекомендаций тем же кодом, что кормит главную.
- Вписать карточку в существующий layout `/settings` без ломки адаптива.
- Сохранить инвариант `len(queue) == total − filled`.

**Non-Goals:**

- Не менять формулу покрытия и сортировку рекомендаций.
- Не добавлять фильтры, поиск, кнопки «Прогнать» в очереди и live-обновление.
- Не показывать BLOCKED/DONE-строки в списке.

## Decisions

### 1. Источник данных — тот же `get_recommendations` с большим `top_n`

Роут настроек вызывает `get_recommendations(index_data, top_n=<верхняя граница>)`, где граница — число всех возможных ячеек `len(active_tasks) * C(n_active, 2)`. Главная продолжает звать с `top_n=1`. Отдельная функция очереди со своей сортировкой отвергнута: две копии сортировки разъедутся при следующем изменении тиров.

Альтернатива (новый `get_queue()`) отклонена по той же причине — дублирование четырёхключевой сортировки.

### 2. Layout — полноширинная `.card` после «Наличия ответов»

Карточка вне `.settings-grid`, как «Наличие ответов». Третья колонка в гриде отвергнута: таблица пар широкая, в 320px ломается. Внутри: заголовок со счётчиком, строка `stats`, строка `hint`, `.table-wrap` с обычной `table` (`№ | Пара | Таск`), таск — существующей пилюлей, имена — существующим `.edit-link` на `/model/<id>`.

### 3. Длинные списки — скролл контейнера, не пагинация и не JS

Новый класс только для ограничения высоты (например, `.queue-wrap` с `max-height` и `overflow-y: auto`); таблица, пилюли и скролл-обёртка переиспользуются. Пагинация отвергнута: очередь должна читаться как единый порядок «что дальше». JS-фильтры отвергнуты как Non-Goal.

### 4. Пустое состояние — тот же рематч-бейдж, что на главной

Когда READY пуст: `empty-state` («Очередь пуста» / прочерк при неопределённом покрытии) плюс одна строка топ-1 рематча с жёлтым классом типа `.rec-rematch`. Отдельный дизайн пустого состояния не вводится.

## Risks / Trade-offs

- [Рост реестра] При сотнях моделей очередь — десятки тысяч строк, HTML тяжёлый → рендер всё равно серверный и одностраничный; при проблеме позже вводится сворачивание через `<details>`, спека не меняется.
- [Расхождение с главной] Если кто-то поменяет сортировку только для главной → очередь врёт → митигация решением 1 (единый вызов) и инвариантом из спек.
- [Рематч без активного таска] `recommended_task` пуст → в строке показываем прочерк, карточка не падает.
