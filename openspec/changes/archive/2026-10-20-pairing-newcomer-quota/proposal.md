# Proposal

## Why

Пул моделей растёт, а полное покрытие пар стоит `n(n−1)/2` судейских прогонов на каждый активный таск: 630 при 36 моделях, 1770 при 60, 11 175 при 150. Новичок при этом играет всех подряд — включая дальние по ELO пары, которые почти не двигают рейтинг, — и остаётся недокалиброванным относительно цели 50 игр. Квота новичка закрывает эту дыру, не ломая покрытие, пока пул мал.

## What Changes

- Новичок определяется по реестру: активная модель с `added >= 2026-10-19` и числом игр меньше 50. Новых полей в `models.yaml` не появляется.
- В режиме рематчей (READY-ячеек нет) `get_recommendations` сначала добирает игры новичку: ближайшие по ELO пары, у которых есть неаннулированный вердикт в первом активном таске и меньше 3 игр.
- Приоритет квоты: меньше игр у новичка → меньше игр у пары → ближе ELO. Запись помечается `is_rematch=True`.
- Покрытие пар не меняется: пока есть READY-ячейки, квота не включается. При пуле меньше ~52 моделей это сохраняет полную матрицу сравнений.
- Полосовой режим для всего пула (порог n≈52, полоса ±200, квота 50 игр на модель) описан в `docs/pairing-scaling.md`; его код и смена метрики прогресса — отдельным изменением позже.

## Impact

- Код: `tools/server.py` — `get_model_added_map()`, константы квоты, ветка `get_recommendations`.
- Тесты: `tools/test_pairing.py`.
- Спека: `pairing-algorithm` (новое требование).
- UI и формат записи рекомендации не меняются.
