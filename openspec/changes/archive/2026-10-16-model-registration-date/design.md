## Контекст

Реестр `models.yaml` не хранит дату появления модели. Модель нужно уметь
сортировать/фильтровать по «свежести» (будущий фильтр «последние N новых»),
поэтому вводится поле `added`. Изменение маленькое: новое опциональное поле
метаданных + его копия в `index.json`.

## Решения

### Формат: дата без времени (`YYYY-MM-DD`)

Дата, а не timestamp: согласуется с существующим `released` и с датами в
вердиктах (`date`). При регистрации нескольких моделей в один день порядок
внутри дня не определён — тай-брейк по id отдаётся будущему UI. Timestamp
отклонён как избыточный для реестра и ломающий ручное редактирование.

### Бэкфилл существующих моделей — из git-истории

Единственный доступный источник: первое появление строки `- id: <slug>` в
`models.yaml` (поиск по обеим путям — до и после переезда в `data/`).
Оговорка: у моделей, попавших в bulk-коммит 2026-09-05/06, будет дата этого
коммита, а не реальная регистрация. Первый матч (`recorded_at`) отклонён:
это дата первой игры, а не регистрации, и она может отставать на недели.
Бэкфилл — одноразовая операция над данными; постоянного инструмента
«бэкфилл из git» не заводим, в CLI достаточно флага `--added`.

### Копия в `index.json` с проверкой устаревания

UI по спеке `data-storage` читает только `index.json`, поэтому `added`
копируется в `models.<id>` при генерации. Критерий `is_index_stale`
расширяется ключом `added` — иначе правка даты в реестре не перегенерирует
кэш (остальные метаданные уже в списке сравнения). Сравнение для
отсутствующего поля — по пустой строке с обеих сторон: записи без `added`
не считаются расхождением.

### Совместимость

Поле опционально: `load_models_yaml` отдаёт `added` только если оно есть;
`format_model` пишет строку только при непустом значении. `archive_model.py`
и `update_model` (веб) перезаписывают реестр через `format_model`, поэтому
`added` сохраняется автоматически — правка этих скриптов не требуется.

## Альтернативы

- **Timestamp вместо даты** — строгий порядок внутри дня, но реестр
  ручной; дата ближе к текущему стилю `released`. Отклонено.
- **Перенести всё в новый тип данных/БД** — вне масштаба задачи.
- **Сразу UI-фильтр и сортировка** — отдельный change: сначала поле должно
  накопиться в данных и попасть в индекс.

## Риски

- Даты старых моделей могут быть неисторическими (bulk-коммит) — это
  известное ограничение источника, фиксируется в задаче бэкфилла.
- Ручное редактирование `added` возможно как и любых метаданных; `--check`
  ELO-движка на метаданные не смотрит, расхождение ловит `is_index_stale`.
