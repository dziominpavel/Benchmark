# Design

## Context

Волна 3 дорожной карты `docs/ui-ux-review.md` (п. 3 остаток, п. 10, п. 5).
Мотивация — в `proposal.md`; требования — в дельте
`specs/leaderboard-ui/spec.md`.

Текущее состояние, задающее рамки решения:

- Консоль — Flask (`tools/server.py`) + серверные Jinja-шаблоны; фильтры
  ездят через query-параметры GET-форм (`filter_panel_context` собирает блок
  «Фильтр»). Клиентского JS почти нет: `validate()` формы вердикта, `theme.js`,
  в слепке — `mirror.js`.
- `/history` (`history_page`, `tools/server.py:2106`) уже имеет пагинацию по 20,
  фильтры «Модель», «Включать неактивные», «Показывать аннулированные»,
  агент/компания и режимы «скрывать/подсвечивать»; строка рендерится из
  `render_helpers.format_elo_history` (`model_a_name`, ELO до/после, дельты,
  дата, `matchup`, `voided`). Таска, исхода, ссылок и `seq` в строке нет.
- `elo_history`/`voided_history` в `data/index.json` несут `seq`, `matchup`,
  `winner`, `date`, `recorded_at`, id моделей и снэпшоты ELO. Таск в
  `elo_history` отдельным полем не хранится, но всегда есть префикс `matchup`
  (`T-NNN/NNN`); у `voided_history` есть и поле `task`.
- Главная (`leaderboard`, `tools/server.py:2345`): таблица сортируется жёстко
  по ELO; отображаемый пул — `models_sorted` (статусный пул) минус агент/чипы;
  места/медали/d5 считаются по пулу и не должны пересчитываться фильтрами.
  Ни поиска, ни сортировки по клику нет.
- Зеркало (`export_web.py`) рендерит те же страницы при
  `app.config["READ_ONLY"] = True` и собирает слепок; `read_only()` — штатный
  способ деградации контролов (им уже пользуются волны 1–2). Строки истории
  для слепка собираются регуляркой `_HISTORY_ROW_RE` по плоской разметке
  `.history-item`.
- Бюджеты `tools/test_perf.py`: главная ≤0.5/1 с, `/history` ≤1 с при
  1000 моделях и 10 000 событий.

## Goals / Non-Goals

**Goals:**

- Фильтры-поиск истории (таск, даты, исход, пара, «только аннулированные») и
  самодостаточная строка: находятся без листания, URL стабилен для закладок
  и кросс-ссылок (аналитика A4, профиль п. 6 — появятся в волне 4).
- Поиск/сортировка рейтинга и комбобоксы селектов моделей, рассчитанные на
  1000 пунктов, без серверных запросов на ввод.
- Экспорт текущей выборки (CSV/JSON) и постоянные ссылки на вердикт.
- Сохранить без изменений: формат журнала и `index.json`, существующие URL,
  контракты роутов, бюджеты отзывчивости; корректная деградация слепка.

**Non-Goals:**

- «Показать ещё» (лёгкое долистывание) — отклонено: конкурирует с серверной
  пагинацией и не работает в слепке; в ревью помечено опциональным.
- Экспорт «топ-10 как markdown» — icebox (п. 10, подпункт «опционально»).
- Клиентские фильтры/сортировка в слепке — слепок деградирует явно
  (read_only-ветки), перенос в `mirror.js` — отдельная задача.
- Пагинация рейтинга, глобальный поиск по консоли, счётчик в `<title>`
  истории (остаток п. 11 — не эта волна).
- Изменение формата журнала, индекса, CLI-контрактов, ELO-механики.

## Decisions

### D1. Фильтры истории — серверные, поверх существующего конвейера ленты

- Параметры: `task`, `from`, `to`, `outcome` (`a|b|draw`), `pair`,
  `only_voided=1`. Невалидные значения игнорируются (как у существующих
  параметров страницы).
- Конвейер `history_page` расширяется: сборка ленты (`elo_history` или
  `merge_history_feed` при `include_voided`/`only_voided`) → существующие
  фильтры модель/агент/компания → поисковые фильтры → счётчики → пагинация.
  Так «Всего записей: N» = лента до поисковых фильтров, «найдено: M» = после.
- Таск записи выводится из префикса `matchup` (`split("/", 1)[0]`), с
  fallback на `task` для аннулированных (там поле есть). Индекс и журнал
  не меняются — аддитивное поле в `index.json` не требуется.
- Даты сравниваются как строки ISO по `date` с fallback на
  `recorded_at[:10]`; границы `from`/`to` включительные. Пресеты — ссылки
  `from=<сегодня−N>`, `to=<сегодня>` (вычисляются на сервере при рендере,
  UTC-сдвиги не при чём: `date.today()` сервера и есть база).
- `pair`: если значение имеет вид `idA:idB` и оба id есть в реестре —
  точная пара (сравнение неупорядоченной пары id); иначе — подстрока
  регистронезависимой длины по «id и имя» обеих сторон. Точную пару
  используют будущие кросс-ссылки A4 и профиля; свободный текст — ручной
  поиск.
- `only_voided=1` подразумевает показ аннулированных (лента —
  `merge_history_feed`, из неё остаются только `voided`).
- Режим «Подсвечивать»: поисковые фильтры сужают состав и в подсветке
  (поиск — это выборка), подсветка по-прежнему маркирует отобранное по
  модели/агентам/компаниям. Это расхождение зафиксировано в спеках
  («Состав блока «Фильтр»», «Фильтр по агенту и фирме»).
- Новые параметры добавляются в `history_params` (ссылки пагинации,
  «в конец», поле страницы, формы сброса).
- Альтернатива «фильтрация в JS на клиенте» отклонена: ломает URL-стабильность
  (закладки/кросс-ссылки) и бюджет 10k записей; клиентский поиск есть только
  в слепке, но новых фильтров в слепке нет по определению Non-Goals.

### D2. Строка истории: расширение `format_elo_history` passthrough-полями

- В выходные словари добавляются `model_a_id`/`model_b_id`, `task`, `seq`,
  `winner` (и готовые `winner_label` / `winner_aria` подпись+озвучка).
  Разметка строки остаётся плоской (`<span>`/`<a>` внутри
  `.history-item`) — `_HISTORY_ROW_RE` в экспорте зеркала продолжает
  работать, якорь `id="v-<seq>"` вешается на существующий `<div>`.
- Бейдж таска: ссылка на `/history?task=T-001` в живой консоли (быстрый
  переход «показать таск»), `<span>` в слепке (`read_only()`-ветка).
- Метка исхода: текст «победила A» / «победила B» / «ничья» с `aria-label`
  по именам моделей («победила Alpha», «ничья: Alpha vs Beta»); цветовые
  классы `outcome-a`/`outcome-b`/`outcome-draw` — только текст и окантовка,
  без цветозаливки всей строки.
- Чип `matchup_id`: ссылка `?v=<seq>#v-<seq>` (постоянная ссылка), в слепке —
  нейтральный `<span>`.
- CSS: `.badge`, `.badge-task`, `.matchup-chip`, `.outcome-*`,
  `.history-item:target` (подсветка адреса-цели), разделитель имени и
  подписи у `.history-side .model-caption`.

### D3. Постоянные ссылки на вердикт — якорь `#v-<seq>` и редирект `?v=`

- Строка несёт `id="v-<seq>"`; `seq` уникален и есть и у применённых, и у
  аннулированных записей.
- `/history?v=<seq>`: сервер ищет `seq` в текущем составе ленты (с учётом
  переданных фильтров). Найдено → редирект на ту же страницу с нужным
  `page` и `#v-<seq>` (`:target` подсвечивает, JS не нужен). Не найдено по
  текущим фильтрам → поиск по полной ленте (с аннулированными) и редирект
  без поисковых фильтров, с `include_voided=1`. Не найдено вовсе → алерт
  «Вердикт не найден», список не меняется.
- Альтернатива `/verdict/<T-NNN>/<NNN>` (отдельная страница вердикта)
  отклонена: второй источник правды для строки и рассинхрон форматирования;
  якорь дешевле и сразу ведёт в контекст ленты. Ревью допускает оба варианта.

### D4. Пагинация истории: «найдено», поле страницы, «в конец»

- «Найдено: M» показывается только при активном поисковом фильтре (иначе
  счётчик как раньше — не шумим лишними числами).
- Поле «страница №» — маленькая GET-форма рядом с виджетом: hidden-поля
  собраны из `history_params`, значение клампится существующей логикой
  `history_page` (1..pages). «В конец» — ссылка на последнюю страницу.
- Оба элемента — `read_only()`-ветки (в слепке виджет остаётся прежним,
  клиентская пагинация зеркала его не использует).

### D5. Поиск рейтинга: `q`, серверная подстрока

- `q` фильтрует отображаемый пул по подстроке (casefold) в имени и id в
  обоих режимах (единое правило с D1: поисковые фильтры сужают, подсветка
  маркирует остаток).
- Сохраняется в URL и во всех ссылках страницы: сортировка, экспорт,
  «Сбросить». Пустое состояние при `q` получает текст «Ничего не найдено по
  запросу» с подсказкой сбросить поиск.
- Альтернатива «datalist/JS-поиск на клиенте» отклонена: нужен URL-стабильный
  серверный результат и работа без JS.

### D6. Сортировка рейтинга: ссылки в заголовках, состояние в URL

- Ключи: `rank` (место), `name` (casefold), `elo`, `games`, `winrate`
  (при `games=0` — в конец), `trend` (числовое значение d5, «–» — в конец
  при любом направлении). Вторичный ключ — место, порядок детерминирован.
- Дефолты направления: `rank`/`name` — `asc`, `elo`/`games`/`winrate`/
  `trend` — `desc`. Клик по колонке: та же колонка — переворот направления,
  другая — дефолт колонки. Без параметров — текущее поведение (место по ELO).
- Места/медали/d5 присваиваются до сортировки (по пулу), сортируется только
  список для вывода (`models_visible` — новая копия, `models_sorted` не
  мутируется: на нём завязаны тренды).
- `aria-sort` — на заголовке активной колонки; стрелка ▲/▼ (aria-hidden).
  Заголовки без ссылки — `±` и победы/поражения/ничьи. Колонка «Всего»
  сортируется ключом `games`; для ключа `trend` заведена отдельная колонка
  «Тренд» после «#» (индикатор d5 перенесён из ячейки места — так заголовок
  становится естественной ссылкой, спека формы не меняется).
- Сервер отдаёт в шаблон callable `sort_url(col)` и данные активной сортировки
  (как `_history_page_url` в истории) — без ручной сборки query в шаблоне.

### D7. Экспорт: роуты-чтения рядом со страницами, выборка — общий хелпер

- `GET /export/rating.csv|json` и `GET /export/history.csv|json`;
  `Content-Disposition: attachment; filename="<name>-<YYYY-MM-DD>.<ext>"`.
  CSV — `csv.writer` с `;`, `\r\n`, BOM (`\ufeff`); JSON — `ensure_ascii=False`
  с метаданными (`generated_at`, действующие фильтры, число строк).
- Чтобы экспорт не расходился со страницей, отбор строк выносится в хелперы
  (`rating_selection(...)`, `history_feed(...)`), которые используют и роуты
  страниц, и экспорт. Экспорт берёт всю отфильтрованную выборку, не страницу.
- Колонки рейтинга — как в таблице (+id, компания, агент, статус для
  машинной обработки); история — seq, matchup, task, date, recorded_at,
  id+имена сторон, winner, ELO до/после и дельты, voided/reason.
- Кнопки — ссылки с текущими параметрами (`data` не нужны): живут в шапке
  карточки «Рейтинг» и в блоке controls истории; в `read_only()` не
  рендерятся. Роуты доступны и в read_only-режиме сервера (не мешает
  тестам слепка), слепок их просто не показывает.
- Альтернатива «JS-скачивание blob» отклонена: слепок и no-JS.

### D8. Комбобокс селектов — прогрессивное улучшение `data-combobox`

- Новый `tools/static/js/combobox.js` (vanilla, без зависимостей): для
  `select[data-combobox]` строится текстовый input (role=combobox,
  `aria-expanded`, `aria-activedescendant`) и список (`role=listbox`) с
  заголовками групп `role=presentation`; нативный select прячется
  визуально, но остаётся источником значения (`name` не меняется).
- Данные вариантов: сервер добавляет `data-agent` каждому `<option>`
  (форма A/B и фильтр истории); группировка — по агенту.
- Фильтрация по подстроке (имя/id, casefold) без серверных запросов; список
  строится один раз, при вводе скрываются несовпавшие пункты и пустые группы
  (1000 пунктов — без перестройки DOM). Клавиши: ↓/↑, Enter, Esc; клик мышью;
  blur без выбора возвращает прежнее значение (произвольный текст в форму не
  попадает — спека формы запрещает значения вне списка). Изменение
  диспатчит `change` на select — работают `validate()` и
  `onchange="this.form.submit()"` истории.
- Подключение: `shell.html` для live-режима (`{% if not read_only() %}`);
  слепок остаётся на обычных select. См. `static-mirror`
  «Клиентский интерактив зеркала» — перечень фильтров слепка не меняется.
- Альтернатива «`<input list>`/datalist» (быстрый вариант ревью) отклонена:
  нет группировки и контроля выбора из справочника.

### D9. Слепок: деградация через `read_only()`, без постпроцессора

- Новые серверные элементы получают ветки `read_only()`: ссылки экспорта и
  поле поиска не рендерятся; заголовки сортировки — простой `<th>` без
  ссылки и `aria-sort`; поисковые фильтры истории, поле «страница №» и
  «в конец» не рендерятся; бейдж-ссылка таска и чип `matchup_id` — `<span>`.
- Постпроцессор `export_web.py` изменён точечно: `_HISTORY_ROW_RE` допускает
  атрибуты после `class` (якорь `id="v-<seq>"`), строка остаётся плоской;
  страницы слепка остаются валидными по «Целостности вывода» (никаких новых
  POST-форм и абсолютных ссылок).
- Альтернатива «перенести поиск/фильтры в mirror.js» отклонена: объём и
  риск для страницы-витрины, не входит в критерии волны.

### D10. Тесты и бюджеты

- `tools/test_data_cache.py` — новый блок волны 3 на tmp-фикстурах:
  фильтры истории (каждый + комбинация + счётчик «найдено»), поля строки
  (task/winner/seq/ссылки), `?v=` (попадание, аннулированная запись,
  неизвестный), сортировка и поиск рейтинга (порядок, aria-sort,
  переключение, места не пересчитываются), экспорт CSV/JSON (заголовки,
  BOM, разделитель, состав/порядок, «только чтение»), `read_only`-рендер
  (нет экспорта/поиска/сортировки/новых фильтров).
- `tools/test_export.py` — прогон слепка как есть (плюс точечная проверка,
  что live-only контролы отсутствуют, если попадёт в существующий стиль).
- `tools/test_perf.py` — бюджеты не меняются; при желании добавить замер
  экспорта 10k записей (необязательно, S-риск).
- Ручной смоук: живой сервер, обе темы, слепок на временном каталоге.

## Risks / Trade-offs

- [Регулярка слепка чувствительна к разметке строк] → строка остаётся
  плоской; якорь и бейджи — атрибуты/`<span>`; прогон `test_export.py` до и
  после.
- [Расхождение подсветки и поиска запутывает] → спека фиксирует правило
  («поиск сужает, чипы подсвечивают») и сценарий на комбинацию; счётчики
  поясняют числа.
- [Сортировка по тренду:] `trend` есть не у всех моделей → «–» всегда в
  конце; вторичный ключ место.
- [Комбобокс ломает клавиатурный сценарий формы (фокус в «Модель A» по
  загрузке)] → фокус ставится на созданный input; Enter/выбор диспатчат
  `change`, `validate()` и подсказка H2H продолжают работать; при отключённом
  JS — прежний select.
- [Экспорт больших выборок] → 10k строк CSV/JSON — десятки мс, память в
  пределах; Content-Disposition без стриминга достаточен.
- [Новые параметры теряются в чьих-то ссылках] → `history_params` —
  единственное место сборки ссылок; тест на сохранение набора параметров.
- [Слепок «поиск» не имеет] → осознанная деградация, зафиксирована в спеках
  сценариями «Слепок без…».

## Migration Plan

Миграций нет: данные, журнал и формат `index.json` не меняются; все новые
роуты — GET-чтение. Порядок работ: серверные хелперы и роуты → шаблоны и
CSS → `combobox.js` → проверки слепка → тесты → `docs/ui-ux-review.md` и
`CHANGELOG.md` (секция `[Unreleased]`); релиз — отдельным шагом по решению
координатора.

## Open Questions

Нет: деферрируемых неизвестных нет, спорные варианты (бесконечное
долистывание, клиентский поиск в слепке, отдельная страница вердикта)
отклонены осознанно и могут вернуться отдельными изменениями.
