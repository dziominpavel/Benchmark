# leaderboard-ui Specification

## MODIFIED Requirements

### Requirement: Главная страница (layout)

Главная страница leaderboard SHALL использовать единый `.page` контейнер:
`width: 100%`, `max-width: 1400px`, `margin: 0 auto`, горизонтальный padding
24–32px. Контент НЕ SHALL прижиматься к левому краю; на широких мониторах
контейнер должен использовать значительно больше горизонтального пространства,
оставаясь центрированным.

Внутри контейнера SHALL находиться `header`, `.controls` и `.content-grid`.
Header SHALL содержать заголовок слева и кнопку «+ Добавить модель» справа.
Controls SHALL содержать строку статистики и фильтр «Показывать`, выровненные
относительно основного content-зазора.

`.content-grid` SHALL использовать CSS Grid:
`grid-template-columns: minmax(0, 1fr) 320px;`, `gap: 24px;`,
`align-items: stretch;`. При доступной ширине около 1400px основная колонка
SHOULD занимать примерно 1000px, sidebar — около 320px. Sidebar SHALL состоять
из двух карточек, расположенных вертикально с gap 16px, и выравниваться по
высоте с карточкой рейтинга. Основная колонка SHALL содержать `.rating-card` и
`.history-card`.

#### Scenario: Страница на широком мониторе

- **WHEN** viewport шириной примерно 1920px или 2560px
- **THEN** контейнер занимает до 1400px и центрирован
- **AND** по бокам остаётся небольшое поле, а не огромная пустота

#### Scenario: Узкий экран

- **WHEN** viewport менее примерно 900px
- **THEN** grid переключается в одну колонку
- **AND** таблица рейтинга идёт первой, панель добавления результата — под ней

### Requirement: Таблица рейтинга

Таблица рейтинга SHALL занимать 100% ширины основной колонки (`width: 100%`,
`min-width: 0`). Если содержимое таблицы превышает доступную ширину, горизонтальная
полоса прокрутки SHALL появляться внутри `.table-wrap`, а не ломать ширину страницы.
Колонки SHOULD распределяться пропорционально пространству. Названия моделей
SHALL NOT чрезмерно сжимать остальные колонки.

#### Scenario: Адаптивная таблица

- **WHEN** ширина основной колонки меняется
- **THEN** таблица остаётся внутри своей колонки
- **AND** при overflow появляется скролл внутри `.table-wrap`

#### Scenario: Отображение рейтинга

- **WHEN** пользователь открывает страницу сервера
- **THEN** видит таблицу всех моделей из `index.json` по убыванию ELO
- **AND** ELO отображается как обычное число без цветного фона, бейджа или цветной подсветки
- **AND** таблица занимает всю ширину основной колонки

#### Scenario: Нет моделей

- **WHEN** в реестре нет моделей
- **THEN** таблица заменяется пустым состоянием «Нет моделей. Нажмите «+ Добавить модель»…»

#### Scenario: Меньше двух моделей для вердикта

- **WHEN** моделей меньше 2
- **THEN** форма вердикта заменяется состоянием «Нужно минимум 2 модели…»

### Requirement: История ELO

История `elo_history` SHALL показываться в сворачиваемом блоке внизу основной
колонки, под таблицей рейтинга. Ширина блока истории SHALL быть равна ширине
карточки рейтинга. По умолчанию блок SHALL быть свёрнут. Раскрытие SHALL
происходить по клику на заголовок блока. Внутри SHALL отображаться не более
20 записей на одну страницу (новые сверху). Навигация SHALL осуществляться
номерами страниц. Каждая строка SHALL содержать имена обеих моделей, ELO до и
после вердикта для обеих моделей, дельты (+N зелёным / −N красным / ±0 серым),
дату и `recorded_at`. Запись SHALL соответствовать одному вердикту, а не одной
стороне.

#### Scenario: История свёрнута по умолчанию

- **WHEN** пользователь открывает главную страницу
- **THEN** блок «История» свёрнут
- **AND** записи не видны

#### Scenario: Раскрытие и пагинация

- **WHEN** пользователь кликает заголовок «История»
- **THEN** блок раскрывается и показывает первые 20 записей
- **AND** при наличии более 20 записей видны номера страниц
- **AND** клик по номеру страницы показывает соответствующие 20 записей

#### Scenario: История после вердикта

- **WHEN** записан вердикт A > B
- **THEN** в истории одна строка:
  - `A vs B  1200 → 1220 (+20)  1200 → 1180 (−20)  2026-09-05 19:32`
- **AND** не создаётся отдельная строка `B vs A`

#### Scenario: Ручная запись через UI

- **WHEN** пользователь ввёл вердикт через веб-форму
- **THEN** в истории появляется одна строка с реальными id модели и соперника
- **AND** для обеих сторон видны ELO до, ELO после и дельта
- **AND** строка содержит `recorded_at`
