# Design

## Context

Текущее состояние (файл `tools/static/css/console.css`, рабочее дерево):

| Правило | Строки | Значение |
|---|---|---|
| `tr.filter-miss td` | 687 | 0.55 |
| `tr.filter-miss:hover td` | 688 | 0.85 |
| `tr.archived.filter-hit td` | 689 | 0.8 |
| `tr.archived.filter-miss td` | 690 | 0.45 |
| `tr.archived.filter-miss:hover td` | 691 | 0.75 |
| `tr.archived td` | 679 | 0.6 |
| `.history-item.filter-miss` / `:hover` | 1039–1040 | 0.55 / 0.85 |
| `rect.dist-pt.filter-miss` (бары `/stats`) | 1472 | 0.5 |
| `--caption-opacity` (тёмная / светлая) | 26 / 107 | 0.75 / 0.90 |

Значения заданы литералами в четырёх местах; общего токена нет.

Классы `filter-hit` / `filter-miss` навешиваются сервером:

- главная — `tools/server.py:1717`: guard `{% if filter_view == 'highlight' and highlight_hits %}`;
- `/add` — `tools/server.py:2590`: `{% if filter_view == 'highlight' and highlight_hits %}`;
- `/settings` (матрица ответов) — `tools/server.py:2971`: тот же guard;
- история — `tools/templates/_history_results.html:18`: guard по `history_hits`;
- бары `/stats` — `tools/render_helpers.py:583,615`: guard `any_hits` (если отобранных нет, классы не навешиваются вовсе).

То есть правило «приглушать только при наличии отобранных строк» на всех
страницах уже реализовано одинаково; это change закрепляет его тестом и
фиксирует степень приглушения числом.

Ограничения и контекст проекта:

- значения непрозрачности в этой консоли — литералы в CSS; общий токен
  непрозрачности уже есть только у подписей (`--caption-opacity`, 0.75/0.90);
- страницы консоли делят один `console.css`; активные changes
  `filter-settings-trigger` (10/11 задач) и `live-search` (0/24 задач) правят
  тот же файл — правки накладываются поверх, не переписывая чужие блоки;
- `console-shell` требует контраста ≥ 4.5:1 для текста, а требование о подписи
  «Компания · Агент» — непрозрачности не ниже 0.75/0.90; при приглушённой
  строке эти пороги не выполняются (см. «Подпись» в решениях);
- changelog: пользовательский пункт в `[Unreleased]`, строка ≤ 140 символов и
  без обратных кавычек; детали — под `###` того же раздела.

## Goals / Non-Goals

**Goals:**

- Неотобранные строки приглушены до 0.30 в обеих темах; архивные неотобранные —
  до 0.25; приглушение при наведении — 0.85.
- Значение приглушения задаётся один раз (токеном), а не литералом в
  четырёх правилах, и одинаково для тёмной и светлой темы.
- Приглушение применяется только когда есть отобранные строки — на всех
  страницах одинаково, как в спецификации.
- Правила приглушения читаются как одно место в файле, а не как разбросанные
  литералы.

**Non-Goals:**

- Не меняются: правила отбора, состав блока «Фильтр», URL-параметры
  (`view`/`chips`), счётчики, экспорт, статический слепок.
- Не меняется приглушение баров на `/stats` (0.5) — это график, а не строки
  списка, и у него своя шкала.
- Не меняется токен `--caption-opacity` и правила подписи вне приглушённых
  строк.
- Не меняется подсветка отобранных строк (акцентный фон 12% и полоса слева) и
  медали топ-3.
- Не вводится пользовательская настройка степени приглушения — это не
  настройка отображения, а фиксированное оформление режима.

## Decisions

### 1. Степень приглушения — токен, одно значение для обеих тем

`--filter-miss-opacity: 0.30` объявляется в базовом блоке `:root,
[data-theme="dark"]` рядом с `--caption-opacity`; светлая тема наследует
значение, потому что `:root` — тот же элемент, что и `[data-theme="light"]`,
и светлая тема не переопределяет этот токен.

Альтернативы: (а) два токена с разными значениями по темам (0.30 тёмная,
0.35 светлая) — отклонено: пользователь выбрал одно значение для обеих тем,
а разница в 0.05 не даёт видимого выигрыша; (б) литерал 0.30 в каждом из
четырёх правил — отклонено: расхождение значений при правке; (в) `calc()` от
одного токена — отклонено: значение перестаёт читаться прямо в CSS.

### 2. Архивные неотобранные — отдельный токен 0.25

`--filter-miss-archived-opacity: 0.25`. Сегодня архивные неотобранные темнее
обычных на 0.10 (0.45 против 0.55); при новом базовом значении такой разрыв
(0.20) растворял бы строку, поэтому разрыв уменьшен до 0.05.

Альтернативы: (а) `calc(var(--filter-miss-opacity) - 0.05)` — отклонено по
той же причине, что и в п. 1; (б) не различать архивные (0.30) — отклонено:
архивная строка должна оставаться узнаваемо более тусклой, это несёт
собственный смысл; (в) оставить 0.45 — отклонено: архивные строки тогда
окажутся ярче обычных неотобранных, что переворачивает смысл приглушения.

### 3. При наведении — 0.85 для всех приглушённых строк

`tr.filter-miss:hover td` и `tr.archived.filter-miss:hover td` получают одно
значение 0.85; сегодня у архивных оно 0.75. Требование спецификации
«при наведении приглушение SHALL ослабляться» выполняется с запасом, а
значение не расходится между двумя правилами.

### 4. Приглушение — только при наличии отобранных строк

Guard `and highlight_hits` на строках таблицы рейтинга главной уже стоит в
коде (и в HEAD, и в рабочем дереве) — так же, как на `/add`
(`server.py:2592`), в `/settings` (`server.py:2973`), в истории
(`_history_results.html:18`) и в графике `/stats` (`render_helpers.py:615`).
Change не меняет это правило, а закрепляет его тестом и делает явным в
спецификации.

Побочный эффект правила: при пустом отборе таблица главной выглядит как
обычная (никакого приглушения) и показывает подсказку «Ничего не подсвечено»
(`server.py:1741`) — ровно как требует сценарий спецификации.

Альтернатива: оставить главную как есть — отклонено: это расхождение кода со
спецификацией, и именно оно даёт самую тяжёлую картину (вся таблица
приглушена при 0.30).

### 4а. Рендер строк главной (следствие незавершённого `live-search`)

Шаблон главной итерировал `rating_rows` — переменную, которой нет в контексте
роута (следствие незавершённого change `live-search`). Jinja отдаёт пустой
список, таблица рейтинга рендерилась без строк, и существовавший тест
`test_wave3_rating_search_sort` падал. Заменено на `models_pool` — тот же
отсортированный пул, из которого несовпавшие с поиском строки помечаются
`hidden` (по замыслу `live-search`).

Альтернативы: (а) добавить в контекст отдельную переменную `rating_rows` —
отклонено: дублирующий ключ контекста может конфликтовать с правкой
незавершённого change; (б) оставить как есть — отклонено: главная остаётся
пустой, и ни это change, ни его проверка не работают.

### 5. Подпись «Компания · Агент» в приглушённой строке — отдельного правила нет

Подпись наследует непрозрачность строки: эффективное значение ≈ 0.23–0.27
(контраст ≈ 1.5:1 в обеих темах) — визуально подпись в приглушённой строке не
читается. Разметка, токен `--caption-opacity` и высота строк не меняются;
в спецификации фиксируется исключение из порога 4.5:1 для приглушённых строк.

Альтернативы: (а) `display: none` для подписи в приглушённых строках —
отклонено: у приглушённых и отобранных строк станут разные высоты, таблица
станет рваной; (б) компенсирующая непрозрачность подписи внутри приглушённой
строки — отклонено: требование подписи требует единого значения непрозрачности
для всех мест вывода внутри темы, а компенсация это нарушает и возвращает
подписи читаемость, ради которой приглушение и делалось.

### 6. Бары `/stats` не трогаем

`rect.dist-pt.filter-miss` остаётся 0.5. Бары — другой носитель (график), у
них своя шкала приглушения; менять их вместе со строками пользователь не
просил.

### 7. Порядок правил в CSS сохраняется

Блок приглушения (`:687-691`) идёт ниже `tr.top-1..3` и `tr.archived` — так
приглушение перекрывает фон медалей. Новые правила дописываются в этот же
блок, без переупорядочивания соседних блоков.

### 8. Пересечение с активными changes

`console.css` правят `filter-settings-trigger` (стили раскрывашки настроек,
`console.css:1506+`) и `live-search` (индикатор загрузки и состояния
скрытых строк). Правки этого change попадают в другие участки файла (строки
рейтинга, лента истории) — конфликтов по тексту нет; при совпадении
выигрывают правки, уже сделанные в рабочем дереве, ничего не переформатируется
и не откатывается.

## Risks / Trade-offs

- [Приглушённый текст плохо читается] → по требованию пользователя; компенсация
  — наведение (0.85) и отсутствие приглушения, когда отбор пуст.
- [Подпись в приглушённой строке не читается (≈1.5:1)] → осознанное следствие
  значения 0.30; зафиксировано исключением в спецификации; высота строк и
  разметка не меняются.
- [Светлая тема: 0.30 даёт 1.93:1 по основному тексту] → принято по итогам
  визуальной оценки; при желании значение повышается одной правкой токена.
- [Правка главной меняет вид страницы при пустом отборе] → это приведение к
  спецификации, а не новое поведение; проверяется тестом.
- [Общий файл `console.css` с двумя активными changes] → правки накладываются
  поверх, чужие блоки не трогаются.
- [Числа в спецификации могут разойтись с CSS] → тест разбирает `console.css`
  и сверяет значения токенов со значениями из delta-спеки.

## Migration Plan

Данные не мигрируются, формат `index.json` и журнала не меняется, версия не
поднимается. Порядок: правки `console.css` и `server.py` → тесты → пункт в
`CHANGELOG.md` → `openspec validate --all` и `python scripts/check-version.py`.
Откат — revert коммита: единственное состояние — значения CSS и один булев
guard в шаблоне; слепок витрины пересобирается штатным экспортом, старые
сборки продолжают работать со старым приглушением.
