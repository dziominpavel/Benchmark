## Context

См. `proposal.md` (Why). Текущее состояние: `get_answer_matrix` (`tools/elo.py`) сортирует строки `(-debt, name.lower())`; `settings_page` (`tools/server.py`) делит строки на `answer_rows` (активные) и `answer_archived_rows` (архивные в `<details>`); главная (`leaderboard()`) фильтрует таблицу через GET-параметр `filter=active/all/inactive` (по умолчанию `active`). Паттерн главной — образец для унификации. Формат `data/answer_flags.yaml` не меняется.

## Goals / Non-Goals

**Goals:**
- Единый порядок строк по алфавиту во всех режимах фильтра.
- Серверный фильтр строк по статусу модели с состоянием в URL.
- Сохранение без потерь для строк, скрытых фильтром.

**Non-Goals:**
- Не меняем столбцы (только активные таски), сводку `filled/total` (считается только по активным), плашку «Модели», главную страницу, формат `answer_flags.yaml`.
- Не вводим клиентский фильтр вместо серверного; JS «только долги» остаётся как есть.

## Decisions

### 1. Сортировка — в `get_answer_matrix`

Порядок меняется с `(-debt, name.lower())` на `(name.lower())` в одном месте — источнике порядка для роута и сводки. Альтернатива «сортировать в роуте» отвергнута: два источника порядка рассинхронизируются, а матрица используется и сводкой долгов.

### 2. Фильтр — серверный GET-параметр `answer_filter`

`settings_page` читает `request.args.get("answer_filter", "active")`, валидирует (`active` / `all` / `inactive`, иначе `active`) и передаёт отфильтрованные строки + текущее значение в `SETTINGS_TEMPLATE`. Селект — `<form method="GET">` с `onchange="submit()"`, как `.filter-bar` на главной; редиректы после POST (`/answer_flags`, toggle тасков) сохраняют `answer_filter` в query. Альтернатива «клиентский JS-фильтр» отвергнута: не «как на домашней», состояние не живёт в URL и не переживает перезагрузку.

### 3. Единый список вместо details-таблицы архивных

Архивные строки рендерятся в общем `tbody` с пилюлей `неактивна` (класс `archived`, как строки таблицы рейтинга); отдельная таблица в `<details>` убирается. Пустые результаты фильтра получают пустые состояния («Нет активных моделей для учёта» / «Нет неактивных моделей для учёта»). Альтернатива «оставить details + добавить фильтр» отвергнута: два параллельных механизма показа архивных запутают (фильтр «Все» + свернутый details дублируют друг друга).

### 4. Сохранение скрытых строк — fallback на existing

`save_answer_flags_route` для моделей вне текущего фильтра (и для всех моделей вне активных тасков — как сейчас) берёт значение из `load_answer_flags()`, а не из `submitted`. Альтернатива «hidden inputs для скрытых» отвергнута: раздувает форму и рискует рассинхроном при параллельных правках.

### 5. JS bulk-действия без изменений

`onlyDebts`, `flagsCounter`, `rowToggle`, `colSet` уже работают через `tr.style.display` и `closest('tr')` — серверная фильтрация только уменьшает число строк в DOM, логика не меняется. Счётчик «показано N из M» считается по отфильтрованному набору (M = строк в фильтре), что и ожидается.

## Risks / Trade-offs

- [Потеря флагов скрытых моделей при сохранении] → fallback на `existing` для всех моделей вне фильтра + ручная проверка: выставить флаг архивной, сохранить в режиме `active`, переоткрыть в `all`.
- [Невалидный `answer_filter` в URL] → строгая валидация с fallback `active`, как `filter_mode` на главной.
- [Должников больше не видно сверху] → колонка «Долг» + «только долги» остаются; trade-off принят в пользу находимости по алфавиту (см. proposal).
- [Сводка `закрыто X из Y` считается только по активным] → без изменений; в режимах `all`/`inactive` сводка может не совпадать с видимыми строками — подпись остаётся «ответы: закрыто…», как сейчас для архивных.

## Migration Plan

Миграции данных нет. Деплой — обычный рестарт `tools/server.py`. Откат — откат трёх файлов (`tools/server.py`, `tools/elo.py`, спеки) без конвертации данных.
