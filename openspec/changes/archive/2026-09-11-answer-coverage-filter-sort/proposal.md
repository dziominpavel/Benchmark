## Why

Окно «Наличие ответов» на `/settings` ведёт себя иначе, чем главная: строки отсортированы «должники сверху», а фильтра по статусу моделей нет — активные и архивные показаны в разных таблицах (основная + свернутая details-секция). При росте реестра модель сложно найти глазами, поведение непоследовательно с фильтром «Показывать» на главной.

## What Changes

- Строки матрицы «Наличие ответов» сортируются по алфавиту (имя модели, case-insensitive), а не «сначала должники».
- В окно добавляется фильтр «Показывать»: «Только активные» (по умолчанию) / «Все» / «Только неактивные» — как фильтр таблицы рейтинга на главной.
- Фильтр применяется только к строкам (моделям); столбцы остаются только активными тасками, неактивные таски по-прежнему скрыты с hint и сохранением флагов.
- Архивные модели в режимах «Все» / «Только неактивные» показываются в общем списке с пилюлей «неактивна» (как на главной); отдельная details-таблица архивных убирается.
- Сохранение матрицы не теряет флаги скрытых фильтром моделей (по образцу сохранения флагов неактивных тасков).
- Колонка «Долг», чекбокс «только долги» и счётчик «показано N из M» сохраняются без изменений.

### Modified Capabilities

- `answer-coverage`: меняется сортировка строк матрицы по умолчанию (алфавит вместо должников сверху) и добавляется фильтр строк по статусу модели (активные / все / неактивные, по умолчанию активные) с сохранением скрытых флагов.
- `leaderboard-ui`: меняется секция «Наличие ответов» на странице `/settings` (фильтр «Показывать», единый список вместо details-таблицы архивных, параметр URL).

## Impact

- `tools/server.py`: `settings_page` (чтение `answer_filter` из query, фильтрация строк, передача в шаблон), `SETTINGS_TEMPLATE` (селект фильтра, единый список, сохранение `answer_filter` при пагинации/сохранении), `save_answer_flags_route` (сохранение флагов моделей, скрытых фильтром, как было).
- `tools/elo.py`: `get_answer_matrix` (сортировка строк по имени; возможно возврат несмешанного порядка для фильтрации в роуте).
- Спеки: `openspec/specs/answer-coverage/spec.md`, `openspec/specs/leaderboard-ui/spec.md` (дельты в этом change).
- Обратная совместимость: формат `data/answer_flags.yaml` не меняется; URL без параметра ведёт себя как «Только активные» (текущее поведение по умолчанию для видимых строк).
