# Spec Delta

## ADDED Requirements

### Requirement: Живой поиск по таблице рейтинга

Поле `q` на главной SHALL применять поиск по имени и id при каждом изменении
значения, без отправки формы и перезагрузки страницы. Поиск SHALL выполняться
по всем строкам текущего пула фильтров, а не только по изначально видимым;
очистка поля SHALL возвращать все строки пула. Серверный `q` SHALL сохраняться
для прямых ссылок и работы без JavaScript.

#### Scenario: Фильтрация на каждый символ

- **WHEN** пользователь вводит `gem` в поле поиска на главной
- **THEN** строки без совпадения по имени или id скрываются без Enter и перезагрузки
- **AND** строки с совпадением остаются видимыми

#### Scenario: Очистка возвращает строки

- **WHEN** пользователь очищает поле поиска, ранее содержавшее запрос
- **THEN** все строки текущего пула фильтров снова становятся видимыми

#### Scenario: Пустой результат

- **WHEN** живой поиск не совпадает ни с одной моделью
- **THEN** таблица заменяется пустым состоянием с подсказкой сбросить поиск

#### Scenario: Начальное состояние из ссылки

- **WHEN** пользователь открывает `/?q=gem`
- **THEN** поле заполнено, а таблица показывает только совпадения
- **AND** пул для последующей живой фильтрации содержит все строки фильтров

#### Scenario: Поиск в режиме подсветки

- **WHEN** включён режим «Подсвечивать» и пользователь вводит запрос
- **THEN** состав строк сужается по поиску
- **AND** среди оставшихся сохраняется разметка подсветки hit/miss

#### Scenario: Работа без JavaScript

- **WHEN** JavaScript отключён и пользователь отправляет форму поиска
- **THEN** серверный поиск применяется по Enter или кнопке отправки
- **AND** результат доступен по прямой ссылке с `q`

### Requirement: Счётчики главной при живом поиске

Счётчик «Моделей» и счётчик «подсвечено» на главной SHALL обновляться при
каждом изменении `q` без перезагрузки и SHALL соответствовать числу видимых
строк. При нулевом результате счётчик SHALL показывать 0, а таблица SHALL
заменяться пустым состоянием с подсказкой сбросить поиск.

#### Scenario: Счётчик после фильтрации

- **WHEN** поиск оставляет 2 строки из 100
- **THEN** счётчик показывает «Моделей: 2 из 100»

#### Scenario: Счётчик подсветки

- **WHEN** в режиме «Подсвечивать» поиск оставляет 2 строки, из которых одна отобрана чипами
- **THEN** счётчик показывает «Моделей: 2 · подсвечено 1»

#### Scenario: Нулевой результат

- **WHEN** поиск не оставляет ни одной строки
- **THEN** счётчик показывает 0
- **AND** отображается пустое состояние

#### Scenario: Очистка восстанавливает счётчик

- **WHEN** пользователь очищает поле поиска
- **THEN** счётчики снова соответствуют полному текущему пулу

### Requirement: Ссылки главной при живом поиске

URL главной, ссылки сортировки, ссылки экспорта и ссылка «Сбросить» SHALL
синхронизироваться с текущим `q` без перезагрузки. Непустой запрос SHALL
сохраняться в них вместе с прочими параметрами; пустой SHALL удалять `q`, а
«Сбросить» SHALL скрываться, если других активных фильтров нет.

#### Scenario: Ввод обновляет ссылки

- **WHEN** пользователь вводит `alpha`
- **THEN** URL содержит `q=alpha`
- **AND** ссылки сортировки и экспорта содержат `q=alpha`
- **AND** ссылка «Сбросить» видима

#### Scenario: Очистка без других фильтров

- **WHEN** пользователь очищает поле поиска, а других активных фильтров нет
- **THEN** `q` исчезает из URL, ссылок сортировки и экспорта
- **AND** ссылка «Сбросить» скрывается

#### Scenario: Очистка при активном фильтре

- **WHEN** пользователь очищает поле поиска, но активен другой фильтр
- **THEN** `q` исчезает из URL и ссылок
- **AND** ссылка «Сбросить» остаётся видимой

#### Scenario: Сортировка сохраняет запрос

- **WHEN** активна сортировка по ELO и пользователь вводит запрос
- **THEN** ссылки сортировки сохраняют и `q`, и текущие `sort`/`dir`

### Requirement: Живой поиск в истории ELO

Поле `pair` на `/history` SHALL применять поиск при каждом изменении значения
с задержкой 150–250 мс после последнего ввода, без перезагрузки страницы.
Смена запроса SHALL сбрасывать страницу на первую, а устаревшие ответы MUST NOT
заменять результаты более нового запроса. Серверная семантика `pair`
(подстрока или точная пара) SHALL сохраняться.

#### Scenario: Поиск после паузы

- **WHEN** пользователь вводит `gemini` в поле «Пара»
- **THEN** после паузы 150–250 мс показываются только совпавшие записи
- **AND** URL содержит `pair=gemini`
- **AND** страница не перезагружается

#### Scenario: Устаревший ответ не применяется

- **WHEN** пользователь продолжает вводить запрос до завершения предыдущего поиска
- **THEN** ответ на устаревший запрос не заменяет результаты последнего запроса

#### Scenario: Смена запроса сбрасывает страницу

- **WHEN** пользователь находится на странице 3 и меняет запрос
- **THEN** результаты показываются с первой страницы
- **AND** `page` отсутствует в URL

#### Scenario: Точная пара

- **WHEN** в поле введено `alpha:beta`, где оба id есть в реестре
- **THEN** показываются только записи встреч Alpha и Beta

#### Scenario: Очистка возвращает всю ленту

- **WHEN** пользователь очищает поле «Пара»
- **THEN** показывается вся лента с первой страницы
- **AND** `pair` исчезает из URL

#### Scenario: Работа без JavaScript

- **WHEN** JavaScript отключён и пользователь отправляет форму истории
- **THEN** серверный поиск по `pair` применяется по Enter или отправке формы

### Requirement: Синхронизация истории при живом поиске

Каждый живой поиск истории SHALL обновлять счётчик «найдено», пустое
состояние, пагинацию, заголовок вкладки и ссылки экспорта в соответствии с
новой выборкой. `page` SHALL сбрасываться, а прочие фильтры и настройки
отображения SHALL сохраняться.

#### Scenario: Обновление выборки

- **WHEN** живой поиск оставил M записей
- **THEN** счётчик показывает «найдено: M»
- **AND** заголовок вкладки содержит число M в правильной форме слова
- **AND** ссылки экспорта содержат текущий `pair`
- **AND** пагинация начинается с первой страницы

#### Scenario: Нулевая выборка

- **WHEN** живой поиск не оставил ни одной записи
- **THEN** отображается пустое состояние
- **AND** заголовок вкладки содержит «0 записей»

#### Scenario: Очистка восстанавливает выборку

- **WHEN** пользователь очищает поле «Пара»
- **THEN** счётчик и заголовок соответствуют полной ленте
- **AND** ссылки экспорта больше не содержат `pair`

### Requirement: Ошибка живого поиска истории

Если запрос живого поиска истории завершился ошибкой, страница SHALL сохранить
предыдущие строки и показать доступное сообщение об ошибке. Следующий ввод
SHALL повторять запрос.

#### Scenario: Ошибка запроса

- **WHEN** запрос живого поиска истории завершился ошибкой
- **THEN** предыдущие строки остаются на странице
- **AND** сообщение об ошибке доступно вспомогательным технологиям
- **AND** страница не перезагружается

#### Scenario: Повтор после ошибки

- **WHEN** после ошибки пользователь снова меняет запрос
- **THEN** выполняется новый запрос и результаты обновляются

### Requirement: Живой поиск «Личных встреч»

Поле `h2h_q` SHALL фильтровать строки «Личных встреч» при каждом изменении
значения без отправки формы и перезагрузки. Пустое значение SHALL возвращать
все строки; поиск SHALL комбинироваться с сортировкой, а её ссылки SHALL
сохранять текущий запрос. URL SHALL содержать `h2h_q` и параметры сортировки.

#### Scenario: Фильтрация соперников

- **WHEN** пользователь вводит `BETA` в поле поиска соперника
- **THEN** остаётся только строка Beta без перезагрузки
- **AND** URL содержит `h2h_q=BETA`

#### Scenario: Очистка возвращает соперников

- **WHEN** пользователь очищает поле поиска соперника
- **THEN** все строки «Личных встреч» снова видимы
- **AND** `h2h_q` исчезает из URL

#### Scenario: Сортировка после поиска

- **WHEN** пользователь вводит запрос и нажимает заголовок «Винрейт»
- **THEN** сортируются только оставшиеся строки
- **AND** ссылки сортировки сохраняют текущий `h2h_q`

#### Scenario: Пустой результат

- **WHEN** поиск не находит соперников
- **THEN** отображается пустое состояние со ссылкой сбросить поиск

#### Scenario: Работа без JavaScript

- **WHEN** JavaScript отключён и пользователь отправляет форму «Личных встреч»
- **THEN** серверный поиск применяется по Enter или кнопке «Найти»

### Requirement: Доступность и деградация живого поиска

Живой поиск SHALL сохранять фокус в поле ввода, не перезагружать страницу и
сообщать число результатов через `aria-live="polite"`. При отключённом
JavaScript поиск SHALL применяться отправкой GET-формы; в статическом слепке
поисковые поля и скрипт живого поиска MUST NOT отображаться.

#### Scenario: Фокус и озвучивание

- **WHEN** результаты живого поиска обновляются
- **THEN** фокус остаётся в поле ввода
- **AND** число результатов озвучивается через область `aria-live="polite"`

#### Scenario: Без JavaScript

- **WHEN** JavaScript отключён
- **THEN** поиск применяется отправкой GET-формы
- **AND** результат доступен по URL с параметром поиска

#### Scenario: Статический слепок

- **WHEN** открыта демонстрационная копия консоли
- **THEN** поисковые поля не показываются
- **AND** скрипт живого поиска не подключается
