# Design

## Context

См. `proposal.md` — Why. Текущее состояние (после архивной доработки `filter-display-settings`):

- Роут `/stats` (`tools/server.py:1730`) собирает пул `entries` по режиму фильтра и передаёт в билдер `build_elo_distribution_svg(entries, width, highlight)` (`tools/render_helpers.py:336`); в режиме «Подсвечивать» каждая запись несёт признак `hit`.
- Раскраска сегодня — два класса: `.dist-pt-below { fill: var(--neg); }`, `.dist-pt-above { fill: var(--pos); }` (`tools/static/css/console.css:1194–1195`); подсветка — `rect.filter-hit` (акцентный контур) и `rect.filter-miss` (приглушение) (`:1197–1198`).
- Темы — `:root, [data-theme="dark"]` (`console.css:9`) и `[data-theme="light"]` (`:86`), переключение клиентское; палитра живёт в токенах (capability `console-shell`), SVG рендерится один раз на сервере.
- Реальный пул сейчас: 33 активные модели, 895…1520, среднее 1199 — почти совпадает с фиксированными анкерами ±300, поэтому «по пулу» и «абсолютная шкала» на полном пуле визуально почти не отличаются; разница видна под фильтрами и на будущих данных.
- Варианты проверены на scratch-превью (`.devin/cache/stats-gradient-preview`, вне репозитория): V0 бинарная, V1 абсолютные анкеры 900/1050/1200/1350/1500 с клипом, V2 растяжка по пулу; синтетическая модель 2500 показала мёртвую зону V1; под фильтром «Google» (1171/1279) видно перекрашивание V2.

## Goals / Non-Goals

**Goals:**

- Непрерывная, монотонная по рейтингу раскраска: ни ступеньки на 1200, ни мёртвых зон за границами.
- Цвет — функция Elo и пула, а не серверный hex: обе темы и клиентское переключение сохраняются без JS.
- Подсветка (`filter-hit`/`filter-miss`) и вся серверная логика пулов и сводок не меняются.

**Non-Goals:**

- Не трогаем данные, формулу ELO, `index.json`, состав пулов, сводки, подписи, линии 1200/среднего, пустое состояние.
- Не добавляем настройки палитры (число цветов, пороги) — это дизайн-решение, а не опция интерфейса.
- Никакого клиентского JS и inline-hex в SVG.

## Decisions

### 1. Шкала — «по пулу» с пивотом 1200 (V2)

Анкеры — пары «значение + номер опоры палитры», собираются из двух половин:

- тёплая (если `min < 1200`): `[(min, s0), ((min + 1200) / 2, s1), (1200, s2)]`;
- холодная (если `max > 1200`): `[(1200, s2), ((1200 + max) / 2, s3), (max, s4)]`.

Доли внутри сегмента — линейные по Elo. Альтернатива V1 (абсолютные анкеры 900/1050/1200/1350/1500 с клипом за краями) отвергнута: за границами всё сливается в один цвет (на синтетике 1520 и 2500 неразличимы), и анкеры пришлось бы перенастраивать руками при дрейфе рейтингов. Пул сам лежит вокруг стартового 1200, поэтому растяжка по min/max не ломает привычную картину.

Trade-off V2: одна экстремальная модель сжимает существующий диапазон к жёлтой зоне (на синтетике верхушка 1200–1520 уехала в жёлто-зелёное). На текущих объёмах (десятки моделей) это терпимо; при реальных выбросах растяжку можно ограничить (кламп/перцентили) без смены схемы.

Вырожденные пулы: `min == max` — как в текущем билдере, расширение ±10; пул целиком выше/равно 1200 — тёплая половина не добавляется (нет красного); целиком ниже — нет холодной (нет зелёного). На стыке сегментов цвет непрерывен: доля 1 слева равна доле 0 справа, `1200` — всегда жёлтый `s2`.

### 2. Раскраска — `color-mix` в oklab поверх токенов темы

Пара опор и доля считаются в Python на рендере и передаются на бар двумя inline-переменными:

```
<rect class="dist-pt" style="--a:var(--dist-s2);--b:var(--dist-s3);--p:41.7%">
```

CSS:

```
.dist-pt { fill: var(--dist-s2);
           fill: color-mix(in oklab, var(--b) var(--p), var(--a)); }
```

Порядок аргументов принципиален: процент — это доля **первого** цвета, поэтому первым идёт `--b` (0% даёт `--a` — левую опору сегмента, 100% — `--b`). Перестановка даёт инверсию внутри каждого сегмента («пила»: к концу сегмента цвет возвращается к началу) — этот дефект ловился на превью.

Почему не серверный hex: тема переключается на клиенте, SVG рендерится один раз — hex заморозил бы одну тему. Почему не клиентский JS: в консоли нет JS-слоя цвета, а CSS уже умеет смешивание.

### 3. Палитра — пять токенов в обеих темах

`--dist-s0…--dist-s4` в блоках `:root, [data-theme="dark"]` и `[data-theme="light"]`, в секции «графики» рядом с `--chart-*`:

| Опора | s0 (мин) | s1 | s2 (1200) | s3 | s4 (макс) |
|---|---|---|---|---|---|
| dark | `#dc2626` | `#f97316` | `#fbbf24` | `#4ade80` | `#16a34a` |
| light | `#b91c1c` | `#ea580c` | `#ca8a04` | `#16a34a` | `#166534` |

Тёплая половина — от тёмно-красного к янтарному, холодная — от салатового к зелёному; тёмная тема светлее по краскам, светлая — глубже. Существующие `--neg`/`--pos` остаются: они используются топ-3, дельтами истории, прогрессом и другими правилами.

### 4. Код билдера

- Чистые хелперы: `build_elo_scale(elos)` → список пар `(elo, stop_index)` с вырожденными случаями; `scale_segment(elo, anchors)` → `(index, fraction)`.
- В `build_elo_distribution_svg()` бар получает класс `dist-pt` (плюс `filter-hit`/`filter-miss` в подсветке) и inline `--a`/`--b`/`--p`; подписи, линии, легенда, сводка не меняются.
- Классы `dist-pt-below`/`dist-pt-above` удаляются; селекторы подсветки обновляются на `rect.dist-pt.filter-hit` / `rect.dist-pt.filter-miss`.

### 5. Взаимодействие с режимами страницы

- «Скрывать лишние»: пул = отфильтрованные модели → анкеры по нему.
- «Подсвечивать»: пул = все показанные модели → анкеры по нему; контур (`stroke`) и приглушение (`opacity`) не конфликтуют с `fill` и работают поверх градиента.

## Risks / Trade-offs

- [Инверсия направления смешивания (`color-mix`)] → порядок аргументов зафиксирован дизайном; проверка программная: оттенок бара монотонно растёт по Elo (методика отработана на scratch-превью, снимались computed-цвета в headless-браузере).
- [Экстремальный выброс сжимает середину шкалы] → осознанный компромисс V2; при появлении реальных выбросов добавляется ограничитель растяжки, схема не меняется.
- [Вырожденные пулы (всё выше/ниже 1200)] → используется одна половина шкалы; сценарий в спеке, ручная проверка на фильтрах.
- [`color-mix`/oklab требуют современного браузера] → консоль локальная, актуальные Chromium/Firefox/Safari; фолбэк — базовый `fill: var(--dist-s2)`.
- [Кэш стилей у пользователя] → после мержа — жёсткое обновление (Ctrl+F5), как в прошлых изменениях консоли.

## Migration Plan

Данные не мигрируются, деплой не требуется (локальный сервер): изменение выходит с обычным перезапуском `tools/server.py`; откат — revert коммита, состояние живёт только в коде и CSS. Пользовательский пункт — в `CHANGELOG.md` (`[Unreleased]`, «Изменено») при реализации, по правилам репозитория.
