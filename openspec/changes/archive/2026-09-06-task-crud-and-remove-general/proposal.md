# Proposal: task-crud-and-remove-general

## Why

Сейчас задачи (tasks) создаются только вручную из `tasks/_TEMPLATE.md` — нет аналога `register_model.py` и веб-формы. При этом в системе остался фиктивный `general`: корзина для «ручных» вердиктов, не привязанных к задаче. Пользователь считает, что все вердикты должны быть привязаны к реальной задаче, а `general` — лишнее. Кроме того, поле «Таск» в форме записи вердикта сделано как `<input list>` — оно не работает как выпадающий список и показывает не все активные таски сразу.

## What Changes

- **Убрать `general` как корзину**: все 68 вердиктов из `matchups/general/` мигрируют в `matchups/T-001/` с заменой поля `task` с `general` на `T-001`. `settings.yaml` больше не содержит `general`, `current_task` по умолчанию равна первой активной задаче (сейчас `T-001`), fallback `general` исключается.
- **Полный CRUD тасок**: добавление, редактирование (название/проект/baseline), включение/выключение (active/inactive), выбор текущей. «Удаление» таски — это перевод в `inactive`, данные (`answers/`, `matchups/`) остаются, как и при архивации модели.
- **Исправить форму вердикта**: поле «Таск» заменяется на настоящий `<select>` с активными тасками, по умолчанию `current_task`. Запись вердикта без выбранной таски невозможна.
- **CLI-скрипт `register_task.py`**: автоматически определяет следующий `T-NNN`, создаёт `tasks/T-NNN-<slug>/task.md` из `_TEMPLATE.md`, активирует задачу в `settings.yaml`.
- **Веб-форма управления тасками**: либо отдельная страница, либо расширение `/settings` — список тасок с кнопками «Добавить», «Изменить», «Деактивировать/Активировать».
- **Обновление `run-progress`**: метрика покрытия считает только реальные активные таски, без `general`.
- **Обновление спек, README, workflow-guide**.

## Capabilities

### New Capabilities

*(нет — CRUD тасок логически продолжает `task-management`)*

### Modified Capabilities

- `task-management`: создание и редактирование тасок через CLI и UI, удаление = `inactive`, отказ от `general` как валидной таски.
- `leaderboard-ui`: форма вердикта с `<select>` активных тасок, страница управления тасками.
- `matchup-management`: вердикт пишется только в `matchups/<active-task-id>/`, нет специальной корзины `general`.
- `data-storage`: `settings.yaml` без `general`, миграция `matchups/general/` → `matchups/T-001/`.
- `run-progress`: прогресc считается по активным задачам без `general`.
- `benchmark-workflow`: создание задач через `register_task.py`, запись вердиктов только в `matchups/T-NNN/`, удаление упоминаний `general`.

## Impact

- **Код**: `tools/server.py`, `tools/elo.py`, `tools/record_verdict.py`, новый `tools/register_task.py`, `tools/generate_html.py` (если затронет UI).
- **Данные**: миграция 68 JSON-файлов из `matchups/general/` в `matchups/T-001/`, обновление `settings.yaml`, пересчёт `index.json`.
- **UI/UX**: главная страница получает рабочий выпадающий список тасок; появляется полноценное управление тасками.
- **Обратная совместимость**: `general` перестаёт существовать как задача; все старые вердикты сохраняются под `T-001`, ELO не меняется.
