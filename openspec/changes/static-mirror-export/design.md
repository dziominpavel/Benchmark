# Design

## Context

- Консоль — Flask-приложение `tools/server.py` (роуты + инлайн-шаблоны страниц) на общей оболочке `tools/templates/shell.html`; дизайн-система — `tools/static/css/console.css`, `tools/static/js/theme.js` (портирована из витрины change'ом `redesign-console-ui`).
- Сейчас на витрине публикуется рукописная папка `web/` (одна страница-лидерборд). Переключение витрины на сборку — отдельный change `web-app-build-hook`: витрина исполнит `build`-команду над свежим клоном и передаст каталог вывода.
- Данные: `data/index.json` (кэш ELO: `updated`, модели с elo/games/agent/provider/status/answers, `elo_history`), журнал `data/matchups/journal.jsonl`, `models.yaml`, `data/lookups.yaml`, задачи, ответы, флаги. Страницы читают их серверными хелперами; при устаревании кэш пересобирается и **сохраняется** (`_load_index` → `save_index`).
- Ограничения репозитория: stdlib + Flask, без JS-фреймворков, без CDN; артефакты на русском. В работе параллельный change `compact-pagination` — пересечений нет: экспорт рендерит текущий вид страниц.
- Масштаб: 28 моделей / 535 вердиктов сейчас; целевой — 1000 моделей / 10 000 вердиктов (change `scale-console-1000-models`).

## Goals / Non-Goals

**Goals:**

- Полный read-only слепок консоли — «Рейтинг», «История», «Аналитика», «Настройки», страницы моделей, очередь — из тех же шаблонов и данных.
- Автономный, детерминированный вывод для публикации в подкаталоге `/apps/benchmark/` без сервера и сети.
- Нулевой риск для данных репозитория и для поведения локальной консоли.

**Non-Goals:**

- Никакого второго UI: слепок — режим той же консоли плюс упаковка, а не новый фронтенд.
- Не менять URL-контракт и поведение локальной консоли; write-роуты остаются в коде как есть.
- Не решать масштабную стратегию (шардинг, JSON-рендер): только предупреждения о порогах; смена подхода — отдельный change.
- Не трогать репозиторий витрины — его часть в change'е `web-app-build-hook`.

## Decisions

**D1. Слепок через Flask test_client, а не скрейпинг и не второй фронтенд.**
Экспорт импортирует `tools/server.py` как библиотеку (сервер стартует только под `__main__`), рендерит страницы штатными роутами через `test_client()` и пишет HTML в каталог вывода. Отклонено: (а) отдельный витринный UI — дрейф разметки и цифр; (б) съём с живого сервера — хрупко и требует его запуска.

**D2. Read-only — флаг приложения плюс условные блоки только в местах записи.**
`app.config["READ_ONLY"]` (по умолчанию false) попадает в шаблоны как `read_only`. Правки:
- оболочка (`shell.html`): плашка «демонстрационная копия — только просмотр», ссылка в каталог, подмена футера («локальная консоль»), favicon зеркала; навигация и переключатель темы — без изменений;
- главная: формы записи (вердикт, «Прогнать») оборачиваются в `<fieldset disabled>` — нативная блокировка всех контролов без тега `<form method="post">` в выводе (нужно для целостности, D6); инлайновые скрипты записи не рендерятся; рекомендательная карточка — без кнопок запуска;
- страница модели: «Изменить» и прочие действия записи — нейтральный текст вместо ссылки;
- «Настройки»: формы (матрица ответов, справочники, сохранение, таски) — `<fieldset disabled>`; ссылки на `/add`, `/add_task`, `/edit*` не рендерятся как ссылки.
История, «Аналитика» и очередь записи не содержат — не трогаются. Небольшая добавка в `console.css` сбрасывает вид `fieldset` (border/margin/padding), чтобы вид копии совпадал с консолью.
Отклонено: «вырезать» контролы совсем (владелец выбрал полный вид копии с обезвреженным управлением) и отдельный набор шаблонов (дрейф разметки).

**D3. Ссылки и пути — пост-обработка по карте «URL → файл».**
Экспорт сам обходит известные URL, поэтому карта вывода строится заранее: `/` → `index.html`, `/history` → `history/`, `/stats` → `stats/`, `/settings` → `settings/`, `/model/<id>` → `model/<id>/`, `/static/...` → `static/...`. Проход по разметке переписывает абсолютные ссылки консоли в относительные по карте; ссылки с query (`?page=2`, `?show=…`, `?queue_page=K&…`) остаются как есть — их применяет JS зеркала; исключение — `queue_page` на «Настройках»: ведёт на предгенерированный файл `settings/queue-00K/` с сохранением остальных параметров. Маркеры `__catalog__` (корень витрины) и `__root__` (корень зеркала) заменяются относительным путём по глубине конкретного файла; глубина каталога — параметр `--catalog-depth` (по умолчанию 2 — положение `apps/<slug>/`).
Отклонено: `url_for` во всех шаблонах (большой дифф консоли, риск регрессий) и `SCRIPT_NAME` (литеральные `/static/...` и хардкод-ссылки им не покрываются).

**D4. Интерактив — `mirror.js` без фреймворков, данные из DOM.**
Подключается только в read-only. Фильтры («Показывать», агент/компания, «только долги», скрыть/подсветить) работают по data-атрибутам строк — те же правила, что серверные: показать/скрыть/подсветить, пересчитать счётчики, применить фильтры из адреса при загрузке и обновить адрес через `replaceState`. «История»: все записи отрендерены, клиентская пагинация по 20 и фильтры; ссылки `?page=` перехватываются. «Аналитика»: распределение Elo перерисовывается под фильтр — порт `build_elo_distribution_svg` на JS; вход — JSON-остров `#mirror-stats-data` (модели, elo, признаки), шкала и градиент повторяются как в консоли. «Настройки»: матрица ответов — тот же механизм фильтров; очередь — статические страницы без JS.
Отклонено: переносить рендер страниц целиком в JS (дублирование разметки) и оставить слепок без интерактива (нужен паритет).

**D5. Экспорт не пишет в рабочую копию.**
В read-only режиме `_load_index()` при устаревшем кэше возвращает пересчитанный индекс, не вызывая `save_index`; остальные хелперы только читают. Гарантия проверяется тестом (`git status` чист). Альтернатива «требовать свежий `index.json`» отклонена: лишний шаг для владельца.

**D6. Целостность — пост-проход по выводу с ненулевым кодом при нарушении.**
После записи: обход HTML-файлов (stdlib `html.parser`), каждая ссылка/ресурс — относительные разрешаются в существующий файл, query/fragment допустимы; `href|src="/…"` — ошибка; внешние `http(s)` — ошибка; `<form method="post">` — ошибка; остаточные `__`-маркеры — ошибка. Печатается файл и причина, код возврата — ненулевой. Ссылки на write-страницы попадут сюда автоматически, если D2 что-то пропустил. В конце — сводка (число страниц, моделей, страниц очереди, объём).

**D7. Очередь — предгенерированные страницы; вывод детерминирован.**
Очередь не подчиняется фильтрам, поэтому раскладывается по файлам `settings/queue-00K/` (соответствие `?queue_page=K`); на текущем масштабе это единицы файлов, при 1000 моделях — тысячи, что покрыто предупреждением порога. Время сборки в страницы не попадает; тест сравнивает две сборки.

**D8. Поставка и синхронизация.**
Команда — `python tools/export_web.py --out <каталог> [--catalog-depth N]`; её вызывает витрина (change `web-app-build-hook`). До переключения витрина продолжает публиковать `web/`. `notify-store.yml` дополняется путями `tools/**`: от инструментов и шаблонов теперь зависит публикуемая статика (`data/**` уже есть). В корень вывода пишется `icon.svg` — витринная карточка находит `icon.*` автоматически, страницы получают favicon; без него остаётся буквенный плейсхолдер.

**D9. Тесты — `tools/test_export.py` по образцу `test_perf.py`.**
Синтетическое хранилище в tmp с подменой путей `elo`/`server`/`lookups` (как в `_perf_storage`), сборка вызовом точки входа, проверки: состав страниц и модели, disabled-контролы, отсутствие POST-форм и корневых ссылок, разрешимость ссылок, чистая рабочая копия, детерминизм, что обычный режим рендера не изменился. JS автоматическими тестами не покрывается (в репозитории нет JS-инфраструктуры) — ручной чеклист в задачах.

## Risks / Trade-offs

- [Шаблон содержит ссылку, которой нет в карте] → сборка падает с диагностикой (D6); лечение: карта или шаблон; интеграционный тест ловит до витрины.
- [Паритет JS-фильтров с серверными] → правила дублируются в `mirror.js`; при изменениях серверной фильтрации нужно обновлять JS — отметка в `docs/architecture.md`; правила простые (совпадение множеств по data-признакам).
- [Объём истории в DOM] → порог 2000 записей: предупреждение; дальше — отдельный change (JSON-рендер), пока DOM дешевле дублирования разметки.
- [Число страниц моделей/очереди при 1000 моделях] → предупреждения порогов; общее время сборки ограничивает таймаут хука витрины (см. её change).
- [Устаревший `index.json` в клоне] → данные пересчитываются в памяти (D5); карточка витрины берёт `updated` из файла, расхождение покажет существующая сверка витрины.
- [Валидатор витрины требует store-chrome на каждой HTML-странице] → витринный change скоупит проверки для `apps/**` (D8 в `web-app-build-hook`), иначе слепок не опубликовать.

## Migration Plan

1. Benchmark: read-only, экспорт, `mirror.js`, тесты; папка `web/` не трогается — витрина публикует старую страницу.
2. Витрина: change `web-app-build-hook` (exec-хук) и `build:` в записи реестра.
3. Приёмка: `/apps/benchmark/` — полный слепок; после неё `web/` удаляется (шаг витринного change'а).
   Rollback: до удаления `web/` — убрать `build:` из реестра (витрина вернётся к папке); после удаления — откат коммитов.

## Open Questions

- Нужна ли страницам зеркала ссылка «О проекте» витрины (сейчас только «Мои приложения»)? На подход не влияет, решается после первой публикации.
- Пороги масштаба (2000 записей истории, 1000 моделей): переходить ли на JSON-рендер истории и шардинг страниц моделей — отдельный change по факту превышения.
