# task-management Specification

## Purpose
Создание и хранение задач бенчмарка. Единый формат — аналитические задачи (анализ проекта, поиск багов, планирование, граничные случаи) с опциональным кодом в ответе. Задачи создаются редко: 1 задача на 2–3 недели прогонов.

## Requirements

### Requirement: Формат задачи

Каждая задача хранится в `tasks/T-NNN-<slug>/task.md`. NNN — порядковый номер (001, 002, ...). slug — короткое описание в kebab-case. Файл содержит YAML front matter и описание.

#### Scenario: Структура задачи

- **WHEN** создаётся задача "Анализ WorkoutScoreCalculator"
- **THEN** создаётся директория `tasks/T-001-analyze-workout-score/`
- **AND** файл `task.md` внутри

### Requirement: Front matter задачи

YAML front matter содержит: `id` (T-NNN), `title` (человекочитаемое название), `baseline_commit` (опционально, хеш коммита проекта-референса), `project` (опционально, имя проекта-референса).

#### Scenario: Задача с референсом на проект

- **WHEN** задача связана с проектом GymProgress
- **THEN** front matter содержит: project: GymProgress, baseline_commit: <хеш>

#### Scenario: Абстрактная задача

- **WHEN** задача не связана с конкретным проектом
- **THEN** поля project и baseline_commit отсутствуют

### Requirement: Содержание задачи

Тело task.md описывает: что нужно проанализировать/найти/спланировать, критерии полноты ответа, ограничения. UI-тексты на русском, код и идентификаторы на английском.

#### Scenario: Задача на анализ багов

- **WHEN** задача требует найти баги в модуле
- **THEN** task.md описывает: модуль, файлы, что искать, сколько багов ожидается, формат ответа

### Requirement: Шаблон задачи

Файл `tasks/_TEMPLATE.md` содержит пустой шаблон задачи с front matter и секциями описания.

#### Scenario: Создание новой задачи из шаблона

- **WHEN** генерируется новая задача
- **THEN** используется tasks/_TEMPLATE.md как основа
- **AND** заполняются id, title, project, baseline_commit, описание

### Requirement: Нумерация задач

Номера задач (NNN) — сквозные, не переиспользуются. При создании новой задачи система определяет следующий номер как max(существующие) + 1.

#### Scenario: Первая задача

- **WHEN** задач ещё нет
- **THEN** первая задача получает номер T-001

#### Scenario: После двух задач

- **WHEN** существуют T-001 и T-002
- **THEN** следующая задача получает номер T-003

### Requirement: baseline_commit опционален

Для задач, связанных с реальным проектом, baseline_commit обеспечивает воспроизводимость: модель читает проект на конкретном коммите. Для абстрактных задач — не нужен.

#### Scenario: Модель читает проект

- **WHEN** задача имеет baseline_commit и project
- **THEN** промпт для модели включает: "cd C:/projects/<project> && git checkout <baseline_commit>"

#### Scenario: Абстрактная задача

- **WHEN** задача без baseline_commit
- **THEN** промпт для модели не включает git checkout
