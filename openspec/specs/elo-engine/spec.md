# elo-engine Specification

## Purpose
ELO-движок (`tools/elo.py`, только stdlib) пересчитывает рейтинги моделей
из попарных вердиктов. Классическая формула ELO с адаптивным K-factor:
быстрая калибровка новых моделей, стабильность устоявшихся. Пересчёт всегда
полный — из всех вердиктов в хронологическом порядке.

## Requirements

### Requirement: Начальный ELO

Все модели SHALL стартовать с ELO = 1200, `games` = 0, `wins` = 0, `losses` = 0,
`draws` = 0. Покрытие `python tools/test_elo.py` SHALL оставаться зелёным.

#### Scenario: Новая модель регистрируется

- **WHEN** модель добавляется в реестр (`models.yaml`)
- **THEN** следующий пересчёт присваивает ей ELO = 1200
- **AND** статистику 0/0/0/0

### Requirement: Расчёт ожидания

Перед каждым вердиктом система SHALL вычислять ожидаемую вероятность победы:
`E_A = 1 / (1 + 10^((R_B − R_A) / 400))`, `E_B = 1 − E_A`
(в коде: `expected_score`, `e_b = 1.0 − e_a`).

#### Scenario: Равные модели

- **WHEN** модель A (ELO=1200) сравнивается с моделью B (ELO=1200)
- **THEN** E_A = 0.50, E_B = 0.50

#### Scenario: Фаворит против аутсайдера

- **WHEN** модель A (ELO=1300) сравнивается с моделью B (ELO=1100)
- **THEN** E_A = 0.76, E_B = 0.24

### Requirement: Адаптивный K-factor

K-factor SHALL зависеть от числа игр модели: `< 10` → 40; `10–30` (включительно,
в коде `games <= 30`) → 32; `> 30` → 24. K SHALL применяться индивидуально
к каждой модели в паре (у A и B может быть разный K).

#### Scenario: Новая модель (0 игр)

- **WHEN** модель с 0 игр получает вердикт
- **THEN** её K-factor = 40

#### Scenario: Установившаяся модель (35 игр)

- **WHEN** модель с 35 игр получает вердикт
- **THEN** её K-factor = 24

#### Scenario: Граница 30 игр

- **WHEN** у модели ровно 30 игр
- **THEN** её K-factor = 32

#### Scenario: Модели с разным опытом в одной паре

- **WHEN** модель A (5 игр, K=40) сравнивается с моделью B (35 игр, K=24)
- **THEN** обновление A использует K=40, обновление B использует K=24

### Requirement: Обновление рейтинга

После вердикта система SHALL обновлять ELO: `R_A′ = R_A + K_A × (S_A − E_A)`,
где S = 1 (победа), 0 (поражение), 0.5 (ничья). Статистика W/L/D/games обеих
моделей SHALL обновляться симметрично.

#### Scenario: Победа фаворита (ожидаемый результат)

- **WHEN** A (ELO=1300, K=32, E_A=0.76) побеждает B (ELO=1100, K=32)
- **THEN** R_A′ = 1300 + 32 × (1 − 0.76) = 1308
- **AND** R_B′ = 1100 + 32 × (0 − 0.24) = 1092

#### Scenario: Победа аутсайдера (апсет)

- **WHEN** A (ELO=1100, K=40, E_A=0.24) побеждает B (ELO=1300, K=24)
- **THEN** R_A′ = 1100 + 40 × (1 − 0.24) = 1130
- **AND** R_B′ = 1300 + 24 × (0 − 0.76) = 1282

#### Scenario: Ничья равных

- **WHEN** A (ELO=1200, K=32, E_A=0.50) играет вничью с B (ELO=1200, K=32)
- **THEN** оба остаются 1200 (дельта 0)

### Requirement: Пересчёт из вердиктов

ELO SHALL пересчитываться полным проходом: все модели стартуют с 1200,
вердикты из `matchups/` применяются последовательно в порядке (`date`,
`_matchup_id`). Вердикты с неизвестными моделями SHALL пропускаться молча;
вердикты с неизвестным `winner` SHALL пропускаться с предупреждением в stderr.
Инкрементальный и полный пересчёт дают идентичный результат.

#### Scenario: Полный пересчёт

- **WHEN** вызывается `generate_index()` (команда `python tools/elo.py`, запись вердикта или добавление модели на сервере)
- **THEN** система загружает все вердикты в хронологическом порядке
- **AND** применяет каждый последовательно, начиная с ELO=1200
- **AND** записывает итоги в `index.json`

#### Scenario: Проверка без записи

- **WHEN** выполняется `python tools/elo.py --check`
- **THEN** файл не пишется; exit 0 — кэш актуален, exit 1 — нужен пересчёт

### Requirement: История изменений ELO

Система SHALL сохранять **одну** запись истории на каждый применённый вердикт. Запись содержит идентификатор матча (`matchup` и `after_matchup`), глобальный `seq`, `date`, `recorded_at`, идентификаторы обеих моделей (`model_a_id`, `model_b_id`), победителя (`winner`) и ELO-снэпшоты обеих сторон (`elo_a`, `elo_b`), каждый с полями `before`, `after`, `delta`. Записи истории моделей (`model`, `opponent`) SHALL NOT генерироваться в `elo_history`.

#### Scenario: Запись истории

- **WHEN** вердикт `general/001` обновляет ELO модели A с 1200 до 1220, а модели B с 1200 до 1180
- **THEN** в `elo_history` добавляется одна запись `{matchup: "general/001", model_a_id: "A", model_b_id: "B", winner: "a", elo_a: {before: 1200, after: 1220, delta: 20}, elo_b: {before: 1200, after: 1180, delta: -20}}`
- **AND** поля `seq`, `date`, `recorded_at` сохраняются из вердикта
- **AND** не создаётся отдельная запись для модели B

#### Scenario: Проверка монотонности recorded_at

- **WHEN** `recorded_at` вердикта `seq=3` раньше `recorded_at` вердикта `seq=2`
- **THEN** `--check` сообщает об ошибке

#### Scenario: Проверка recorded_at на наличие

- **WHEN** вердикт не содержит `recorded_at`
- **THEN** `--check` сообщает об ошибке

### Requirement: Архивные модели в пересчёте

Вердикты с участием архивных моделей SHALL учитываться в истории наравне
с остальными (фильтра по статусу в `recalculate` нет). Запрета создавать новые
вердикты с архивной моделью в коде нет — ограничение существует только
на уровне договорённости.

#### Scenario: Архивная модель в пересчёте

- **WHEN** система пересчитывает ELO из всех вердиктов
- **THEN** старые вердикты архивной модели влияют на рейтинг как раньше

### Requirement: Целочисленный ELO

ELO SHALL храниться как целое число. Промежуточные вычисления — float, итог
округляется Half-to-Even (банковское округление, Python `round`).

#### Scenario: Округление

- **WHEN** вычисление даёт R′ = 1216.5
- **THEN** сохраняется ELO = 1216
- **AND** при 1217.5 сохраняется 1218

### Requirement: Миграция legacy-вердиктов

Для вердиктов, записанных до введения обязательного `recorded_at`, система MAY проставить синтетическое `recorded_at` на основе `date` и `seq` при миграции, чтобы сохранить монотонность. Новые вердикты MUST получать реальное системное время.

#### Scenario: Бэкфилл recorded_at

- **WHEN** `tools/migrate_recorded_at.py` обрабатывает вердикт с `seq=2` и `date=2026-09-05` без `recorded_at`
- **THEN** файл дополняется `recorded_at: "2026-09-05T00:00:04+00:00"`
- **AND** при следующем `elo.py --check` ошибок не возникает
