# pairing-algorithm Specification

## Purpose
Алгоритм предложения пар моделей для следующего сравнения в веб-UI
(`get_recommendations` в `tools/server.py`). Работает глобально поверх всех
моделей реестра (без разреза по задачам): исключает уже сравнённые пары
и ранжирует остальные двухуровнево — сначала тир калибровки (новые модели
выше всех), внутри тира — близость ELO. Возвращает топ-3.

## Requirements

### Requirement: Источник кандидатов

Кандидатами SHALL быть все неупорядоченные пары моделей из `index.json`
(`C(n,2)`), кроме пар, которые уже сравнивались. Сравнение фиксируется глобально:
множество `frozenset({a, b})` поверх файлов всех директорий `matchups/*/`.
Наличие ответов и разрез по задачам НЕ учитываются (упрощение MVP).

#### Scenario: Одна уже сравнённая пара

- **WHEN** существует вердикт A vs B (в любой директории matchups)
- **THEN** пара A-B исключается из кандидатов навсегда
- **AND** повторное сравнение через рекомендации не предлагается

#### Scenario: Меньше двух моделей

- **WHEN** в `index.json` меньше 2 моделей
- **THEN** рекомендации пусты

### Requirement: Тиры калибровки и сортировка

Пары SHALL раскладываться по тирам калибровки по `min_games`
(числу игр менее игранной модели в паре, данные из `index.json`):
тир 0 — `min_games == 0` (новая модель), тир 1 — `min_games < 3`
(нужна калибровка), тир 2 — остальные. Сортировка SHALL быть
лексикографической: сначала тир по возрастанию, внутри тира —
близость ELO (`score = closeness = 1 / (1 + elo_diff / 100)`,
`elo_diff = |elo_a − elo_b|`), больший score выше. Любая пара
тира 0 SHALL стоять выше любой пары тиров 1 и 2 независимо от
разницы ELO. Старая композитная формула `0.6 × closeness +
0.4 × calibration` НЕВЕРНА для текущего кода и MUST NOT использоваться.

#### Scenario: Расчёт score

- **WHEN** пара A-B: elo_diff=0
- **THEN** score = closeness = 1.0

#### Scenario: Новая модель выше старого близкого боя

- **WHEN** пара X: elo_diff=0, min_games=1 (тир 1);
  пара Y: elo_diff=200, min_games=0 (тир 0)
- **THEN** выше ранжируется пара Y

### Requirement: Причина рекомендации

Каждая рекомендация SHALL содержать человекочитаемую причину по фактическим
порогам кода: `min_games == 0` → «новая модель, ещё не играла»;
`min_games < 3` → «мало игр (N), нужна калибровка»; `elo_diff < 50` →
«близкий рейтинг (разница N)»; `elo_diff < 150` → «рейтинг различается
умеренно (ΔN)»; иначе → «разный уровень (ΔN) — проверить апсет».

#### Scenario: Новая модель

- **WHEN** модель D имеет 0 игр
- **THEN** пары с D получают причину «новая модель, ещё не играла»
- **AND** как тир 0 стоят выше всех пар без новых моделей

#### Scenario: Близкий рейтинг

- **WHEN** A=1216 (5 игр), B=1220 (5 игр), пара не сравнена
- **THEN** причина — «близкий рейтинг (разница 4)»

### Requirement: Вывод рекомендации

Система SHALL возвращать не более 3 пар (`top_n=3`), отсортированных
сначала по тиру, затем по убыванию score. Каждая запись содержит:
`model_a`, `model_b`, имена, `elo_a`, `elo_b`, `elo_diff`, `reason`,
`tier`, `score`. Блок «Рекомендуемые модели к прогону» показывает имя, ELO
и причину; кнопка «Прогнать» подставляет пару в форму вердикта.

#### Scenario: Отображение рекомендации

- **WHEN** есть несравнённые пары
- **THEN** пользователь видит до 3 карточек «Имя (ELO) vs Имя (ELO) | причина»

#### Scenario: Нет несравнённых пар

- **WHEN** все возможные пары уже сравнены (при ≥ 2 моделях)
- **THEN** блок показывает «Все пары уже прогнаны…»
- **AND** предлагается добавить новую модель

### Requirement: Фильтр архивных моделей

Алгоритм SHALL исключать модели со `status: archived` из кандидатов на сравнение. `get_recommendations` SHALL читать `status` из `index.json["models"][<id>]["status"]` и пропускать архивные модели. Пары, в которых хотя бы одна модель `archived`, SHALL NOT появляться в рекомендациях.

#### Scenario: Архивная модель исключена

- **WHEN** модель C имеет `status: archived`
- **THEN** пары с участием C не предлагаются в блоке рекомендаций

#### Scenario: Активная модель предлагается

- **WHEN** обе модели в паре имеют `status: active`
- **THEN** пара MAY появиться в рекомендациях при прочих условиях
