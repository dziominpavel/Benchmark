# matchup-management Specification

## Purpose
Хранение и запись попарных вердиктов (задача × модель A × модель B × победитель). Вердикт — минимальная запись результата сравнения двух ответов, без обоснования и идентификации судьи.

## Requirements

### Requirement: Формат вердикта

Каждый вердикт хранится в отдельном JSON-файле: `matchups/<task-id>/<NNN>.json`. NNN — порядковый номер вердикта для данной задачи, начинается с 001.

#### Scenario: Структура файла вердикта

- **WHEN** записывается вердикт для задачи T-001, моделей A и B, победитель A
- **THEN** создаётся файл `matchups/T-001/001.json`
- **AND** файл содержит: { "task": "T-001", "model_a": "A", "model_b": "B", "winner": "a", "date": "YYYY-MM-DD" }

#### Scenario: Ничья

- **WHEN** судья определяет ничью
- **THEN** поле "winner" = "draw"

### Requirement: Уникальность вердикта

Каждый вердикт имеет уникальный идентификатор в формате `<task-id>/<NNN>`. Нумерация сквозная в пределах задачи, не переиспользуется.

#### Scenario: Второй вердикт для той же задачи

- **WHEN** записывается второй вердикт для T-001
- **THEN** файл называется `matchups/T-001/002.json`

### Requirement: Запись через веб-UI

Пользователь записывает вердикт через локальный веб-сервер: выбирает задачу, модель A, модель B, победителя. Система создаёт файл вердикта, пересчитывает ELO, обновляет index.json.

#### Scenario: Успешная запись

- **WHEN** пользователь выбирает T-001, модель A, модель B, победитель A в веб-форме
- **THEN** система создаёт matchups/T-001/NNN.json
- **AND** пересчитывает ELO обеих моделей
- **AND** обновляет index.json
- **AND** показывает обновлённый leaderboard

#### Scenario: Модель не имеет ответа на задачу

- **WHEN** пользователь выбирает модель, у которой нет ответа на выбранную задачу
- **THEN** система показывает ошибку: "У модели X нет ответа на задачу T-001"

### Requirement: Валидация вердикта

Система SHALL проверять: обе модели существуют в реестре, обе имеют ответы на указанную задачу, модели A и B различны, победитель — одно из: "a", "b", "draw".

#### Scenario: Одинаковые модели

- **WHEN** пользователь выбирает модель A = модель B
- **THEN** система отклоняет запись с ошибкой "Модели должны различаться"

#### Scenario: Несуществующая модель

- **WHEN** пользователь выбирает модель, не зарегистрированную в models.yaml
- **THEN** система отклоняет запись с ошибкой "Модель не найдена в реестре"

### Requirement: Анонимность вердикта

Вердикт не содержит идентификатора судьи, обоснования или баллов. Только результат сравнения.

#### Scenario: Содержимое вердикта

- **WHEN** вердикт записан
- **THEN** файл содержит только: task, model_a, model_b, winner, date
- **AND** не содержит: judge, reasoning, scores, anonymization map

### Requirement: Хронологический порядок

Вердикты упорядочиваются по дате записи (поле date + порядок создания файла). При пересчёте ELO вердикты применяются в этом порядке.

#### Scenario: Два вердикта в один день

- **WHEN** два вердикта записаны в один день для одной задачи
- **THEN** вердикт с меньшим NNN считается более ранним
