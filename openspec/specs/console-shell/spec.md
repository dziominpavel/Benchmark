# console-shell Specification

## Purpose

Глобальная оболочка веб-консоли Benchmark: ассеты дизайн-системы, тема оформления
(тёмная по умолчанию + переключатель), верхняя навигация, хлебные крошки и единый
контейнер страниц — то, что действует одинаково на всех страницах сервера.

## Requirements

### Requirement: Статические ассеты дизайн-системы

Система SHALL раздавать файлы дизайн-системы (стили и скрипт темы) со стабильных
однородных URL вида `/static/...`. Каждая страница консоли SHALL подключать эти
ассеты. Стили, встроенные в HTML-шаблоны сервера, MUST NOT быть единственным
источником оформления страницы. Интерфейс SHALL работать без внешних сетевых
запросов: сторонние CDN, веб-шрифты и JS-библиотеки MUST NOT подключаться.

#### Scenario: Загрузка ассетов на любой странице

- **WHEN** пользователь открывает любую страницу консоли (например `/history`)
- **THEN** стили и скрипт темы загружаются с того же origin по URL `/static/...`
- **AND** страница отрисовывается в едином оформлении с остальными страницами

#### Scenario: Работа без интернета

- **WHEN** внешняя сеть недоступна
- **THEN** страницы консоли отрисовываются полностью, ошибок загрузки ресурсов нет

### Requirement: Тема оформления

Тёмная тема SHALL быть темой по умолчанию. Пользователь SHALL иметь возможность
переключать тему на светлую кнопкой в шапке; выбор SHALL сохраняться между
загрузками страниц и применяться на всех страницах консоли. При загрузке страницы
отрисовка SHALL начинаться сразу в выбранной теме — вспышка не-тёмной темы при
тёмной теме пользователя MUST NOT происходить. Атрибут `color-scheme` документа
SHALL соответствовать выбранной теме (элементы браузера — скроллбары, поля ввода —
следуют теме).

#### Scenario: Первое открытие

- **WHEN** пользователь открывает консоль впервые (сохранённой темы нет)
- **THEN** страница отрисована в тёмной теме

#### Scenario: Переключение и сохранение выбора

- **WHEN** пользователь нажимает кнопку темы и выбирает светлую
- **THEN** страница переключается на светлую тему без перезагрузки
- **AND** после перезагрузки страницы светлая тема сохранена

#### Scenario: Отсутствие вспышки при загрузке

- **WHEN** пользователь с тёмной темой открывает страницу консоли
- **THEN** первый отрисованный кадр страницы уже тёмный

### Requirement: Верхняя навигация

На каждой странице консоли SHALL отображаться общая шапка со ссылками
«Рейтинг» (`/`), «История» (`/history`), «Аналитика» (`/stats`), «Настройки»
(`/settings`) и кнопкой переключения темы. Текущий раздел SHALL быть визуально
выделен. Шапка SHALL оставаться доступной без прокрутки (sticky) на всех
страницах, включая страницы форм `/add`, `/edit/<id>`, `/add_task`,
`/edit_task/<id>`. Локальные шапки страниц MUST NOT дублировать эту навигацию.

#### Scenario: Переход между разделами со страницы модели

- **WHEN** пользователь на `/model/<id>` нажимает «Настройки» в шапке
- **THEN** открывается страница `/settings`

#### Scenario: Подсветка активного раздела

- **WHEN** пользователь открыл `/history`
- **THEN** ссылка «История» визуально выделена как текущая
- **AND** остальные ссылки навигации не выделены

#### Scenario: Навигация на странице формы

- **WHEN** пользователь открыл `/edit_task/T-001`
- **THEN** шапка с четырьмя ссылками навигации и кнопкой темы видна
- **AND** контент формы доступен сразу, без поиска ссылки «назад»

### Requirement: Хлебные крошки

Каждая страница консоли, кроме главной, SHALL показывать хлебные крошки — путь от
раздела до текущей страницы. Страницы форм (`/add`, `/edit/<id>`, `/add_task`,
`/edit_task/<id>`) SHALL включать в путь свой контекст: раздел-владелец и объект
(например, «Настройки» → «Таски» → …). Элементы крошек, кроме текущего, SHALL
быть ссылками на соответствующие страницы.

#### Scenario: Крошки на странице редактирования модели

- **WHEN** пользователь открыл `/edit/<id>` существующей модели
- **THEN** путь содержит ссылку на модель (`/model/<id>`) и текущий шаг
  «Редактирование»

#### Scenario: Крошки на странице аналитики

- **WHEN** пользователь открыл `/stats`
- **THEN** первый элемент крошек «Рейтинг» ведёт на `/`

### Requirement: Единый контейнер страниц

Все страницы консоли SHALL рендериться в едином контейнере с одинаковыми
отступами и ограничением ширины, включая `/add`, `/edit/<id>`, `/add_task`,
`/edit_task/<id>`. Контент страницы MUST NOT прижиматься к краю окна.

#### Scenario: Страница добавления модели

- **WHEN** пользователь открывает `/add`
- **THEN** отступы и максимальная ширина контейнера совпадают с главной страницей
- **AND** форма не прилегает к левому краю окна

### Requirement: Видимый фокус и контраст текста

Интерактивные элементы (ссылки, кнопки, поля ввода, чекбоксы) SHALL иметь видимый
индикатор фокуса при навигации с клавиатуры. Текстовые элементы — включая
приглушённый текст подсказок, статистики, легенд и плейсхолдеров — SHALL иметь
контраст к своему фону не ниже 4.5:1.

#### Scenario: Навигация с клавиатуры

- **WHEN** пользователь перемещает фокус клавишей Tab по странице
- **THEN** активный элемент выделен видимым контуром

#### Scenario: Контраст приглушённого текста

- **WHEN** измеряется контраст текста подсказок или статистики к фону карточки
- **THEN** значение контраста составляет не менее 4.5:1

### Requirement: Иконка вкладки

Каждая страница живой консоли SHALL подключать иконку вкладки `/static/icon.svg`
с того же origin (файл дизайн-системы). Страницы статического слепка витрины
SHALL сохранять существующий маркер `__root__icon.svg` — поведение слепка не
меняется.

#### Scenario: Иконка на странице консоли

- **WHEN** пользователь открывает любую страницу живой консоли (например, `/settings`)
- **THEN** в `<head>` страницы есть `<link rel="icon" href="/static/icon.svg">`
- **AND** файл иконки обслуживается тем же сервером

#### Scenario: Слепок витрины не меняется

- **WHEN** страница собирается в статический слепок
- **THEN** иконка подключается относительным путём через маркер `__root__icon.svg`

### Requirement: Озвучивание системных сообщений

Сообщение об успехе (`.alert-success`) SHALL иметь `role="status"`, сообщение
об ошибке (`.alert-error`) SHALL иметь `role="alert"`. Сообщения SHALL
оставаться видимыми и читаемыми без JavaScript.

#### Scenario: Успех после записи вердикта

- **WHEN** вердикт записан и страница показана с сообщением об успехе
- **THEN** контейнер сообщения имеет `role="status"`

#### Scenario: Ошибка формы

- **WHEN** страница показана с сообщением об ошибке
- **THEN** контейнер сообщения имеет `role="alert"`

### Requirement: Семантика заголовков таблиц

Все заголовки столбцов (`th`) таблиц консоли SHALL иметь атрибут `scope="col"`.
Внешний вид и состав таблиц SHALL NOT меняться.

#### Scenario: Таблицы главной страницы

- **WHEN** открыта главная страница
- **THEN** каждый `th` таблицы рейтинга имеет `scope="col"`

#### Scenario: Таблицы настроек

- **WHEN** открыт `/settings`
- **THEN** каждый `th` таблиц очереди, справочников, моделей, тасков и матрицы
  ответов имеет `scope="col"`

### Requirement: Подтверждение деструктивных действий

Деструктивные действия консоли SHALL требовать явного подтверждения
с указанием объекта: архивация модели (смена статуса на «Неактивна» в форме
`/edit/<id>`) и удаление значения справочника. Подтверждение SHALL
запрашиваться до отправки формы; при отказе изменение SHALL NOT выполняться.
Серверные проверки SHALL действовать независимо от подтверждения.

#### Scenario: Архивация модели

- **WHEN** пользователь переводит модель в статус «Неактивна» и сохраняет форму
- **THEN** запрашивается подтверждение с именем модели
- **AND** при отказе статус модели не меняется

#### Scenario: Обычное сохранение формы

- **WHEN** пользователь сохраняет форму модели без перевода в архив
- **THEN** подтверждение SHALL NOT запрашиваться

#### Scenario: Удаление значения справочника

- **WHEN** пользователь удаляет неиспользуемое значение справочника
- **THEN** запрашивается подтверждение со значением
- **AND** при отказе значение остаётся в справочнике

### Requirement: Версия и дата-время сборки консоли

Подвал каждой страницы консоли SHALL показывать версию — тег последнего релиза
(`vX.Y.Z`) — и дату-время сборки запущенного кода по минскому времени (UTC+3)
с меткой `МСК`, независимо от часового пояса машины, где запущена консоль или
собран слепок. Страница настроек SHALL показывать те же значения в секции
«О консоли» с пояснением происхождения. Если источник значений недоступен,
блок SHALL скрываться, разметка MUST NOT ломаться.

#### Scenario: Подвал на любой странице живой консоли

- **WHEN** пользователь открывает любую страницу консоли (например `/history`)
- **THEN** в подвале видны версия в форме `vX.Y.Z` и строка «сборка ДД.ММ.ГГГГ ЧЧ:ММ МСК»
- **AND** версия совпадает с тегом последнего выпущенного релиза

#### Scenario: Секция «О консоли» страницы настроек

- **WHEN** пользователь открыл `/settings`
- **THEN** в секции «О консоли» парами «подпись → значение» показаны версия и сборка
- **AND** сборка показана по минскому времени с меткой `МСК`
- **AND** секция доступна по пункту локальной навигации страницы настроек

#### Scenario: Значения в слепке витрины

- **WHEN** страница собирается в статический слепок витрины
- **THEN** подвал слепка содержит версию и сборку, запечённые на момент сборки слепка
- **AND** сборка показана по минскому времени с меткой `МСК` независимо от зоны
  сборочной машины

#### Scenario: Сборка слепка в UTC

- **WHEN** статический слепок собирается на машине с часовым поясом UTC (GitHub Actions)
- **THEN** в подвале слепка указано минское время с меткой `МСК`
  (коммит `2026-10-19T21:23:54+03:00` показан как `19.10.2026 21:23 МСК`, а не `18:23`)

#### Scenario: Запуск без git-репозитория

- **WHEN** консоль запущена из копии без git (архив исходников)
- **THEN** версия берётся из файла версии проекта
- **AND** сборка определяется по времени файла версии проекта
- **AND** время показано по минскому времени с меткой `МСК`

#### Scenario: Источники недоступны

- **WHEN** недоступны и git, и файл версии проекта
- **THEN** блоки версии и сборки в подвале и настройках скрыты
- **AND** страница отрисовывается без ошибок
