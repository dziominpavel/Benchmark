# leaderboard-ui Specification

## Purpose
Веб-интерфейс leaderboard на локальном сервере. Показывает таблицу рейтинга моделей с ELO, статистикой W/L/D, количеством оценок. Предоставляет форму для записи вердиктов и отображает предложения пар.

## Requirements

### Requirement: Локальный веб-сервер

Система запускается как локальный веб-сервер (Flask) одной командой. Доступен по адресу http://localhost:5000.

#### Scenario: Запуск сервера

- **WHEN** пользователь выполняет `python tools/server.py`
- **THEN** сервер запускается на порту 5000
- **AND** выводит URL http://localhost:5000

#### Scenario: Порт занят

- **WHEN** порт 5000 уже занят
- **THEN** система пытается использовать следующий свободный порт (5001, 5002, ...)
- **AND** выводит фактический URL

### Requirement: Таблица рейтинга

Главная страница показывает таблицу: ранг, название модели, провайдер, ELO, W (победы), L (поражения), D (ничьи), всего игр. Сортировка по ELO (по убыванию).

#### Scenario: Отображение рейтинга

- **WHEN** пользователь открывает localhost:5000
- **THEN** видит таблицу с колонками: #, Модель, Провайдер, ELO, W, L, D, Игры
- **AND** строки отсортированы по ELO по убыванию

#### Scenario: Нет моделей

- **WHEN** в реестре нет моделей или нет вердиктов
- **THEN** таблица пуста, показывается сообщение "Нет данных. Создайте задачу и запустите модели."

### Requirement: Фильтр архивных моделей

По умолчанию архивные модели скрыты. Переключатель "показывать архивные" включает их отображение (серым цветом, в конце списка).

#### Scenario: Скрытие архивных по умолчанию

- **WHEN** модели A (active, ELO=1300) и B (archived, ELO=1100) существуют
- **THEN** по умолчанию видна только A
- **AND** B скрыта

#### Scenario: Включение архивных

- **WHEN** пользователь включает "показывать архивные"
- **THEN** B отображается серым цветом
- **AND** B расположена в списке по ELO (не в конце)

### Requirement: Форма записи вердикта

На странице есть форма: выбор задачи (dropdown), выбор модели A (dropdown), выбор модели B (dropdown), выбор победителя (radio: A / B / Ничья), кнопка "Записать".

#### Scenario: Заполнение формы

- **WHEN** пользователь выбирает T-001, модель A, модель B, победитель A
- **AND** нажимает "Записать"
- **THEN** система создаёт вердикт, пересчитывает ELO, обновляет index.json
- **AND** страница перезагружается с обновлённым рейтингом

#### Scenario: Валидация в UI

- **WHEN** пользователь выбирает одинаковые модели A и B
- **THEN** кнопка "Записать" блокируется с сообщением "Модели должны различаться"

### Requirement: Dropdown фильтрации по задаче

Dropdown моделей A и B фильтруется по выбранной задаче — показываются только модели, у которых есть ответ на эту задачу.

#### Scenario: Выбор задачи фильтрует модели

- **WHEN** пользователь выбирает задачу T-001
- **THEN** dropdown моделей показывает только те, у которых есть answers/T-001/<model>.md

### Requirement: Блок предложений пар

На странице есть блок "Рекомендуемая пара" — система показывает одну пару с наивысшим приоритетом (по pairing-algorithm). Кнопка "Сравнить" заполняет форму записи вердикта этой парой.

#### Scenario: Отображение рекомендации

- **WHEN** есть неоценённые пары
- **THEN** блок показывает: "Задача T-001 | A vs B | Причина: близкий ELO"
- **AND** кнопка "Сравнить" заполняет форму (задача, A, B) и скроллит к ней

#### Scenario: Нет неоценённых пар

- **WHEN** все пары для всех задач оценены
- **THEN** блок показывает "Все пары оценены. Создайте новую задачу или добавьте модель."

### Requirement: Статичный экспорт HTML

Система MAY генерировать статичный leaderboard.html (без сервера) для просмотра без запуска Flask. Команда: `python tools/generate_html.py`.

#### Scenario: Генерация статичного HTML

- **WHEN** пользователь выполняет `python tools/generate_html.py`
- **THEN** создаётся leaderboard.html с таблицей рейтинга (только чтение)
- **AND** файл можно открыть в браузере напрямую (file://)
