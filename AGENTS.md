# Benchmark — протокол для модели-участницы

> Этот файл читает LLM-модель, которая выполняет задачу бенчмарка
> в роли **участника** (слот modelA или modelB).

## Что делать

1. **Прочитай задачу** — `tasks/T-NNN-<slug>/task.md`. Изучи: front matter,
   описание, что искать, критерии полноты, ограничения.

2. **Если есть baseline_commit** — перейди в папку проекта и сделай checkout:
   ```
   cd C:/projects/<project>
   git checkout <baseline_commit>
   ```
   Это обеспечивает воспроизводимость: ты анализируешь код на конкретном коммите.

3. **Изучи код проекта** (если задача связана с проектом) согласно описанию.

4. **Напиши ответ** — MD-файл своего слота:
   ```
   answers/<task-id>/modelA.md   # если ты участник A (@benchmark-run-a)
   answers/<task-id>/modelB.md   # если ты участник B (@benchmark-run-b)
   ```
   Ручной прогон произвольной модели из реестра — файл
   `answers/<task-id>/<model-id>.md` по формату `answers/_TEMPLATE.md`.

## Формат ответа

```markdown
---
task: T-NNN
model: modelA
date: YYYY-MM-DD
---

# Ответ на задачу T-NNN

## Анализ
<!-- Краткий обзор: что рассмотрено -->

## Находки
### 1. [Название]
**Файл:** `path/to/file.kt:NN`
**Критичность:** критичный / средний / низкий
**Описание:** ...

**Пример:**
<!-- Входные данные, на которых баг проявляется -->

**Исправление:**
```kotlin
// Исправленный код
```

## Граничные случаи (проверено, не баг)
<!-- Что проверено и почему работает корректно -->

## Дополнительные находки
<!-- Неиспользуемые импорты, стиль и т.д. -->
```

## Правила

- **Ответ = MD-файл** (анализ + код в блоках), не код в проекте.
- **Максимально полный ответ** — все граничные случаи, все находки.
- **Код в блоках** ```kotlin (или другой язык) — судья оценивает качество кода.
- **UI-тексты на русском**, код и идентификаторы на английском.
- **Не модифицируй проект** — только читаешь и анализируешь.
- После работы верни проект в исходное состояние:
  ```
  git checkout . && git clean -fd
  ```
- **Сохрани ответ** в файл своего слота (см. выше), при повторном прогоне файл перезаписывается.

## Саморегистрация

Если ты делаешь ручной прогон под своим `<model-id>`, а тебя нет в `models.yaml`,
зарегистрируйся заранее:
```
python tools/register_model.py --auto --id <slug> --name "<Имя Модели>"
```
Для skill-прогонов A/B регистрация не требуется — участник не знает реальный `id`. Координатор укажет реальные `id` при записи вердикта.

## Git — коммиты (для работы над этим репозиторием)

- `git commit` / `git push` — **только по явному указанию** пользователя
  («закоммить», «запушь», «commit and push»). Не коммитить «заодно».
- **ЗАПРЕЩЕНО** добавлять в сообщение коммита трейлеры `Generated with ...`,
  `Co-Authored-By:` и любые другие авторские/агентские пометки.
- Сообщение — через файл: `git commit -F <file>` (PowerShell не поддерживает
  heredoc `$(cat <<'EOF'...)`). Файл писать без BOM
  (`[IO.File]::WriteAllText` с `UTF8Encoding($false)`).
- Перед коммитом проверь текст: никаких строк, начинающихся с
  `Generated with` или `Co-Authored-By:`.
- Полные правила — `.devin/rules/git.md`.
