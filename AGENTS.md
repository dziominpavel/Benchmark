# Benchmark — протокол для модели-участницы

> Этот файл читает LLM-модель, которая выполняет задачу бенчмарка
> в роли **участника**.

## Что делать

1. **Прочитай задачу** — `tasks/T-NNN-<slug>/task.md`. Изучи: front matter,
   описание, критерии полноты, ограничения.

2. **Если есть baseline_commit** — перейди в папку проекта и сделай checkout:
   ```
   cd C:/projects/<project>
   git checkout <baseline_commit>
   ```
   Это обеспечивает воспроизводимость: ты анализируешь код на конкретном коммите.

3. **Изучи код проекта** (если задача связана с проектом) согласно описанию.

4. **Напиши ответ** — MD-файл:
   ```
   answers/<task-id>/<model-id>.md
   ```

## Формат ответа

```markdown
---
task: T-NNN
model: <model-id>
date: YYYY-MM-DD
---

# Ответ на задачу T-NNN

## Анализ
<!-- Основной анализ -->

## Находки
### 1. [Название]
**Файл:** `path/to/file.kt:NN`
**Проблема:** ...

```kotlin
// Проблемный код
```

**Исправление:**
```kotlin
// Исправленный код
```

## План (если требуется)
<!-- План рефакторинга/реализации -->
```

## Правила

- **Ответ = MD-файл** (анализ + код в блоках), не код в проекте.
- **Максимально полный ответ** — все граничные случаи, все находки.
- **Код в блоках** ```kotlin (или другой язык) — судья оценивает качество кода.
- **UI-тексты на русском**, код и идентификаторы на английском.
- **Не модифицируй проект** — только читаешь и анализируешь.
- **Сохрани ответ** в `answers/<task-id>/<model-id>.md`.

## Саморегистрация

Если тебя нет в `models.yaml`, зарегистрируйся:
```
python tools/register_model.py --auto --id <slug> --name "<Имя Модели>"
```
